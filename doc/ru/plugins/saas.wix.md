# Wix — плагин `saas.wix`

**Что делает:** даёт ИИ-агенту редактировать сайты Wix: страницы и содержимое (блог, CMS),
дизайн, картинки и файлы, SEO, публикацию. Подключение идёт через официальный сервер MCP Wix
(`https://mcp.wix.com/mcp`) по **ключу API**. Сайтов может быть несколько, у каждого свой ключ
(или общий ключ плагина).

Агент работает с сайтом четырьмя **универсальными** действиями AI2P — они одни для всех
SaaS-редакторов сайтов (Wix сегодня, другие потом):

| Действие | Что делает |
|---|---|
| `site_list` | какие сайты подключены, есть ли ключ, не закрыт ли сайт правилами |
| `site_tools` | инструменты Wix для сайта со схемами аргументов |
| `site_call` | вызвать инструмент Wix для выбранного сайта; `siteId` подставляется сам |
| `site_upload` | выложить папку проекта (`dir`, например `site/wix`) на сайт «из файлов» и опубликовать |

У CLI-агента это команды `ai2p call site_list`, `ai2p call site_tools --site ai2p`,
`ai2p call site_call --stdin`, `ai2p call site_upload --stdin`.

### Сайты «из файлов» (`site_upload`)

Сайт, собранный из загруженных файлов (адрес `*.wix-site-host.com`, без редактора Wix),
принимает новые файлы только загрузкой multipart, а инструменты MCP Wix так отправлять не
умеют. `site_upload` отправляет все файлы папки одним запросом на адрес `drop` сайта с ключом
API сайта, и Wix сразу публикует результат. **Загрузка заменяет весь набор файлов:** файл,
которого нет в папке, с сайта пропадёт. До отправки AI2P отказывает, если папка вне проекта,
в ней нет `index.html` или файлы больше 20 МБ. `wix.config.json` не выкладывается никогда.
Операция правил — `publish` (`saas.wix:ai2p:publish`).

## 1. Что взять в Wix

1. **Ключ API.** Войдите в Wix → значок профиля → **Account Settings → API Keys**
   (`https://manage.wix.com/account/api-keys`) → **Generate API Key**.
   - Название — например `AI2P`.
   - **Sites:** выберите только нужный сайт (например ai2p), а не «All sites».
   - **Permissions:** отметьте то, что агенту можно делать. Для полной правки сайта:
     *Wix Media Manager*, *Wix Blog*, *Wix Data (CMS)*, *SEO / Promote*, *Wix Site Pages*,
     *Manage Sites* (публикация и правка сайта). Чего не отметили — того агент не сделает
     даже без правил AI2P.
   - Нажмите **Generate**, скопируйте ключ: Wix покажет его один раз.
2. **Account ID** — на той же странице API Keys, справа (блок «Account ID»).
3. **Site ID** — откройте панель сайта: адрес вида
   `https://manage.wix.com/dashboard/<Site ID>/home`. Часть между `/dashboard/` и `/home` —
   и есть Site ID (GUID). Пока домен не подключён, адрес сайта — `https://<логин>.wixsite.com/<имя>`;
   Site ID при подключении домена **не меняется**, перенастраивать ничего не придётся.

## 2. Подключение в AI2P

1. **Настройки → Плагины и MCP → Wix** (строка `saas.wix`). Нужна роль admin.
2. Блок **Сайты → Добавить сайт**:
   - **Короткое имя** — латиница без пробелов, например `ai2p`. По нему агент выбирает сайт
     и по нему пишутся правила безопасности. Потом его не поменять.
   - **Название**, **Адрес сайта** — для людей и для агента.
   - **Site ID**, **Account ID** — из п. 1.
   - **Ключ API сайта** — из п. 1. Хранится в `secrets/` этого сервера, обратно не
     показывается; пустое поле при правке — «не менять».
3. Нажмите **Инициализировать** (внизу формы). AI2P подключится к Wix через первый сайт с
   ключом, снимет список инструментов Wix и заведёт на каждый запись справочника действий.
   Ошибка «401/403» — ключ или Account ID неверны либо у ключа нет прав.
4. Готово: у заданий на этом сервере появляются действия `site_list`, `site_tools`, `site_call`.
   Если Wix позже добавит инструменты — кнопка **Обновить список инструментов**: новый
   инструмент без этого запрещён.

Общий ключ: если один ключ годится на несколько сайтов, его можно ввести один раз в поле
**Токен сервера MCP** блока «Подключение» — сайты без своего ключа возьмут его.

Список сайтов и ключи — настройка **этого компьютера** (config.json и `secrets/`): на другом
сервере кластера сайт заводится заново.

## 3. Безопасность

Правила пишутся в **Настройки → Безопасность** (или проекта, или задачи) видом
**«Плагины и MCP»**, операция «использовать». Маска: `<плагин>:<сайт>:<операция>`.

Операции: `read` (чтение, документация, GET), `pages` (страницы, блог, CMS, меню), `design`
(тема, стили, правка сайта), `media` (загрузка и удаление файлов), `seo`, `publish`
(публикация), `api` (всё, что не распознано — самая широкая).

| Маска | Что закрывает |
|---|---|
| `saas.wix` | весь Wix |
| `saas.wix:ai2p:*` | сайт ai2p целиком |
| `saas.wix:*:publish` | публикацию любого сайта Wix |
| `*:*:publish` | публикацию в любом SaaS |
| `saas.wix:ai2p:api` | нераспознанные вызовы сайта ai2p |
| `*` | все плагины |

Разумная стартовая настройка: **переспросить** `*:*:publish` (публикует только человек) и
**переспросить** `saas.wix:*:api`. Кроме того, работу с сайтами целиком закрывают правила на
действия `AI2P.Site.List / AI2P.Site.Tools / AI2P.Site.Call / AI2P.Site.Upload`, а отдельные инструменты Wix —
правила на их записи справочника `Plugin.saas.wix.<инструмент>`.

## 4. Как ставить задачу агенту

Пишите в задаче сайт и что сделать: «На сайте `ai2p` (Wix) создай страницу FAQ из файла
`site/faq.md`, загрузи картинки из `site/img`, пропиши SEO-заголовок и описание. Не публикуй».
Агент начинает с `site_list`, затем `site_call tool=WixREADME` и ищет нужный метод API через
`SearchWixRESTDocumentation`.

## Ограничения

- Вход OAuth не поддержан — только ключ API.
- Структурированную разметку и llms.txt Wix правит в своём редакторе SEO; доступность их через
  API зависит от тарифа сайта.
- Отнесение вызова к операции делается по имени инструмента и тексту аргументов (правила в
  манифесте `plugins/saas.wix/plugin.json`, блок `saas.rules`). Не распознанное — `api`.
