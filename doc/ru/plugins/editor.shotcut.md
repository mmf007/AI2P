# Shotcut / Kdenlive (MLT XML)

**Код плагина:** `editor.shotcut`
**Вид:** шлюз (`gateway`)
**Формат обмена:** MLT XML — один файл открывается и в Shotcut (`.mlt`), и в Kdenlive
**Софт:** ставится нами (портативный Shotcut) либо берётся уже установленный `melt`
**Что делает:** собирает монтажный лист из медиатеки проекта и **считает по нему готовый ролик без окна**

## Почему это первый выбор из четырёх шлюзов

Из четырёх редакторов ветки (Shotcut/Kdenlive, DaVinci Resolve, Blender VSE, OpenShot)
только у этого есть **рендер без окна и без человека**: программа `melt` из поставки MLT
читает собранный нами файл и пишет готовый `mp4`. У Resolve и OpenShot такого пути нет
вовсе, у Blender он есть, но через исполнение нашего скрипта Python.

Поэтому цепочка здесь замкнутая: агент собрал монтажный лист → агент же посчитал ролик →
человек получил результат файлом. Ни одного шага мышью.

Второй довод: **один файл на два редактора**. MLT XML — родной формат Shotcut и он же
читается Kdenlive (`Проект → Открыть`). Заводить отдельный шлюз в Kdenlive не понадобилось.

## Действия агента

| Инструмент | Что делает |
|---|---|
| `shotcut_timeline_write` | собрать `ai2p_library.mlt` из медиатеки проекта |
| `shotcut_render` | посчитать ролик по собранному монтажному листу программой `melt` |

Параметры `shotcut_timeline_write` (все необязательные):

| Поле | Смысл |
|---|---|
| `scene` | взять только ресурсы этой сцены |
| `kind` | взять только этот вид медиа (`video`, `audio`, `image`, `subtitle`, `project`) |
| `tag` | взять только ресурсы с этим тэгом |
| `file` | куда положить файл; по умолчанию `ai2p_library.mlt` в корне папки проекта |

Параметры `shotcut_render`:

| Поле | Смысл |
|---|---|
| `file` | что рендерить; по умолчанию `ai2p_library.mlt` |
| `out` | куда положить результат; расширение `.mp4`, кодеки H.264 + AAC |

**Своей командной строки у рендера нет.** Аргументы `melt` заданы манифестом плагина, а
агент передаёт только два пути. Действия «выполнить произвольную команду» в системе нет
намеренно: это исполнение чужого кода с правом писать файлы, и правилом безопасности его не
сузить.

Порядок клипов — **тот же, что печатает `media_list`**: сцена, порядок (`order`), дубль
(`take`), код объекта. Человек, посмотревший список, обязан увидеть в редакторе ровно его.

Раскладка по дорожкам:

| Дорожка | Что на неё идёт |
|---|---|
| `V1` | `video`, `image`, `project` |
| `A1` | `audio` (дорожка помечена `hide="video"`) |

Ресурс без известной длительности (картинка, титр) получает **5 секунд**, а не ноль: клип
нулевой длины — это молча пропавший кадр.

## Софт

Плагин сначала **ищет программу на этом компьютере**: `melt`, `qmelt`, `melt.exe`,
`qmelt.exe` в `PATH`, проверка ключом `--version`, минимальная годная версия **7.0**. Нашёл —
берёт как есть; не нашёл — кнопка **«Установить»** качает портативный Shotcut и распаковывает
его сама. Третий путь — указать путь руками в форме плагина
(**Настройки → Плагины и MCP → Shotcut / Kdenlive (MLT XML)**); годится и файл программы, и
каталог, куда она поставлена.

В поставке Shotcut для Windows программа называется **`melt.exe`**, а не `qmelt.exe` — искать
надо оба имени. В сборках Linux и в некоторых сборках macOS она называется `qmelt`.

Путь к программе хранится **в `config.json` этого сервера** и не реплицируется никогда: у
соседа по кластеру Shotcut стоит по другому пути, а у половины серверов его нет вовсе. Само
описание плагина, наоборот, реплицируется на всю организацию.

Пока программа не найдена, состояние плагина на этом сервере — **«софт ищется»**, и его
действия агенту не публикуются: инструмент, который заведомо ответит отказом, тратил бы ход
агента впустую. Это и есть отказ «софт не найден на этом сервере».

## Ограничения по операционным системам

| Система | Что важно знать |
|---|---|
| **Windows** | Работает без оговорок. Программа рендера называется `melt.exe` и лежит рядом с `shotcut.exe` в каталоге установки. Переменная окружения `QT_QPA_PLATFORM` не нужна и не ставится. |
| **Linux** | На сервере **без дисплея** `melt` не стартует вовсе — падает с «could not connect to display», потому что это программа Qt. Поэтому плагин запускает его с `QT_QPA_PLATFORM=offscreen`; переменная ставится **только на Linux** (`envOs` в манифесте). Если вы зовёте `melt` руками — ставьте её сами. В сборках дистрибутивов программа обычно называется `melt`, в поставке Shotcut — `qmelt`. |
| **macOS** | Программа лежит **внутри пакета приложения**: `/Applications/Shotcut.app/Contents/MacOS/qmelt`. В `PATH` её нет, поэтому автопоиск чаще всего не находит ничего — путь указывается руками. Сборки из Homebrew (`brew install mlt`) дают `melt` в `PATH` и годятся тоже. |
| **Все системы** | Набор кодировщиков зависит от сборки MLT. Наши умолчания — `libx264` для видео и `aac` для звука — есть в поставке Shotcut на всех трёх системах, но в урезанной системной сборке MLT их может не быть; тогда рендер отказывает с текстом самого `melt`, и материал надо готовить плагином `tool.ffmpeg`. |
| **Kdenlive** | Файл открывается, но Kdenlive **пересчитывает его в свой профиль проекта** при открытии. Если частота нашего монтажного листа не совпала с профилем Kdenlive, длительности клипов сдвинутся: держите настройку «Кадров в секунду» одинаковой с обеих сторон. |

## Настройки записи плагина

**Настройки → Плагины и MCP → Shotcut / Kdenlive (MLT XML) → «Настроить»:**

| Настройка | Умолчание | Смысл |
|---|---|---|
| Кадров в секунду | 25 | частота монтажного листа; в неё же пересчитываются длительности клипов |
| Ширина кадра | 1920 | размер профиля MLT |
| Высота кадра | 1080 | то же |

Настройки — свойство **записи организации**, они реплицируются: договорились монтировать в
25 кадрах — договорились на всём кластере. Путь к программе, наоборот, свой у каждого сервера.

## Пути и безопасность

* **Все пути внутри `.mlt` — только относительные** (свойство `resource`). Абсолютный путь
  убивает переносимость: у соседа по кластеру тот же ролик лежит в другом месте, и
  монтажный лист откроется пустым.
* Путь клипа считается **от каталога выходного файла**.
* Ресурс из хранилища организации (`store:`) лежит вне папки проекта, поэтому при экспорте
  **копируется** в подкаталог `ai2p_media/` рядом с монтажным листом: иначе ссылка на него
  была бы либо абсолютной, либо с `..`.
* Агент пишет **только свой файл** `ai2p_library.mlt`. Проект человека не трогается никогда:
  человек может держать его открытым в редакторе, и сохранение из редактора затёрло бы нашу
  запись (или наоборот). Готовый монтажный лист человек импортирует к себе сам.
* Писать можно **в папку проекта**, а если правила безопасности задачи открыли внешние
  каталоги — то и в них. Проверяются и путь самого файла, и каждый путь внутри него.

## Связка с плагином «видео конвертор (ffmpeg)»

Материал разного размера и разной частоты MLT сведёт, но с пересчётом на лету — то есть
медленно и не всегда точно. Дешевле привести его заранее:

1. `ffmpeg_uniform` — общий размер кадра и общая частота;
2. `ffmpeg_extract_audio` — вынуть звук в WAV, если он нужен отдельной дорожкой;
3. `media_add` — положить полученные файлы в медиатеку;
4. `shotcut_timeline_write` и `shotcut_render`.

Перекодирование — **явный шаг**, а не молчаливая магия внутри экспорта: агент видит, что
делает, а вы видите, что получилось.
