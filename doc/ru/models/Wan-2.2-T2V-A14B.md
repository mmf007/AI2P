# Wan-2.2-T2V-A14B

**Размещение:** ЛОКАЛЬНАЯ (работает на этом компьютере)
**Подключение:** `provider: comfyui`, `baseUrl: http://127.0.0.1:8188`, модель `wan2.2_t2v_a14b`
**Ключ API:** не нужен — сервер поднимается локально без авторизации
**Что делает:** текст → видео, навык `video-generate` 80

Видео-модель Alibaba, открытая линейка **Wan 2.2** (версии 2.5 и выше — закрытые
API-продукты, их весов нет). По общему качеству ролика это сильнейшая из открытых
моделей справочника после LTX-2.5, и заметно сильнее Kandinsky 5.0 Video Lite.

Модель **составная** (MoE): в ней два эксперта по 14 миллиардов параметров. «Шумный»
рисует первую половину шагов — общую композицию и движение, «чистый» доводит вторую —
детали и резкость. Поэтому в манифесте установки два файла весов, а в графе ComfyUI два
сэмплера, передающих латент друг другу.

Работает через **ComfyUI**: AI2P поднимает его как локальный сервер, отправляет workflow
и забирает готовый `.mp4` в артефакты задачи.

## Ключ не нужен, нужна установка

Всё ставится кнопкой **«Установить»** в форме модели: **Настройки → Справочники →
Модели → Wan-2.2-T2V-A14B → «Установить»**. Ставятся:

* **пакет ComfyUI** (~2,1 ГБ) — портативная сборка с собственным Python;
* **четыре файла весов** в репозиторий моделей (`storage.modelsRepo`), группа `Wan-2.2-T2V`:

| Файл | Размер | Куда |
|---|---|---|
| `wan2.2_t2v_high_noise_14B_fp8_scaled.safetensors` | ~13,3 ГиБ | `diffusion_models` |
| `wan2.2_t2v_low_noise_14B_fp8_scaled.safetensors` | ~13,3 ГиБ | `diffusion_models` |
| `umt5_xxl_fp8_e4m3fn_scaled.safetensors` | ~6,3 ГиБ | `text_encoders` |
| `wan_2.1_vae.safetensors` | ~242 МиБ | `vae` |

**Итого около 35,6 ГБ загрузки.** Качается с докачкой: прерванная установка продолжится
с того места, где остановилась, уже скачанные файлы не перекачиваются.

Пока файлы не на месте, модель **не может быть активной** — это проверяется и при старте
приложения.

## Требования к железу

| | |
|---|---|
| Видеокарта | NVIDIA, **от 16 ГБ VRAM** (24 ГБ комфортно) |
| Драйвер NVIDIA | **580 или новее** — на старом драйвере torch падает без сообщения |
| Место на диске | ~38 ГБ (веса + пакет ComfyUI), плюс ~68 ГБ, если будете обучать LoRA |
| Оперативная память | от 32 ГБ |
| ОС | Windows (портативная сборка ComfyUI); на Linux ComfyUI ставится руками |

Эксперты грузятся по очереди, поэтому в память одновременно попадает один файл из двух —
на 16 ГБ VRAM ролик 832×480 считается, хотя и небыстро.

## Сколько ждать

Ролик 832×480 на 81 кадр (5 секунд при 16 кадрах в секунду) — это **десятки минут** на
современной карте: 20 шагов по двум экспертам на каждом кадре. Таймаут задания в профайле
выставлен в 240 минут (`params.timeoutMinutes`).

Ход генерации виден в **консоли задания** в карточке задачи: туда льётся собственный
вывод ComfyUI вместе с его прогресс-баром.

## Параметры генерации

Правятся в профайле модели (кнопка «Профайл подключения»):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `width` / `height` | 832 × 480 | разрешение кадра, родное для 14B |
| `length` | 81 | кадров в ролике; 16 кадров в секунду, то есть 5 секунд |
| `steps` | 20 | шагов диффузии на оба эксперта вместе |
| `negative` | пусто | негативный промпт |
| `timeoutMinutes` | 240 | сколько ждать результат |

**Про число шагов.** Граница экспертов (после какого шага «шумный» передаёт работу
«чистому») зашита в шаблоне workflow числом 10 — половина от двадцати. Если меняете
`steps`, поправьте и её: `end_at_step` первого сэмплера и `start_at_step` второго
в файле `models/workflow_….json` каталога организации. Арифметики над параметрами
у коннектора нет, поэтому граница не пересчитывается сама.

Turbo-режим официального шаблона ComfyUI (4 шага вместо 20) сюда не перенесён: ему нужны
отдельные файлы Lightning-LoRA, которых в манифесте установки нет.

Описание задачи целиком уходит в промпт. Указание вида «результат положить в файл X.mp4»
исполняется коннектором: файл копируется в папку проекта, а сама строка из промпта
вырезается.

## Обучение LoRA

Поддержано полностью: адаптер и **применяется** (узел `LoraLoaderModelOnly` вставляется
в граф на лету), и **обучается** прямо из AI2P — редактором LoRA в карточке объекта
проекта.

Обучает [musubi-tuner](https://github.com/kohya-ss/musubi-tuner) — скрипты
`wan_cache_latents.py`, `wan_cache_text_encoder_outputs.py` и `wan_train_network.py`
(`--task t2v-A14B`, `--network_module networks.lora_wan`), одна видеокарта, внимание
через `sdpa`. Адаптер учится сразу на обоих экспертах: «чистый» задаётся ключом `--dit`,
«шумный» — `--dit_high_noise`.

Пакет `musubi-tuner` (исходники, ~30 МБ) и **Python 3.12** (~45 МБ) ставятся вместе с
моделью, кнопкой «Установить»; уже стоящий на компьютере Python 3.10–3.12 берётся как
есть. Окружение с `torch` (~3 ГБ) тренер создаёт себе при первом запуске обучения.

**Что нужно знать заранее.** Генерация считает на сборках `fp8_scaled` — они вдвое легче,
и именно их ставит кнопка «Установить». Тренер такие сборки не принимает
([прямо сказано в его документации](https://github.com/kohya-ss/musubi-tuner/blob/main/docs/wan.md)),
поэтому при первом обучении `train.cmd` один раз догружает **свою пару fp16** (~57 ГБ)
и оригинальный текстовый энкодер `models_t5_umt5-xxl-enc-bf16.pth` (~11 ГБ) в подкаталог
`train` группы `Wan-2.2-T2V`. Итого ~68 ГБ сверх установки — заложите место на диске.
Класть эти файлы в манифест нельзя: от его состава считается признак «модель
установлена», и модель погасла бы у всех, кто адаптеры не обучает.

Готовый адаптер ложится в `<репозиторий моделей>/loras/<код объекта>.safetensors`. Все
ключи обучения, `dataset.toml` и `train.cmd` лежат в профайле модели (`lora.train`) и
переписываются перед каждым запуском — правьте их в профайле, а не в файлах.

## Частые ошибки

* **Процесс исчезает без сообщения** — почти всегда старый драйвер NVIDIA (см. выше).
* **«Модель не установлена»** — файлы не докачаны; откройте «Установить», окно покажет
  оставшийся объём.
* **Нехватка VRAM** — уменьшите `width`/`height` или `length`; 81 кадр в 720p 14B-модели
  требует уже 24 ГБ.
* **Ролик мутный или «дёрганый»** — проверьте, что не сбита граница экспертов после
  правки `steps` (см. «Параметры генерации»).
* **ComfyUI занят чужим процессом** — AI2P выгружает только тот сервер, который запустил
  сам; уже работающий чужой ComfyUI на 8188 он не трогает.
