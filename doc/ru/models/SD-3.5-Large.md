# SD-3.5-Large

**Размещение:** ЛОКАЛЬНАЯ (работает на этом компьютере)
**Подключение:** `provider: comfyui`, `baseUrl: http://127.0.0.1:8188`, модель `sd3_5_large`
**Ключ API:** не нужен — сервер поднимается локально без авторизации
**Что делает:** текст → изображение, навыки `image-generate` 80, `image-photo` 79,
`image-concept` 78, `image-text` 70

Stable Diffusion 3.5 Large от Stability AI, 8 миллиардов параметров. В справочнике она
стоит **средней ступенью**: заметно лучше SDXL, заметно слабее FLUX.2 и Qwen-Image, зато
ставится **одним файлом** и работает на карте с 12 ГБ.

Ставится fp8-сборка Comfy-Org: **текстовые энкодеры лежат внутри самого файла**, отдельно
качать `clip_g`, `clip_l` и `t5xxl` не нужно.

Работает через **ComfyUI**: AI2P поднимает его как локальный сервер, отправляет workflow
и забирает готовый `.png` в артефакты задачи.

## Ключ не нужен, нужна установка

Всё ставится кнопкой **«Установить»** в форме модели: **Настройки → Справочники →
Модели → SD-3.5-Large → «Установить»**. Ставятся:

* **пакет ComfyUI** (~2,1 ГБ) — портативная сборка с собственным Python;
* **один файл весов** в репозиторий моделей (`storage.modelsRepo`), группа `SD-3.5`:

| Файл | Размер | Куда |
|---|---|---|
| `sd3.5_large_fp8_scaled.safetensors` | ~13,9 ГиБ | `checkpoints` |

**Итого около 15 ГБ загрузки.** Качается с докачкой: прерванная установка продолжится
с того места, где остановилась.

Категория `checkpoints`, а не `diffusion_models` — это полный чекпойнт, из которого
ComfyUI берёт сразу модель, текстовые энкодеры и VAE.

Пока файл не на месте, модель **не может быть активной** — это проверяется и при старте
приложения.

## Требования к железу

| | |
|---|---|
| Видеокарта | NVIDIA, **от 10 ГБ VRAM** (12 ГБ комфортно) |
| Драйвер NVIDIA | **580 или новее** — на старом драйвере torch падает без сообщения |
| Место на диске | ~18 ГБ (веса + пакет ComfyUI) |
| Оперативная память | от 16 ГБ |
| ОС | Windows (портативная сборка ComfyUI); на Linux ComfyUI ставится руками |

## Сколько ждать

Двадцать шагов на кадре 1024×1024 — **десятки секунд** на современной карте.
Таймаут задания в профайле выставлен в 60 минут (`params.timeoutMinutes`).

Ход генерации виден в **консоли задания** в карточке задачи.

## Параметры генерации

Правятся в профайле модели (кнопка «Профайл подключения»):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `width` / `height` | 1024 × 1024 | разрешение кадра |
| `steps` | 20 | шагов диффузии |
| `negative` | пусто | негативный промпт — действует (`cfg 4.01`) |
| `timeoutMinutes` | 60 | сколько ждать результат |

Значение `cfg 4.01` взято из официального шаблона ComfyUI как есть.

Описание задачи целиком уходит в промпт. Указание вида «результат положить в файл X.png»
исполняется коннектором: файл копируется в папку проекта, а сама строка из промпта
вырезается.

## Обучение LoRA

**Применение — да, обучение из AI2P — нет.**

Готовый адаптер подключается как у всех записей ComfyUI: узел `LoraLoaderModelOnly`
вставляется в граф на лету, файл берётся из `<репозиторий моделей>/loras`. Адаптеров под
SD 3.5 в открытом доступе много, все они годятся.

Обучать адаптер прямо из AI2P нечем: `musubi-tuner`, которым учатся остальные локальные
модели, семейство Stable Diffusion не знает вовсе — это вотчина соседнего инструмента
того же автора, [sd-scripts](https://github.com/kohya-ss/sd-scripts). Поэтому у записи
стоит `lora.train.kind = external`, и кнопка обучения отвечает отказом сразу, а не через
полчаса счёта. Обученный на стороне файл достаточно положить в `loras`.

## Частые ошибки

* **Текст в кадре не получается** — это слабое место SD 3.5; для надписей берите
  `Qwen-Image-2512`, а для кириллицы — `Kandinsky-5.0-Image-Lite`.
* **«Модель не установлена»** — файл не докачан; откройте «Установить», окно покажет
  оставшийся объём.
* **Кнопка обучения LoRA отказывает** — так и задумано (см. выше).
* **Нехватка VRAM** — уменьшите `width`/`height`.
* **ComfyUI занят чужим процессом** — AI2P выгружает только тот сервер, который запустил
  сам.
