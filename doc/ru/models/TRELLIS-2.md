# TRELLIS-2

**Размещение:** ЛОКАЛЬНАЯ (работает на этом компьютере)
**Подключение:** `provider: comfyui`, `baseUrl: http://127.0.0.1:8188`, модель `trellis_2`
**Ключ API:** не нужен — сервер поднимается локально без авторизации
**Что делает:** изображение → 3D-модель С ЦВЕТОМ, навык `3d-image` 85

Открытая модель Microsoft Research (4 миллиарда параметров), превращающая ОДНУ картинку
в трёхмерную сетку. Единственная из трёх локальных 3D-записей справочника, которая выдаёт
не только форму, но и цвет: после ступени формы идёт отдельная ступень текстуры.

Работает через **ComfyUI**: AI2P поднимает его как локальный сервер, отправляет workflow
и забирает готовый `.glb` в артефакты задачи.

**Читается КАРТИНКА, а не текст.** В графе модели нет текстового энкодера вовсе — условие
даёт DINOv3 по стартовому кадру. Описание задачи модель не видит: что нарисовано на
картинке, то и получится. Стартовый кадр задаётся в описании задачи ссылкой на объект
проекта (`@obj:OBJ-3`) либо путём файла относительно папки проекта; без него задание не
запустится вовсе.

Фон со стартового кадра снимается автоматически (BiRefNet), и кадр обрезается по объекту:
3D из картинки с фоном получается заметно хуже.

## Ключ не нужен, нужна установка

Всё ставится кнопкой **«Установить»** в форме модели: **Настройки → Справочники →
Модели → TRELLIS-2 → «Установить»**. Ставятся:

* **пакет ComfyUI** (~2,1 ГБ) — портативная сборка с собственным Python;
* **пять файлов весов** в репозиторий моделей (`storage.modelsRepo`), группа `TRELLIS-2`:

| Файл | Размер | Куда |
|---|---|---|
| `trellis_2_int8_convrot.safetensors` | ~4,89 ГиБ | `diffusion_models` |
| `dino_v3_vit_l.safetensors` | ~1,13 ГиБ | `clip_vision` |
| `trellis_2_shape_vae_bf16.safetensors` | ~1,02 ГиБ | `vae` |
| `trellis_2_texture_vae_bf16.safetensors` | ~904 МиБ | `vae` |
| `birefnet.safetensors` | ~424 МиБ | `background_removal` |

**Итого около 9,0 ГБ загрузки** (8,34 ГиБ). Качается с докачкой: прерванная установка продолжится
с того места, где остановилась, уже скачанные файлы не перекачиваются.

Веса берутся в сборке **int8** — вдвое легче, чем bf16 (~9,6 ГиБ), и рассчитаны на
потребительскую карту. Кому нужна максимальная точность, тот меняет `unet_name` в шаблоне
workflow на `trellis_2_bf16.safetensors` и дописывает файл в манифест сам.

Пока файлы не на месте, модель **не может быть активной** — это проверяется и при старте
приложения.

## Требования к железу

| | |
|---|---|
| Видеокарта | NVIDIA, **от 12 ГБ VRAM** (16 ГБ комфортно) |
| Драйвер NVIDIA | **580 или новее** — на старом драйвере torch падает без сообщения |
| Место на диске | ~13 ГБ (веса + пакет ComfyUI) |
| Оперативная память | от 16 ГБ |
| ОС | Windows (портативная сборка ComfyUI); на Linux ComfyUI ставится руками |

Цифра по видеопамяти — **оценка**, а не замер: считается по размеру int8-весов и двух
VAE. Не хватило памяти — понижайте `target_resolution` у `Trellis2UpsampleStage` в шаблоне
workflow (по умолчанию 1536).

## Сколько ждать

Ступеней в графе четыре — структура, форма, повышение разрешения и текстура, — поэтому
одна модель считается заметно дольше, чем у Hunyuan3D: единицы-десятки минут на
современной карте. Таймаут задания в профайле выставлен в 90 минут
(`params.timeoutMinutes`).

Ход генерации виден в **консоли задания** в карточке задачи: туда льётся собственный
вывод ComfyUI вместе с его прогресс-баром.

## Параметры генерации

Правятся в профайле модели (кнопка «Профайл подключения»):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `steps` | 20 | шагов у ступени ФОРМЫ — главный рычаг качества |
| `timeoutMinutes` | 90 | сколько ждать результат |
| `width` / `height` | 1024 | на результат НЕ влияют: у 3D нет кадра |
| `negative` | пусто | не действует — текстового энкодера в графе нет |

Три остальные ступени идут с числом шагов из официального шаблона (12): менять их можно
только правкой самого workflow — результат они меняют мало, а времени съедают столько же.

**Чего в шаблоне намеренно нет.** Официальный шаблон ComfyUI после сетки делает ещё
UV-развёртку и запекает полный набор карт PBR (`UnwrapMesh` → `BakeTextureFromVoxel`,
`BakeNormalMapFromMesh`, `BakeAmbientOcclusion` → `ApplyTextureToMesh`). В нашем шаблоне
этой ветки нет: это ещё десяток узлов и запекание в 2048–4096 точек, а проверить их без
видеокарты нечем. Цвет при этом на месте — он передаётся вершинами сетки (`PaintMesh`).
Кому нужны карты PBR, тот дописывает ветку в свой workflow: все узлы у ComfyUI есть.

## Обучение LoRA

**Не поддерживается, и это честный отказ, а не недоделка.** Публичного тренера LoRA для
3D-архитектур сегодня нет: [musubi-tuner](https://github.com/kohya-ss/musubi-tuner), на
котором держится всё обучение адаптеров в AI2P, умеет только картинки и видео. Поэтому в
профайле стоит `lora.supported: false`, и форма модели показывает причину словами.

Постоянство объекта между кадрами достигается здесь другим способом: одну и ту же
эталонную картинку персонажа (объект проекта, ссылка `@obj:`) подавайте на вход — от
одинаковой картинки и одинакового `seed` выйдет одинаковая модель.

## Частые ошибки

* **«Модель не установлена»** — файлы не докачаны; откройте «Установить», окно покажет
  оставшийся объём.
* **Задание отказывается стартовать без картинки** — так и задумано: модель работает
  только от изображения. Дайте ссылку `@obj:` на эталонный кадр или путь файла.
* **Нехватка VRAM** — понизьте `target_resolution` у `Trellis2UpsampleStage`.
* **Объект получился обрезанным** — снятие фона выбрало не тот предмет; дайте кадр, где
  нужный объект один и целиком в кадре.
* **Процесс исчезает без сообщения** — почти всегда старый драйвер NVIDIA (см. выше).
