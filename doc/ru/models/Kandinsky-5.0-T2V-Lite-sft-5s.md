# Kandinsky-5.0-T2V-Lite-sft-5s

**Размещение:** ЛОКАЛЬНАЯ (работает на этом компьютере)
**Подключение:** `provider: comfyui`, `baseUrl: http://127.0.0.1:8188`,
модель `kandinsky5lite_t2v_sft_5s`
**Ключ API:** не нужен — сервер поднимается локально без авторизации
**Что делает:** текст → видео (5 секунд), навыки `video-generate` 76, `video-animate` 72

Модель генерации видео семейства Kandinsky 5.0 (вариант Lite, дообученный, 5 секунд).
Работает через **ComfyUI**: AI2P поднимает его как локальный сервер, отправляет workflow
и забирает готовый `.mp4` в артефакты задачи.

## Ключ не нужен, нужна установка

Всё ставится кнопкой **«Установить»** в форме модели: **Настройки → Справочники →
ИИ-модели → Kandinsky-5.0-T2V-Lite-sft-5s → «Установить»**. Ставятся:

* **пакет ComfyUI** (~2,1 ГБ) — портативная сборка с собственным Python;
* **четыре файла весов** в репозиторий моделей (`storage.modelsRepo`, по умолчанию `C:\ai`
  на Windows и `~/ai` на Linux/macOS):

| Файл | Размер | Куда |
|---|---|---|
| `Kandinsky-5.0-T2V-Lite-sft-5s.safetensors` | ~4,3 ГиБ | `diffusion_models` |
| `qwen_2.5_vl_7b_fp8_scaled.safetensors` | ~8,7 ГиБ | `text_encoders` |
| `clip_l.safetensors` | ~235 МиБ | `text_encoders` |
| `hunyuan_video_vae_bf16.safetensors` | ~470 МиБ | `vae` |

**Итого около 16 ГБ загрузки.** Качается с докачкой: прерванная установка продолжится
с того места, где остановилась, уже скачанные файлы не перекачиваются.

Пока файлы не на месте, модель **не может быть активной** — это проверяется и при старте
приложения.

## Требования к железу

| | |
|---|---|
| Видеокарта | NVIDIA, **минимум 6 ГБ VRAM** |
| Драйвер NVIDIA | **580 или новее** — см. предупреждение ниже |
| Место на диске | ~18 ГБ (веса + пакет ComfyUI) |
| Оперативная память | от 16 ГБ |
| ОС | Windows (портативная сборка ComfyUI); на Linux ComfyUI ставится руками |

**Про драйвер — важное.** В пакете ComfyUI идёт torch, собранный под CUDA 13.0. На старом
драйвере (например 527.99 = CUDA 12.0) он падает не с понятной ошибкой, а
**access violation** — процесс просто исчезает. Это не дефект AI2P: обновите драйвер
NVIDIA до 580+ (проверено на 610.x). Если модель «молча не запускается», начните
с `nvidia-smi` и версии драйвера.

## Сколько ждать

На 6 ГБ VRAM генерация ролика **768×512, 121 кадр, 50 шагов занимает около часа**
(проверено вживую: 58 минут 49 секунд). Это нормально — таймаут задания в профайле
выставлен в 180 минут (`params.timeoutMinutes`).

С версии 1.63 то же самое можно задать **у исполнителя**: поле «Таймаут ответа, мин»
в форме исполнителя-ИИ. Заполнено — оно сильнее `timeoutMinutes` профайла, **0 — ждать
без ограничения** (генерация идёт, сколько нужно; оборвать её можно кнопкой
«остановить»). Пусто — как раньше, значение из профайла.

Ход генерации виден в **консоли задания** в карточке задачи: туда льётся собственный
вывод ComfyUI вместе с его прогресс-баром.

## Параметры генерации

Правятся в профайле модели (кнопка «Профайл подключения»):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `width` / `height` | 768 × 512 | разрешение; больше — заметно дольше и больше VRAM |
| `length` | 121 | кадров (≈5 секунд) |
| `steps` | 50 | шагов диффузии; меньше — быстрее и грубее |
| `negative` | пусто | негативный промпт |
| `timeoutMinutes` | 180 | сколько ждать результат |

Описание задачи целиком уходит в промпт. Указание вида «результат положить в файл X.mp4»
исполняется коннектором: файл копируется в папку проекта, а сама строка из промпта
вырезается.

## Обучение LoRA

Устроено так же, как у `Kandinsky-5.0-I2V-Lite-5s`, и отличается двумя строками настройки:
задача тренера здесь `k5-lite-t2v-5s-sd`, веса — `Kandinsky-5.0-T2V-Lite-sft-5s.safetensors`.

Обучает [musubi-tuner](https://github.com/kohya-ss/musubi-tuner) — одна видеокарта,
внимание через `sdpa`, 13–16 ГБ VRAM. Официальный
[kandinsky-5-lora-train](https://github.com/kandinskylab/kandinsky-5-lora-train) требует
NCCL и нескольких видеокарт и на Windows не запускается.

Пакет `musubi-tuner` (исходники, ~30 МБ) и **Python 3.12** (~45 МБ) ставятся вместе с
моделью, кнопкой «Установить»: уже стоящий на компьютере Python 3.10–3.12 при этом
берётся как есть и повторно не качается. Окружение с `torch` (~3 ГБ) тренер создаёт себе
при первом запуске обучения.
Сам тренер догружает исходные `Qwen/Qwen2.5-VL-7B-Instruct` (~16 ГБ) и
`openai/clip-vit-large-patch14` (~1,7 ГБ) — урезанные сборки, которыми пользуется
генерация, ему не подходят.

Готовый адаптер ложится в `<репозиторий моделей>/loras/<код объекта>.safetensors`. Все ключи
обучения, `dataset.toml` и `train.cmd` лежат в профайле модели (`lora.train`) и
переписываются перед каждым запуском.

Датасет в AI2P — **картинки**, поэтому так обучается адаптер внешности; адаптер движения
обучается на видео, и видео-датасета в редакторе LoRA пока нет.

## Частые ошибки

* **Процесс исчезает без сообщения** — почти всегда старый драйвер NVIDIA (см. выше).
* **«Модель не установлена»** — файлы не докачаны; откройте «Установить», окно покажет
  оставшийся объём.
* **Нехватка VRAM** — уменьшите `width`/`height` или `length`.
* **ComfyUI занят чужим процессом** — AI2P выгружает только тот сервер, который запустил
  сам; уже работающий чужой ComfyUI на 8188 он не трогает.
