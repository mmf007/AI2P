# Qwen-Image-2512

**Размещение:** ЛОКАЛЬНАЯ (работает на этом компьютере)
**Подключение:** `provider: comfyui`, `baseUrl: http://127.0.0.1:8188`, модель `qwen_image_2512`
**Ключ API:** не нужен — сервер поднимается локально без авторизации
**Что делает:** текст → изображение, навыки `image-text` 94, `image-photo` 91,
`image-generate` 90, `image-concept` 85

Модель рисования картинок от Alibaba, редакция **2512** (20 миллиардов параметров).
Её сильная сторона — **текст в кадре**: вывески, подписи, обложки, плакаты, интерфейсы,
причём и кириллицей. Это лучшая из открытых моделей по надписям и вёрстке — по ней и
стоит выбирать, если в картинке должны быть слова.

Работает через **ComfyUI**: AI2P поднимает его как локальный сервер, отправляет workflow
и забирает готовый `.png` в артефакты задачи.

## Ключ не нужен, нужна установка

Всё ставится кнопкой **«Установить»** в форме модели: **Настройки → Справочники →
Модели → Qwen-Image-2512 → «Установить»**. Ставятся:

* **пакет ComfyUI** (~2,1 ГБ) — портативная сборка с собственным Python;
* **три файла весов** в репозиторий моделей (`storage.modelsRepo`), группа `Qwen-Image`:

| Файл | Размер | Куда |
|---|---|---|
| `qwen_image_2512_fp8_e4m3fn.safetensors` | ~19,0 ГиБ | `diffusion_models` |
| `qwen_2.5_vl_7b_fp8_scaled.safetensors` | ~8,7 ГиБ | `text_encoders` |
| `qwen_image_vae.safetensors` | ~242 МиБ | `vae` |

**Итого около 30 ГБ загрузки.** Качается с докачкой: прерванная установка продолжится
с того места, где остановилась, уже скачанные файлы не перекачиваются.

Группа `Qwen-Image` — общая с моделью `Qwen-Image-Edit-2511`: текстовый энкодер и VAE у
них одни и те же, поэтому вторая модель докачает только свой файл весов (~19 ГиБ), а не
всю тридцатку заново.

Пока файлы не на месте, модель **не может быть активной** — это проверяется и при старте
приложения.

## Требования к железу

| | |
|---|---|
| Видеокарта | NVIDIA, **от 16 ГБ VRAM** (24 ГБ комфортно) |
| Драйвер NVIDIA | **580 или новее** — на старом драйвере torch падает без сообщения |
| Место на диске | ~32 ГБ (веса + пакет ComfyUI) |
| Оперативная память | от 32 ГБ |
| ОС | Windows (портативная сборка ComfyUI); на Linux ComfyUI ставится руками |

Модель в манифесте — **fp8**: она вдвое легче исходной bf16 и рассчитана ровно на
потребительскую карту. Для обучения LoRA fp8 не годится — см. ниже.

## Сколько ждать

Кадр 1328×1328 за 20 шагов — **минуты** на карте класса 4090 и до десятка минут на
8–16 ГБ с выгрузкой в оперативную память. Таймаут задания в профайле выставлен в
90 минут (`params.timeoutMinutes`).

Ход генерации виден в **консоли задания** в карточке задачи: туда льётся собственный
вывод ComfyUI вместе с его прогресс-баром.

## Параметры генерации

Правятся в профайле модели (кнопка «Профайл подключения»):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `width` / `height` | 1328 × 1328 | разрешение кадра |
| `steps` | 20 | шагов диффузии; меньше — быстрее и грубее |
| `negative` | пусто | негативный промпт (здесь он **действует**, `cfg = 4`) |
| `timeoutMinutes` | 90 | сколько ждать результат |

Описание задачи целиком уходит в промпт. Указание вида «результат положить в файл X.png»
исполняется коннектором: файл копируется в папку проекта, а сама строка из промпта
вырезается.

Текст, который должен появиться в кадре, пишите в промпте **в кавычках и дословно** —
модель воспроизводит именно то, что взято в кавычки.

## Обучение LoRA

Поддержано полностью: адаптер и **применяется** (узел `LoraLoaderModelOnly` вставляется
в граф на лету), и **обучается** прямо из AI2P — редактором LoRA в карточке объекта
проекта.

Обучает [musubi-tuner](https://github.com/kohya-ss/musubi-tuner) — скрипты
`qwen_image_cache_latents.py`, `qwen_image_cache_text_encoder_outputs.py` и
`qwen_image_train_network.py` (`--model_version original`,
`--network_module networks.lora_qwen_image`), одна видеокарта, внимание через `sdpa`.

Пакет `musubi-tuner` (исходники, ~30 МБ) и **Python 3.12** (~45 МБ) ставятся вместе с
моделью, кнопкой «Установить»; уже стоящий на компьютере Python 3.10–3.12 берётся как
есть. Окружение с `torch` (~3 ГБ) тренер создаёт себе при первом запуске обучения.

**Тренеру нужны другие файлы весов.** musubi-tuner прямо говорит, что fp8-сборки
(те самые, которыми считает генерация) обучению не годятся, поэтому `train.cmd` при
первом обучении один раз догружает пару **bf16** — `qwen_image_2512_bf16.safetensors`
(~38 ГиБ) и `qwen_2.5_vl_7b.safetensors` (~15,4 ГиБ) — в подкаталог `train` группы
`Qwen-Image`. Это около **57 ГБ сверх установки**, зато сама генерация продолжает
работать на лёгких fp8-файлах. VAE берётся уже установленный.

Готовый адаптер ложится в `<репозиторий моделей>/loras/<код объекта>.safetensors`. Все
ключи обучения, `dataset.toml` и `train.cmd` лежат в профайле модели (`lora.train`) и
переписываются перед каждым запуском — правьте их в профайле, а не в файлах.

## Частые ошибки

* **Процесс исчезает без сообщения** — почти всегда старый драйвер NVIDIA (см. выше).
* **«Модель не установлена»** — файлы не докачаны; откройте «Установить», окно покажет
  оставшийся объём.
* **Нехватка VRAM** — уменьшите `width`/`height`; 20B на 8 ГБ идёт только с выгрузкой в
  оперативную память и заметно медленнее.
* **Обучение падает на загрузке весов** — проверьте свободное место: тренеру нужны свои
  ~57 ГБ (см. «Обучение LoRA»).
* **ComfyUI занят чужим процессом** — AI2P выгружает только тот сервер, который запустил
  сам; уже работающий чужой ComfyUI на 8188 он не трогает.
