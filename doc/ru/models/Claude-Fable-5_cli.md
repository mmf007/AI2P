# Claude-Fable-5_cli

**Размещение:** облако, но подключение **не по API, а по CLI**
**Подключение:** `transport: cli`, команда `claude --permission-mode acceptEdits`,
модель `claude-fable-5`
**Ссылка на ключ:** пусто — **ключ API не нужен**

Та же модель, что Claude-Fable-5, но запускается через **Claude Code
CLI** в headless-режиме. Платится не за токены, а **подпиской**, поэтому в биллинге AI2P
стоимость таких заданий равна нулю.

## Ключ API не нужен

Авторизация — сессией CLI, а не ключом. Поэтому в профайле `secretRef` пуст, и кнопки
«Установить ключ API» у этой модели нет.

## Что нужно вместо ключа

1. **Установить Claude Code** — [официальная инструкция](https://docs.claude.com/en/docs/claude-code/overview).
   Проверка: в консоли `claude --version` должен что-то напечатать.
2. **Войти под своей подпиской**: `claude login` (браузер откроется сам). Сессия
   сохраняется в профиле пользователя ОС.
3. Убедиться, что `claude` доступен **из PATH того пользователя, под которым работает
   AI2P**. Если AI2P запущен службой от другой учётной записи, вход надо выполнить под ней
   же, иначе агент упрётся в «не авторизован».
4. Если исполняемый файл лежит не в PATH — пропишите полный путь в поле `cliCommand`
   профайла модели (кнопка «Профайл подключения» в форме модели).

## Чем отличается от варианта по API

| | по API | по CLI |
|---|---|---|
| Оплата | по токенам | подпиской |
| Стоимость в биллинге | считается | 0 |
| Инструменты | инструменты AI2P (чтение/запись файлов и т. п.) | **штатные инструменты самого CLI** |
| Рабочий каталог | не важен | **папка проекта** — агент работает прямо в ней |
| Вопросы человеку | штатно | по маркеру `AI2P_QUESTION` в ответе, продолжение — `--resume` |
| Создание подзадач | инструментом `create_task` | по маркеру `AI2P_SUBTASK` в ответе |
| Чтение других заданий | инструментами `get_task_by_code`, `get_task_by_url`, `get_task_chat` | по маркеру `AI2P_GET_TASK` в ответе |
| Внешние файлы задания (картинки вложений) | инструментом `fetch_file` | по маркеру `AI2P_GET_FILE` в ответе |
| Перенос задачи по иерархии | инструментом `move_task` | по маркеру `AI2P_MOVE_TASK` в ответе |
| Решение задачи «Условие» | инструментом `set_condition_result` | по маркеру `AI2P_CONDITION` в ответе или командой `ai2p condition` |
| Исход проверки условий цикла | инструментом `set_loop_result` | по маркеру `AI2P_LOOP` в ответе или командой `ai2p loop` |
| Задачи ветви из узла шаблона | инструментом `create_tasks_from_template` | по маркеру `AI2P_FROM_TEMPLATE` в ответе или командой `ai2p from-template` |
| Завершить выполнение иерархии | инструментом `stop_hierarchy` | по маркеру `AI2P_STOP_HIERARCHY` в ответе или командой `ai2p stop-hierarchy` |

Важное следствие: при CLI-подключении инструменты AI2P агенту **не публикуются** — он
пользуется своими. Правила безопасности AI2P (гл. 12 ТЗ) на его действия внутри каталога
проекта не распространяются, поэтому каталог проекта задавайте осознанно.

### Подзадачи маркером `AI2P_SUBTASK`

Инструмента `create_task` у CLI-агента нет, а API AI2P закрыто входом по cookie — поэтому
разбить задачу на подзадачи он раньше не мог вовсе. Теперь подзадача создаётся **строкой
в ответе**:

```
AI2P_SUBTASK: {"title": "заголовок", "description": "описание работы", "skills": ["code-write"], "priority": 20, "acceptance": "критерии приёмки"}
```

Одна строка — одна подзадача; обязательны `title` и `description`. Как только агент
закончил работу, AI2P выполняет эти строки сама: убирает их из текста ответа, создаёт
подзадачи (исполнитель подбирается автоматически — сначала ИИ, потом человек), помечает
родительскую задачу разбитой и дописывает в результат раздел «Подзадачи» со списком
созданного. Дальше подзадачи запускаются обычной очередью авторазбиения — по убыванию
числового приоритета.

Это тот же **`AI2P.Tasks.Create`**, что и инструмент, поэтому правила безопасности
на это действие работают: запрет (deny) или требование подтверждения (confirm) — и
подзадача не создаётся, а причина отказа попадает в результат задания и в журнал работ.
Маркер засчитывается только **с начала строки**: упоминание внутри предложения или
в отчёте подзадачей не станет.

### Чтение других заданий маркером `AI2P_GET_TASK`

Задачи AI2P лежат в базе организации, в файлах проекта их нет, а `/api` закрыто входом
по cookie — поэтому CLI-агент видел только текст своего задания и блок родительской
задачи. Если человек в формулировке дал ссылку на другую задачу («возьми текстовку из
результата задачи …»), прочитать её агент не мог. Теперь он запрашивает её **строкой
в ответе**:

```
AI2P_GET_TASK: {"code": "T-15"}
```

Вместо `code` можно указать `"url"` (ссылка вида `…/task/<id>`) или `"title"` (поиск по
части заголовка — вернётся список найденных заданий без текстов). AI2P выполняет запрос
и присылает ответ агенту **следующим сообщением той же сессии CLI** (`--resume`, как при
ответе человека на вопрос), после чего он продолжает работу с того же места. Ответ всегда
полный: карточка задания (формулировка, критерии приёмки, статус, результаты-артефакты)
**и чат целиком** — отдельно запрашивать переписку не нужно. Маркеров можно вывести
сразу несколько; всего запросов за одно задание — не больше 10 (защита от зацикливания),
дальше система сообщает агенту, что предел исчерпан.

Это те же действия **`AI2P.Tasks.GetByCode` / `GetByUrl` / `FindByTitle` / `GetChat`**,
что и одноимённые инструменты, поэтому правила безопасности работают как обычно: запрет
или требование подтверждения — задание не читается, отказ уходит агенту и в журнал работ.
Доступны только задачи того же проекта.

## Ограничения

| | |
|---|---|
| Контекст | 1 000 000 токенов |
| Максимум ответа | 128 000 токенов |
| Стоимость | 0 (оплачено подпиской) |

**Остаток лимита подписки CLI не сообщает** (правка v1.62), поэтому AI2P считает расход
сама — по токенам заданий за скользящее окно. Заполните у исполнителя-ИИ поля **«лимит
токенов за окно»** и **«окно лимита, ч»** (у подписки Claude окно — 5 часов): тогда перед
запуском задачи система предупредит, что лимита почти не осталось, и перенесёт старт на
момент освобождения окна (можно вместо этого разбить задачу или запустить принудительно).
Поля пустые — проверок нет, всё работает как раньше. А если лимит наступил уже посреди
задания, AI2P узнаёт сообщение CLI (`5-hour limit reached ∙ resets 4:10pm (…)`), берёт
из него время сброса и переводит задачу в **«ожидает»** до этого времени вместо «встал
с ошибкой» — потом она запускается сама. Подробнее — в документе
Claude-Opus-5.0_cli.

**Сколько ждать ответа** (правка v1.63) — поле **«Таймаут ответа, мин»** в форме
исполнителя: пусто — 30 минут, число — столько минут, **0 — без ограничения**. Вышел
таймаут — задание падает с ошибкой и подсказкой; исполнитель занятым при этом
не помечается (молчание агента лимитом не считается).

## Требования к железу

Никаких особых: считает провайдер. Нужен установленный Claude Code, выход в интернет и
достаточно места в каталоге проекта — агент работает с файлами напрямую.

## Частые ошибки

* **«claude не найден»** — CLI не установлен либо не в PATH пользователя AI2P.
* **Молчаливый отказ или запрос входа** — сессия CLI не создана или создана под другой
  учётной записью ОС; повторите `claude login` под нужным пользователем.
* **Агент не видит файлов задачи** — у проекта не задан каталог (поле «Папка проекта»):
  рабочим каталогом процесса CLI служит именно он.
