# Claude-Opus-5.5_cli

**Размещение:** облако, но подключение **не по API, а по CLI**
**Подключение:** `provider: anthropic`, `transport: cli`, команда
`claude --permission-mode acceptEdits`, модель `claude-opus-5-5`
**Ссылка на ключ:** пусто — **ключ API не нужен**

Та же модель, что Claude-Opus-5.5, но запускается через **Claude Code CLI**
в headless-режиме. Платится не за токены, а **подпиской**, поэтому в биллинге AI2P стоимость
таких заданий равна нулю.

Старшая модель линейки Opus, вышедшая после Opus 5: сильнее её и на API дешевле. Ниша — сложный код, разбор требований и длинные задания по файлам проекта.

## Зачем отдельная запись под версию

Версию модели у Claude Code CLI выбирает поле **«модель»** профайла записи: оно уходит
CLI флагом `--model`. Поэтому на каждую версию, которую вы хотите выбирать исполнителю,
заведена **своя запись справочника**, и записи сосуществуют: Claude-Opus-5.0_cli остаётся
со своим прежним идентификатором, а эта работает на `claude-opus-5-5`.

Допустимых форм значения две (`claude --help`):

* **полное имя версии** — `claude-opus-5-5`;
* **алиас последней версии** — `opus`.

В записях дистрибутива стоит полное имя: алиас со временем молча переезжает на новую
версию (проверено 24.09.2026 живым запуском: `fable` уже означает `claude-fable-5-1`), и
тогда запись перестаёт означать то, что написано в её названии.

## Ключ API не нужен

Авторизация — сессией CLI, а не ключом: `secretRef` в профайле пуст, кнопки «Установить
ключ API» у записи нет. Что нужно вместо ключа:

1. **Установить Claude Code** — [официальная инструкция](https://docs.claude.com/en/docs/claude-code/overview).
   Проверка: `claude --version` должен что-то напечатать.
2. **Войти под своей подпиской**: `claude login`.
3. Убедиться, что `claude` доступен **из PATH того пользователя, под которым работает AI2P**.
4. Если исполняемый файл лежит не в PATH — пропишите полный путь в поле `cliCommand`.

Подробный разбор различий «по API / по CLI» — в документе Claude-Fable-5_cli;
здесь всё устроено ровно так же.

## Проба записи проверяет и модель

Кнопка пробы (правка v1.144) делает три вещи: запускает `claude --version`, спрашивает
состояние входа и **коротким вызовом проверяет сам идентификатор модели**. Неизвестный
или недоступный подписке id виден сразу отказом пробы, а не падением задания через минуты
работы. Если CLI ответит другой моделью, чем просили, AI2P напишет об этом **событием
журнала задания** и строкой в сводке результата.

## Ограничения и стоимость

| | |
|---|---|
| Контекст | 1 000 000 токенов |
| Максимум ответа | 128 000 токенов |
| Стоимость | 0 (оплачено подпиской) |

**Лимит подписки AI2P распознаёт и ждёт сброса**: увидев отказ CLI с кодом 429, система
берёт время сброса и переводит задачу в «ожидает», а по сбросу продолжает ту же сессию.

## Требования к железу

Никаких особых: считает провайдер. Нужен установленный Claude Code, выход в интернет и
место в каталоге проекта.

## Частые ошибки

* **«claude не найден»** — CLI не установлен либо не в PATH пользователя AI2P.
* **«Claude CLI не принял модель»** — идентификатор устарел либо подписка к этой версии не
  пускает; сверьте значение поля «модель» с `claude --help`.
* **Агент не видит файлов задачи** — у проекта не задан каталог («Папка проекта»).

## Нужна свежая версия Claude Code

Эта модель появилась позже самого CLI, поэтому **старый Claude Code её не знает**. На версии
2.1.278 вызов отвечал отказом:

```
[claude-code:unrecognized_model]: Claude Code 2.1.278 does not support this model;
version 2.1.280 or newer is required
```

Нужен **Claude Code 2.1.280 или новее** (проверено живым запуском 24.09.2026 на 2.1.281:
код возврата 0, ответила claude-opus-5-5). Обновление — `claude update`, проверка —
`claude --version`. Если кнопка пробы записи ругается на модель, начните с версии CLI.

Тем же запуском видно, зачем записи дистрибутива называют модель **полным именем**: алиас
`opus` уже переехал с `claude-opus-5` на `claude-opus-5-5`, то есть означал бы разное на
разных машинах. Запись Claude-Opus-5.0_cli при этом осталась на `claude-opus-5`.
