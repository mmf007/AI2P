# Qwen3.5-4B-Local

**Размещение:** ЛОКАЛЬНАЯ (работает на этом компьютере)
**Подключение:** `provider: openai-compatible`, `baseUrl: http://localhost:8084/v1`,
модель `qwen3.5-4b`
**Ключ API:** не нужен — локальный сервер поднимается без авторизации
**Что делает:** лёгкая работа с текстом и разбор данных, оценки навыков 62–74

Самая нетребовательная к железу запись справочника. Заведена заданием T-347-S0
(23.09.2026) ради РОЛИ СУФЛЁРА: перед медиа-заданием суфлёр читает описание задачи и
возвращает маленький управляющий json по схеме профайла рабочей модели. Работа эта
всегда одна и та же и всегда простая — поднимать ради неё 27-миллиардную модель или
платить за облако незачем.

4 млрд параметров, квант **Q4_K_S**, движок **llama.cpp / llama-server**. Модель годится
и на обычные мелкие задачи — перевод, сводка, правка текста, — но на код и сложный
анализ её брать не стоит: для этого в справочнике есть записи посильнее.

## Ключ не нужен, нужна установка

Всё ставится кнопкой **«Установить»** в форме модели: **Настройки → Справочники →
ИИ-модели → Qwen3.5-4B-Local → «Установить»**. Ставятся:

* **пакет llama.cpp** (~0,5 ГБ) — сборка с `llama-server`;
* **файл весов** `Qwen3.5-4B-Q4_K_S.gguf` — **2,41 ГиБ** (2 590 430 368 байт) в
  репозиторий моделей (`storage.modelsRepo`, группа `Qwen3.5-4B`).

Размер снят HEAD-запросом к HuggingFace 23.09.2026: ответ 200 без токена, репозиторий
`unsloth/Qwen3.5-4B-GGUF` не закрыт согласием с лицензией. Качается с докачкой,
скачанное сверяется по точному размеру. **Пока файлы не на месте, модель активной быть
не может** — это правило AI2P, а не ошибка.

После установки в профайл прописывается команда запуска:

```
llama-server.exe -m <путь к .gguf> -ngl 99 -c 16384 --cache-type-k q8_0 --cache-type-v q8_0 --jinja --port 8084 --alias qwen3.5-4b
```

Порт **8084** свой у этой записи: 8080–8083 заняты соседними локальными моделями, иначе
второй `llama-server` не поднялся бы рядом с первым.

## Требования к железу

|---|---|
| Место на диске | **от 4 ГБ** (веса + пакет llama.cpp) |
| Видеопамять | **3 ГБ** — все слои на видеокарте при контексте 16 384 и KV-кэше `q8_0` |

Цифры — **оценка по размеру весов и по объёму KV-кэша, замеров не делали**: модель на
этом компьютере не запускалась. Веса в кванте Q4_K_S занимают 2,41 ГиБ, кэш ключей и
значений при `-c 16384` и `q8_0` — меньше 200 МиБ.

## Эта запись НЕ гасится по выслуге версий

Обычное правило справочника — «у модели есть три более старших версии того же семейства,
значит её пора погасить». К этой записи оно НЕ применяется, пока файл весов доступен для
скачивания у производителя: её ценность не в качестве, а в размере, и замены с такими
требованиями к железу в справочнике нет. Погасить её можно только по одной причине —
репозиторий `unsloth/Qwen3.5-4B-GGUF` перестал отдавать файл.

## Частые ошибки

* **Медиа-задание уходит в генерацию без управляющего json** — у исполнителя-суфлёра не
  выбрана модель либо у рабочей модели в профайле не стоит `prompter.required`.
* **Не хватает видеопамяти** — уменьшите `-c` в команде запуска: контекст и есть главный
  потребитель памяти сверх самих весов.
* **Порт 8084 занят** — поменяйте `--port` в команде запуска и `baseUrl` в профайле.
* **Качество ответов хуже ожидаемого** — это модель на 4 млрд параметров; для кода и
  сложного анализа берите записи посильнее.
