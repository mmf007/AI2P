# LTX-2.5

**Размещение:** ЛОКАЛЬНАЯ (работает на этом компьютере)
**Подключение:** `provider: comfyui`, `baseUrl: http://127.0.0.1:8188`, модель `ltx_2_5_distilled`
**Ключ API:** не нужен — сервер поднимается локально без авторизации
**Что делает:** текст → видео **со звуком**, навык `video-generate` 85

Видео-модель Lightricks, 22 миллиарда параметров, дистиллированный вариант. Это
**единственная открытая модель, которая рисует видео и звук одним проходом**: звуковая
дорожка считается своим латентом рядом с видео и попадает в тот же `.mp4`. Всем
остальным локальным моделям справочника звук надо накладывать отдельно.

По качеству картинки она сильнее Wan 2.2 и HunyuanVideo 1.5, но и тяжелее их: 22B против
14B, и веса закрыты соглашением (см. ниже — файлы придётся положить руками).

Работает через **ComfyUI**: AI2P поднимает его как локальный сервер, отправляет workflow
и забирает готовый `.mp4` в артефакты задачи.

## Установка: файлы придётся положить руками

Репозиторий весов **закрыт соглашением** (gated): HuggingFace отдаёт файлы только тем,
кто принял лицензию, причём по личному токену. Загрузчик AI2P ходит без токена и получит
отказ (проверено запросом 27.08.2026), поэтому порядок такой:

1. откройте <https://huggingface.co/Lightricks/LTX-2.5>, войдите в свою учётную запись
   HuggingFace и примите условия лицензии;
2. скачайте четыре файла из таблицы ниже;
3. положите их в подкаталог `LTX-2.5` репозитория моделей (`storage.modelsRepo`) —
   **плоско, без вложенных папок**, имена файлов не меняя;
4. нажмите **«Установить»** в форме модели: **Настройки → Справочники → Модели →
   LTX-2.5 → «Установить»**. Установка увидит совпадение размеров и поставит только
   пакет ComfyUI, а модель станет установленной.

| Файл | Размер | Куда |
|---|---|---|
| `ltx-2.5-22b-distilled-transformer-comfy-int8-convrot.safetensors` | ~20 ГиБ | `diffusion_models` |
| `gemma4-12b-with-proj-ltx-2.5-comfy-int8-convrot.safetensors` | ~14,3 ГиБ | `text_encoders` |
| `ltx-2.5-video-vae-bf16.safetensors` | ~1,4 ГиБ | `vae` |
| `ltx-2.5-audio-vae-bf16.safetensors` | ~348 МиБ | `vae` |

**Итого около 38,7 ГБ.** Пока файлы не на месте, модель **не может быть активной** — это
проверяется и при старте приложения.

## Требования к железу

| | |
|---|---|
| Видеокарта | NVIDIA, **от 24 ГБ VRAM** (32 ГБ комфортно) |
| Драйвер NVIDIA | **580 или новее** — на старом драйвере torch падает без сообщения |
| Место на диске | ~41 ГБ (веса + пакет ComfyUI) |
| Оперативная память | от 32 ГБ |
| ОС | Windows (портативная сборка ComfyUI); на Linux ComfyUI ставится руками |

Файлы весов взяты в сборке `int8-convrot` — той самой, что стоит в официальном шаблоне
ComfyUI: она вдвое легче bf16 (у которого один только трансформер занимает 39 ГиБ).

## Сколько ждать

Модель дистиллированная, шагов всего восемь, поэтому ролик 1280×704 на 121 кадр
(5 секунд при 24 кадрах в секунду) считается **быстрее**, чем у Wan 2.2 при двадцати
шагах — единицы-десятки минут. Таймаут задания в профайле выставлен в 240 минут
(`params.timeoutMinutes`).

## Параметры генерации

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `width` / `height` | 1280 × 704 | разрешение кадра; оба числа кратны 32 — этого требует узел латента |
| `length` | 121 | кадров в ролике; 24 кадра в секунду, то есть 5 секунд |
| `steps` | 8 | **справочно**: число шагов задают сигмы шаблона, см. ниже |
| `negative` | пусто | негативный промпт |
| `timeoutMinutes` | 240 | сколько ждать результат |

**Про шаги.** У дистиллированной модели расписание шумов задано списком чисел прямо в
шаблоне (узел `ManualSigmas`), а не числом шагов: девять значений — восемь шагов. Правка
`steps` в профайле на генерацию не влияет, значение стоит для сводки задания; чтобы
менять расписание, правьте `sigmas` в файле `models/workflow_….json` каталога
организации.

**Чего в нашем шаблоне нет против официального.** Официальный шаблон ComfyUI считает в
два прохода: первый в половинном размере, второй поднимает разрешение узлом
`LTXVLatentUpsampler`. Коннектор AI2P не умеет арифметики над `width`/`height`, поэтому
«половину» было бы неоткуда взять, а сводка задания называла бы человеку не тот размер —
у нас один проход сразу в целевом разрешении. Улучшение промпта отдельной языковой
моделью (`TextGenerateLTX2Prompt`) тоже выключено: оно тянет ещё один файл весов и
переписывает текст задачи молча.

## Обучение LoRA

Адаптер **применяется** штатно: узел `LoraLoaderModelOnly` вставляется в граф на лету,
файлы берутся из `<репозиторий моделей>/loras`. У LTX богатая готовая экосистема LoRA —
адаптеры движения камеры, стиля и управления публикует сам Lightricks.

А вот **обучать адаптер из AI2P нельзя**, и это отмечено в записи честно: у
[musubi-tuner](https://github.com/kohya-ss/musubi-tuner), которым AI2P учит LoRA для
остальных локальных моделей, тренера LTX нет вовсе — есть Wan, HunyuanVideo, Kandinsky,
Qwen-Image, Z-Image, но не LTX. Поэтому в профайле у обучения стоит способ «внешнее»:
кнопка «обучить» отвечает внятным отказом со ссылкой, а не висит полчаса и падает.

Обучить адаптер можно отдельно, официальным тренером Lightricks
(<https://github.com/Lightricks/LTX-Video-Trainer>), и положить готовый файл
`.safetensors` в `<репозиторий моделей>/loras` — оттуда AI2P его подхватит.

## Частые ошибки

* **Установка отвечает отказом на загрузке** — репозиторий закрыт соглашением, файлы надо
  принести руками (см. «Установка»).
* **«Модель не установлена» после ручной укладки** — проверьте имена файлов и то, что они
  лежат прямо в каталоге группы `LTX-2.5`, а не во вложенных папках; размер должен
  совпадать с таблицей до байта.
* **Ролик без звука** — звук берётся из того же прохода; если его нет, проверьте, что в
  шаблоне остались узлы `LTXVEmptyLatentAudio` и `LTXVAudioVAEDecode`.
* **Нехватка VRAM** — уменьшите `width`/`height` или `length`.
