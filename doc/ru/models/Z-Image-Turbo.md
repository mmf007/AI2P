# Z-Image-Turbo

**Размещение:** ЛОКАЛЬНАЯ (работает на этом компьютере)
**Подключение:** `provider: comfyui`, `baseUrl: http://127.0.0.1:8188`, модель `z_image_turbo`
**Ключ API:** не нужен — сервер поднимается локально без авторизации
**Что делает:** текст → изображение, навыки `image-generate` 85, `image-photo` 84,
`image-concept` 82, `image-text` 78

Модель рисования картинок от Tongyi-MAI (Alibaba), вариант **Turbo**: 6 миллиардов
параметров и **восемь шагов** на кадр вместо обычных двадцати-пятидесяти. Это самая
быстрая и самая нетребовательная из локальных картиночных моделей справочника —
разумный первый выбор, если видеокарта скромная.

Работает через **ComfyUI**: AI2P поднимает его как локальный сервер, отправляет workflow
и забирает готовый `.png` в артефакты задачи.

## Ключ не нужен, нужна установка

Всё ставится кнопкой **«Установить»** в форме модели: **Настройки → Справочники →
Модели → Z-Image-Turbo → «Установить»**. Ставятся:

* **пакет ComfyUI** (~2,1 ГБ) — портативная сборка с собственным Python;
* **три файла весов** в репозиторий моделей (`storage.modelsRepo`), группа `Z-Image`:

| Файл | Размер | Куда |
|---|---|---|
| `z_image_turbo_bf16.safetensors` | ~11,5 ГиБ | `diffusion_models` |
| `qwen_3_4b.safetensors` | ~7,5 ГиБ | `text_encoders` |
| `ae.safetensors` | ~320 МиБ | `vae` |

**Итого около 21 ГБ загрузки.** Качается с докачкой: прерванная установка продолжится
с того места, где остановилась, уже скачанные файлы не перекачиваются.

Пока файлы не на месте, модель **не может быть активной** — это проверяется и при старте
приложения.

## Требования к железу

| | |
|---|---|
| Видеокарта | NVIDIA, **от 8 ГБ VRAM** (16 ГБ комфортно) |
| Драйвер NVIDIA | **580 или новее** — на старом драйвере torch падает без сообщения |
| Место на диске | ~23 ГБ (веса + пакет ComfyUI) |
| Оперативная память | от 16 ГБ |
| ОС | Windows (портативная сборка ComfyUI); на Linux ComfyUI ставится руками |

## Сколько ждать

Восемь шагов — это **секунды-десятки секунд** на кадр 1024×1024 на современной карте,
а не часы, как у видео-моделей. Таймаут задания в профайле выставлен в 60 минут
(`params.timeoutMinutes`) — этого хватает с запасом даже на медленном железе.

Ход генерации виден в **консоли задания** в карточке задачи: туда льётся собственный
вывод ComfyUI вместе с его прогресс-баром.

## Параметры генерации

Правятся в профайле модели (кнопка «Профайл подключения»):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `width` / `height` | 1024 × 1024 | разрешение кадра |
| `steps` | 8 | шагов диффузии; у Turbo больше восьми смысла не имеет |
| `negative` | пусто | негативный промпт — **у Turbo не действует** (см. ниже) |
| `timeoutMinutes` | 60 | сколько ждать результат |

**Про негативный промпт.** Turbo-режим считает без classifier-free guidance (`cfg = 1`),
поэтому отрицательное условие в шаблоне сделано узлом `ConditioningZeroOut` — ровно как
в официальном шаблоне ComfyUI. Значение `negative` в профайл можно вписать, но на
картинку оно не повлияет; если негатив нужен, берите обычную (не Turbo) модель.

Описание задачи целиком уходит в промпт. Указание вида «результат положить в файл X.png»
исполняется коннектором: файл копируется в папку проекта, а сама строка из промпта
вырезается.

## Обучение LoRA

Поддержано полностью: адаптер и **применяется** (узел `LoraLoaderModelOnly` вставляется
в граф на лету), и **обучается** прямо из AI2P — редактором LoRA в карточке объекта
проекта.

Обучает [musubi-tuner](https://github.com/kohya-ss/musubi-tuner) —
скрипты `zimage_cache_latents.py`, `zimage_cache_text_encoder_outputs.py` и
`zimage_train_network.py` (`--network_module networks.lora_zimage`), одна видеокарта,
внимание через `sdpa`.

Пакет `musubi-tuner` (исходники, ~30 МБ) и **Python 3.12** (~45 МБ) ставятся вместе с
моделью, кнопкой «Установить»; уже стоящий на компьютере Python 3.10–3.12 берётся как
есть. Окружение с `torch` (~3 ГБ) тренер создаёт себе при первом запуске обучения.

**Важная особенность именно Turbo.** Turbo — это дистиллированные веса, обучать LoRA на
них не рекомендует сам автор тренера, поэтому `train.cmd` при первом обучении один раз
догружает **базовые** веса `z_image_bf16.safetensors` (~11,5 ГБ) в подкаталог `train`
группы `Z-Image` и учит на них. Текстовый энкодер и VAE берутся уже установленные —
они у базовой и turbo-версии одни и те же. Готовый адаптер работает с turbo-весами.

Готовый адаптер ложится в `<репозиторий моделей>/loras/<код объекта>.safetensors`. Все
ключи обучения, `dataset.toml` и `train.cmd` лежат в профайле модели (`lora.train`) и
переписываются перед каждым запуском — правьте их в профайле, а не в файлах.

## Частые ошибки

* **Процесс исчезает без сообщения** — почти всегда старый драйвер NVIDIA (см. выше).
* **«Модель не установлена»** — файлы не докачаны; откройте «Установить», окно покажет
  оставшийся объём.
* **Негативный промпт не действует** — так и задумано у Turbo (см. «Параметры генерации»).
* **Нехватка VRAM** — уменьшите `width`/`height`.
* **ComfyUI занят чужим процессом** — AI2P выгружает только тот сервер, который запустил
  сам; уже работающий чужой ComfyUI на 8188 он не трогает.
