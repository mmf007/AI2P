# Claude-Opus-5.0_cli

**Размещение:** облако, подключение **по CLI**
**Подключение:** `transport: cli`, команда `claude --permission-mode acceptEdits`,
модель `claude-opus-5`
**Ссылка на ключ:** пусто — **ключ API не нужен**

Claude-Opus-5.0, запускаемый через **Claude Code CLI** в
headless-режиме. Оплата — подпиской, в биллинге AI2P стоимость таких заданий равна нулю.

## Ключ API не нужен

Авторизация идёт сессией CLI. Настройка — ровно та же, что у
Claude-Fable-5_cli:

1. установить [Claude Code](https://docs.claude.com/en/docs/claude-code/overview);
2. выполнить `claude login` **под тем пользователем ОС, под которым работает AI2P**;
3. убедиться, что `claude` доступен из его PATH (иначе прописать полный путь в `cliCommand`
   профайла модели).

Настройка общая на обе CLI-модели: сделав её один раз, вы включаете обе.

## Лимит подписки (правка v1.62)

Остаток лимита подписки CLI не сообщает: ни в `claude --help`, ни в JSON-выводе задания
его нет, а `/usage` работает только в интерактивной сессии. Поэтому расход считает сама
AI2P — по токенам заданий за скользящее окно. Чтобы это заработало, заполните у
исполнителя-ИИ (Исполнители → форма исполнителя) два поля:

* **лимит токенов за окно** — сколько токенов вы готовы истратить за окно; значение
  подбирается опытным путём по вашей подписке;
* **окно лимита, ч** — у подписки Claude окно **5 часов**.

Поля пустые — всё работает как раньше: остаток не считается, предупреждений нет.
Заполнены — перед запуском задачи AI2P проверяет остаток и, если его почти нет,
переносит старт на момент освобождения окна с сообщением в чат задачи (задачу можно
вместо этого разбить на подзадачи или запустить принудительно). Перенесённый старт
хранится в задаче: компьютер можно выключить, после включения задача запустится сама.

**Если лимит всё-таки наступил посреди работы** (правка v1.62), CLI отвечает коротким
сообщением вида `5-hour limit reached ∙ resets 4:10pm (Europe/Moscow)`. AI2P его узнаёт,
берёт из него время сброса и **не считает это ошибкой задачи**: задание закрывается
с артефактом-объяснением, исполнитель помечается «занят до», а задача переходит в
**«ожидает»** — в шапке карточки виден чип «Ожидает до <время>», в чате появляется
сообщение. Когда время придёт, задача запустится сама — **новым заданием, с начала**
(всё, что агент успел записать в файлы проекта, остаётся на месте). Ждать у компьютера
не нужно: его можно выключить. Времени сброса в сообщении не оказалось — ждём час.

## Таймаут ответа (правка v1.63)

Агент CLI ведёт свой цикл сам и во время работы **молчит** — AI2P видит только момент, когда
процесс закончился. Сколько его ждать, задаётся полем **«Таймаут ответа, мин»** в форме
исполнителя:

* **пусто** — 30 минут (умолчание системы, как было зашито в коде до 1.63);
* **число** — столько минут;
* **0** — ждать без ограничения; задание оборвёт только кнопка «остановить».

Вышел таймаут — задание завершается **ошибкой** с подсказкой, где значение увеличить,
а задача переходит в «встал с ошибкой». Исполнитель при этом **занятым не помечается**:
до 1.63 молчание агента считалось исчерпанным лимитом подписки и исполнитель на час
выпадал из работы, хотя лимит мог быть израсходован на треть. Настоящий лимит AI2P
по-прежнему узнаёт по сообщению самого CLI (см. раздел выше).

## Что помнить про CLI-подключение

* агент работает **штатными инструментами CLI**, инструменты AI2P ему не публикуются;
* рабочий каталог процесса — **папка проекта**, поэтому она должна быть задана;
* правила безопасности AI2P на действия агента внутри этого каталога не распространяются;
* вопросы человеку передаются маркером `AI2P_QUESTION` в ответе, продолжение диалога —
  той же сессией CLI (`--resume`);
* подзадачи агент создаёт маркером `AI2P_SUBTASK` в ответе — вместо инструмента
  `create_task`, которого у него нет (см. Claude-Fable-5_cli);
* перенести задачу по иерархии (сменить родителя, вынести в корень) агент может маркером
  `AI2P_MOVE_TASK` — вместо инструмента `move_task`;
* тексты других заданий (описание, результат и весь чат) агент запрашивает маркером
  `AI2P_GET_TASK` — вместо инструментов `get_task_by_code` / `get_task_by_url` /
  `get_task_chat`, которых у него тоже нет.
