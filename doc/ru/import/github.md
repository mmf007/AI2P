# Импорт задач из GitHub — инструкция по подключению

Импорт переносит **задачи (issues) GitHub** в задачи AI2P (ТЗ п. 2.10, гл. 11). Для
подключения нужна одна строка от GitHub — **личный токен доступа** — и одна запись
в справочнике импортов. По шагам:

## 1. Получить токен

GitHub выдаёт токены в настройках аккаунта. Токены бывают двух видов, годятся оба.

**Мелкозернистый токен (fine-grained, рекомендуется — прав можно дать ровно столько,
сколько нужно):**

1. Войдите в GitHub и откройте
   <https://github.com/settings/personal-access-tokens/new>.
2. **Token name** — любое, например `AI2P import`; **Expiration** — срок жизни.
3. **Repository access** — «All repositories» либо «Only select repositories» и перечислите те,
   из которых будете импортировать.
4. **Permissions → Repository permissions → Issues** — поставьте **Read-only**.
   (Полю **Metadata** GitHub включит доступ на чтение сам — он обязателен.)
5. **Generate token** и скопируйте показанную строку. Она начинается с `github_pat_`
   и показывается **один раз**.

**Классический токен (classic):**

1. Откройте <https://github.com/settings/tokens> → **Generate new token (classic)**.
2. Отметьте область **`repo`** (она даёт доступ к задачам приватных репозиториев);
   для публичных репозиториев хватит **`public_repo`**.
3. **Generate token** и скопируйте строку — она начинается с `ghp_`.

Токен даёт доступ к вашим репозиториям — храните его как пароль. **Для публичных
репозиториев токен всё равно нужен**: без него GitHub разрешает лишь 60 запросов в час
на адрес, и импорт упрётся в этот предел.

## 2. Создать источник в справочнике импортов

**Настройки → вкладка «Справочники» → «Справочник импортов» → «Добавить»:**

| Поле | Что вписать |
| --- | --- |
| Имя источника | любое, например `GitHub рабочий` |
| Вид | GitHub |
| Владелец репозиториев | имя пользователя **или организации** — то, что стоит в адресе `github.com/<владелец>` |
| Фильтр | подстрока имени репозитория, например `planner`; пусто — все репозитории владельца |
| Активна | пока недоступно — включится само после шага 3 |

Нажмите **«Сохранить»**. Кнопка ввода токена появляется у **сохранённой** записи:
значение кладётся в хранилище сразу, поэтому до сохранения неизвестно, чьё оно.

## 3. Ввести токен

Откройте сохранённый источник кнопкой **«редактировать»** и нажмите **«Установить токен»** —
вставьте строку из шага 1 и сохраните.

Ключа API у GitHub нет: секрет один, поэтому в форме одна кнопка (у Trello их две).
Старое значение никогда не показывается — чтобы заменить токен, вводится новый. Под формой
видно состояние: «Токен: установлен, источник — организация».

Форма сверяет **вид** значения и предупреждает, если оно не похоже на токен GitHub:
нынешние начинаются с `github_pat_` или `ghp_`, прежние — 40 знаков `0–9 a–f`.

**Кнопка «Проверить подключение»** спрашивает у GitHub «кто я» и сразу отвечает словами:
принят ли токен, какому аккаунту он выдан и совпадает ли этот аккаунт с владельцем,
указанным в источнике. Проверять подключение здесь дешевле, чем ловить отказ при первом
импорте.

**Где лежит токен.** В базе данных вашей организации, **зашифрованным** ключом организации
(как ключи API моделей): он сам доезжает до всех серверов организации, а расшифровать его
может только сервер, которому выдан ключ организации. Вписывать что-либо в `secrets.json`
не нужно; если значение всё же положено файлом, оно тоже будет прочитано — порядок чтения
«организация → `secrets.json` → переменная окружения».

**Пока токен не введён, источник не может быть активным** — переключатель «Активна»
заблокирован. Как только токен введён, источник **включается сам**; дальше активность
переключаете вы.

**Два аккаунта GitHub.** У каждого источника **своя** ссылка на токен — заведите второй
источник и введите в него другое значение.

## 4. Запустить импорт

1. Выберите **проект** — импорт всегда идёт в текущий проект.
2. В списке задач нажмите кнопку-иконку **облако со стрелкой** («Импорт задач») —
   она видна только при выбранном проекте.
3. В диалоге выберите источник и чекбоксы:
   * **добавлять новые** (включён по умолчанию) — задачи, которых ещё нет, станут задачами AI2P;
   * **обновить существующие** — у ранее импортированных задач обновятся заголовок,
     описание и срок (локальные правки этих полей будут перезаписаны).
4. Нажмите **«Импортировать»**. Итог покажется сообщением: «добавлено X, обновлено Y,
   пропущено Z, сообщений обсуждения N»; запись `import.run` появится в «Истории работ».

## Что именно импортируется

* Берутся **открытые задачи** репозиториев владельца; репозитории отбираются по подстроке
  имени (пустой фильтр — все).
* **Запросы на слияние (pull requests) не импортируются.** В API GitHub они выглядят как
  задачи, но задачами не считаются и пропускаются.
* Задача GitHub → задача AI2P со статусом **«черновик»**: заголовок, **текст задачи целиком
  в описании** + приписка-источник внизу («Импортировано из GitHub: репозиторий …, задача #N»
  со ссылкой). Исполнителей и приоритет заполняете уже в AI2P.
* **Обсуждение задачи переносится в чат задачи AI2P**: каждый комментарий становится
  сообщением, автор назван так, как он назван в GitHub — `github:<логин>`, время
  сообщения — время комментария, поэтому хронология сохраняется. Повторный импорт
  добавляет **только новые** сообщения: уже перенесённые узнаются по внешнему id.
* **Срока** у задачи GitHub нет. Если задача отнесена к **вехе (milestone)** с датой,
  эта дата становится сроком задачи AI2P.
* **Дубли не создаются**: внутренний id задачи запоминается в задаче AI2P (`github:<id>`);
  повторный импорт ту же задачу пропустит или обновит — по чекбоксу.
* **Файлы, приложенные к задаче GitHub, не скачиваются.** У GitHub нет отдельного списка
  вложений — картинки и файлы живут ссылками внутри самого текста, и ссылками они
  и остаются. Для публичного репозитория такая ссылка открывается и картинка видна;
  ссылка на файл **приватного** репозитория без входа в GitHub не откроется.
* Метки, исполнители и состояние задачи GitHub **не переносятся**: их ведут в AI2P.

## 5. Импорт одной задачи по ссылке

Рядом с кнопкой массового импорта в списке задач есть кнопка **«Импорт задания по URL»**:

1. Вставьте ссылку вида `https://github.com/<владелец>/<репозиторий>/issues/<номер>`
   (годится и адрес с хвостом — `#issuecomment-…` и `?…` отбрасываются). Источник
   переспрашивается, только если подходящих активных источников GitHub несколько:
   **вид источника определяет сама ссылка**, поэтому вставленный адрес GitHub не попадёт
   к импортёру Trello.
2. Содержимое задачи подставится **в форму новой задачи**: заголовок, описание, срок.
3. Дозаполните форму (исполнитель, приоритет) и сохраните — обсуждение уедет в чат задачи
   сразу после сохранения. Повторный импорт той же задачи дубль не создаст.

ИИ-агентам то же действие доступно инструментом `import_task_from_url` (код действия
`AI2P.Tasks.ImportFromUrl` — правила безопасности deny/confirm применяются как обычно).
Какая процедура возьмётся за ссылку, решает её вид, поэтому агенту достаточно одного
инструмента на все источники.

## 6. Обновление задачи из GitHub

У задачи, приехавшей импортом, заполнено поле **«Ссылка импорта»** (видно в шапке карточки
и в разделе «Расширенное» формы задачи). По этой ссылке задачу можно **перечитать
из источника**:

1. Откройте карточку задачи и нажмите **«обновить»**.
2. Появится переспрос с тремя исходами:
   * **«Из источника импорта»** — задача GitHub читается заново, и в задачу AI2P ложатся
     свежие заголовок, срок и **описание целиком**, а в чат доезжают новые сообщения
     обсуждения;
   * **«Только здесь»** — обычное перечитывание задачи из базы, к GitHub обращения нет;
   * **«Отмена»**.

Что **не** трогается обновлением: критерии приёмки, исполнители, статус, приоритет, теги,
подзадачи и связи — их ведут в AI2P, а не в GitHub. **Описание переписывается целиком**:
обновление из источника затем и запускают, чтобы в задаче стало то, что сейчас в GitHub.
Уже перенесённые сообщения обсуждения не дублируются.

Ссылку импорта можно **вписать руками** — тогда обновится и задача, заведённая в AI2P
без импорта; можно и **очистить поле**, чтобы отвязать задачу от источника (кнопка
«обновить» станет обычным перечитыванием).

## Если что-то не работает

| Сообщение | Причина и что делать |
| --- | --- |
| «Токен GitHub не найден по ссылке …» | Токен не введён: откройте источник и нажмите «Установить токен» (шаг 3). Путь к файлу секретов указан прямо в сообщении. |
| «Этот сервер ещё не получил ключ организации…» | Сервер подключён к чужой организации, но заявка не подтверждена её дирижёром — без ключа организации значение нечем зашифровать. Подтвердите подключение (Настройки → Серверы). |
| «GitHub не принял ТОКЕН…» (ответ `Bad credentials`) | Токен неверен, отозван или истёк его срок. Сообщение показывает длину и префикс введённого значения — по ним видно, не попало ли в поле что-то другое. Повторите шаг 1. |
| «GitHub отказал в доступе…» (403) | Токен принят, но прав на репозиторий у него нет: мелкозернистому нужен доступ **Issues: Read** и сам репозиторий в списке «Repository access», классическому — область **repo**. |
| «GitHub временно отказывает: исчерпан предел числа запросов» | Сработал rate limit API. Подождите несколько минут; проверьте, что импорт идёт **с токеном** — без него предел в 80 раз ниже. |
| «GitHub не нашёл запрошенное (404…)» | Неверны владелец, имя репозитория или номер задачи. Приватный репозиторий, к которому у токена нет прав, GitHub показывает как несуществующий — это тот же 404. |
| «Ссылка не похожа на задачу GitHub…» | Адрес не той формы: нужен `https://github.com/<владелец>/<репозиторий>/issues/<номер>`. Ссылка на **pull request** (`/pull/<номер>`) не годится — импортируются только задачи. |
| Импорт прошёл, но «добавлено 0» | Фильтр не совпал ни с одним репозиторием, у репозиториев нет открытых задач, либо все открытые записи оказались запросами на слияние. Попробуйте с пустым фильтром. |
| Импортировались не все репозитории приватного аккаунта | Токен выдан **другому** аккаунту: чужие приватные репозитории он не видит. Проверьте кнопкой «Проверить подключение» — она называет аккаунт токена и предупреждает о расхождении с владельцем. |

Сообщения приходят целиком в само окно импорта. Подробности запросов — в логах приложения
(`logs/*.jsonl`, записи `GitHubImporter`): по какой ссылке и из какого хранилища взят токен,
какой он длины и с каким префиксом (само значение в лог не пишется никогда), какой ответ
вернул GitHub.

## Пределы

* За один импорт берётся до **10 страниц по 100 записей** каждого рода — репозиториев,
  задач репозитория, комментариев задачи. Этого хватает на 1000 репозиториев, 1000 открытых
  задач на репозиторий и 1000 комментариев на задачу; упёрлись в предел — это видно в логе.
* Поддерживается **github.com**. GitHub Enterprise со своим адресом сервера сейчас
  не поддерживается.
