# Импорт задач из GitLab — инструкция по подключению

Импорт переносит **задачи GitLab** (issue) в задачи AI2P (ТЗ п. 2.10, гл. 11). Для подключения
нужна одна строка от GitLab — **личный токен доступа** — и одна запись в справочнике импортов.
Работает и с облачным `gitlab.com`, и со своим сервером GitLab.

## 1. Получить токен доступа

GitLab выдаёт токены в настройках профиля:

1. Войдите в GitLab в браузере и откройте
   <https://gitlab.com/-/user_settings/personal_access_tokens>
   (на своём сервере — тот же путь от его адреса: `https://git.example.com/-/user_settings/personal_access_tokens`).
   Путь к странице подсказан и в самом интерфейсе: **аватар → Edit profile → Access tokens**.
2. Нажмите **«Add new token»**. Заполните:
   * **Token name** — любое, например `AI2P import`;
   * **Expiration date** — срок годности; по истечении токен перестанет работать, и импорт
     ответит «GitLab не принял ТОКЕН»;
   * **Select scopes** — достаточно **`read_api`**. Полный `api` тоже подойдёт, но он даёт
     право менять данные, а импорт только читает.
3. Нажмите **«Create personal access token»** и **сразу скопируйте** показанное значение:
   второй раз GitLab его не покажет. Нынешние токены начинаются с `glpat-`.

Токен даёт доступ к вашим проектам — храните его как пароль.

**Токен проекта или группы** (Settings → Access tokens внутри проекта) тоже годится, если
у него есть право `read_api`; он удобнее тем, что видит ровно один проект.

## 2. Создать источник в справочнике импортов

**Настройки → вкладка «Справочники» → «Справочник импортов» → «Добавить»:**

| Поле | Что вписать |
| --- | --- |
| Имя источника | любое, например `GitLab основной` |
| Вид | GitLab |
| Сервер GitLab | пусто — облачный `https://gitlab.com`; свой сервер указывается полностью, например `https://git.example.com` |
| Проект GitLab | путь проекта вида `группа/проект` — ровно так, как он виден в адресной строке; подгруппы пишутся через косую черту (`группа/подгруппа/проект`) |
| Метки | отбор задач по меткам через запятую, например `bug,ui`; пусто — все открытые задачи проекта |
| Активна | пока недоступно — включится само после шага 3 |

Нажмите **«Сохранить»**. Кнопка ввода токена появляется у **сохранённой** записи: значение
кладётся в хранилище сразу, поэтому до сохранения неизвестно, чьё оно.

**Отдельного «ключа API» у GitLab нет** — в отличие от Trello, где ключ и токен два разных
значения. Поэтому в форме источника GitLab одна кнопка секрета, и активным источник
становится по одному введённому токену.

## 3. Ввести токен

Откройте сохранённый источник кнопкой **«редактировать»** — в форме появилась кнопка
**«Установить токен»**. Вставьте строку из шага 1 и нажмите «Сохранить».

Старое значение никогда не показывается — чтобы заменить токен, вводится новый. Под формой
видно состояние: «Токен: установлен, источник — организация». Если значение не похоже
на токен GitLab (не начинается с `glpat-`), форма предупредит: это подсказка, а не запрет —
проектные и OAuth-токены выглядят иначе и работают.

**Кнопка «Проверить подключение»** (рядом, работает, когда токен введён) спрашивает у GitLab
«кто я» и, если в источнике назван проект, — виден ли он этому токену. Ответ приходит
словами: принят ли токен, какому аккаунту он выдан, виден ли проект. Проверять подключение
здесь дешевле, чем ловить отказ при первом импорте.

**Где это значение лежит.** В базе данных вашей организации, **зашифрованным** ключом
организации (как ключи API моделей): оно само доезжает до всех серверов организации,
а расшифровать его может только сервер, которому ключ организации выдан. Вписывать
что-либо в `secrets.json` не нужно.

**Два аккаунта или два сервера GitLab.** У каждого источника **своя** ссылка на токен —
заведите второй источник (например, для своего сервера GitLab) и введите в него другое
значение. Импорт одиночной задачи по ссылке сам выбирает источник по адресу сервера
в ссылке.

## 4. Запустить импорт

1. Выберите **проект** (в шапке или на вкладке проекта) — импорт всегда идёт в текущий
   проект AI2P.
2. В списке задач нажмите кнопку-иконку **облако со стрелкой** («Импорт задач») — она видна
   только при выбранном проекте.
3. В диалоге выберите источник и чекбоксы:
   * **добавлять новые** (включён по умолчанию) — задачи, которых ещё нет, станут задачами AI2P;
   * **обновить существующие** — у ранее импортированных задач обновятся заголовок, описание
     и срок из GitLab (локальные правки этих полей будут перезаписаны).
4. Нажмите **«Импортировать»**. Итог покажется сообщением: «добавлено X, обновлено Y,
   пропущено Z»; запись `import.run` появится в «Истории работ».

## Что именно импортируется

* Берутся **открытые задачи** (`state=opened`) указанного проекта; если заданы метки —
  только помеченные ими.
* Задача GitLab → задача AI2P со статусом **«черновик»**: заголовок, срок (`due_date`),
  **сама статья** (текст issue) в описании + приписка-источник внизу
  («Импортировано из GitLab: проект …, задача #N» со ссылкой). Исполнителей и приоритет
  заполняете уже в AI2P.
* **Приложенные файлы.** Отдельного списка вложений у issue в GitLab нет: загруженный файл
  живёт ссылкой `/uploads/<хэш>/<имя>` **внутри самого текста**. Импорт находит такие ссылки,
  **скачивает файлы** в хранилище проекта AI2P и переписывает ссылки на местные — картинки
  остаются картинками. Файл, который скачать не удалось (нет прав, больше 200 МБ), остаётся
  ссылкой на GitLab: полной, а не относительной, — по ней хотя бы можно перейти.
* **Обсуждение.** Комментарии задачи переносятся в **чат задачи** AI2P: автор показывается
  как `gitlab:<логин>`, время и порядок сохраняются. Служебные записи GitLab («изменил метку»,
  «назначил исполнителя», «закрыл») пропускаются — это не разговор людей. Повторный импорт
  добавляет только **новые** сообщения, дублей не делает.
* **Дубли не создаются**: внешний ключ задачи запоминается в виде
  `gitlab:<сервер>:<проект>:<номер>`; повторный импорт ту же задачу пропустит или обновит —
  по чекбоксу. Сервер входит в ключ намеренно: задача №42 вашего GitLab и задача №42
  облачного — разные задачи.

## Импорт одной задачи по ссылке

Рядом с кнопкой массового импорта в списке задач есть кнопка **«Импорт задания по URL»**:

1. Вставьте ссылку вида `https://gitlab.com/<группа>/<проект>/-/issues/<номер>`. Понимаются
   подгруппы, старый вид адреса без `/-/`, хвосты `?…` и `#note_…`, а также адрес своего
   сервера GitLab. Источник переспрашивается, только если активных gitlab-источников
   несколько и по адресу сервера нельзя выбрать один.
2. Содержимое задачи подставится **в форму новой задачи**: заголовок, статья в описании,
   срок, скачанные файлы. Обсуждение попадёт в чат сразу после сохранения задачи.
3. Дозаполните форму (исполнитель, приоритет) и сохраните. Повторный импорт той же задачи
   дубль не создаст.

ИИ-агентам то же действие доступно инструментом `import_task_from_url` (код действия
`AI2P.Tasks.ImportFromUrl` — правила безопасности deny/confirm применяются как обычно).
Какой процедурой импортировать, выбирает **вид ссылки**: агенту не нужно знать, какие
источники заведены.

## Обновление задачи из GitLab

У импортированной задачи заполнена **ссылка импорта** (раздел «Расширенное» формы задачи,
строка в шапке карточки). Кнопка **«обновить»** в карточке такой задачи **переспрашивает**:

* **«Из источника импорта»** — перечитать issue и положить в задачу заголовок, срок,
  описание (со свежими скачанными файлами) и **новые** сообщения обсуждения;
* **«Только здесь»** — просто перечитать задачу, ничего не спрашивая у GitLab;
* **«Отмена»**.

Описание при обновлении переписывается **целиком** — ровно как у массового импорта
с галочкой «обновить существующие». Критерии приёмки, исполнителей, статус, приоритет,
тэги и связи задачи обновление **не трогает**: их ведут здесь, а не в GitLab.

Очистите поле «Ссылка импорта» — задача отвяжется от источника, и переспроса больше не будет.

## Если что-то не работает

| Сообщение | Причина и что делать |
| --- | --- |
| «Токен GitLab не найден (…)» | Токен не введён: откройте источник и нажмите «Установить токен» (шаг 3). У старой установки — проверьте `secrets.json`: путь к файлу указан прямо в сообщении. |
| «Этот сервер ещё не получил ключ организации…» | Сервер подключён к чужой организации, но заявка не подтверждена её дирижёром — без ключа организации значение нечем зашифровать. Подтвердите подключение (Настройки → Серверы). |
| «GitLab не принял ТОКЕН (HTTP 401…)» | Токен неверный, отозван или **просрочен**, либо у него нет права `read_api`. Выпустите новый (шаг 1). Частая причина — скопировано не то значение: сообщение показывает длину введённого (само значение не показывается никогда). |
| «GitLab отказал в доступе (HTTP 403…)» | Токен принят, но у его владельца нет прав на этот проект либо у токена нет `read_api`. |
| «GitLab (…) не нашёл запрошенное (HTTP 404…)» | Неверный путь проекта или номер задачи. **Закрытый проект, невидимый владельцу токена, тоже отвечает 404** — GitLab намеренно не сообщает о существовании чужих проектов. |
| «GitLab отвечает „слишком часто“ (HTTP 429)» | Предел частоты запросов. Подождите минуту и повторите. |
| «У источника импорта не указан проект GitLab» | Поле «Проект GitLab» пустое — массовому импорту неоткуда брать задачи. Впишите путь вида `группа/проект`. |
| «Ссылка … не похожа на задачу GitLab» | Адрес не ведёт на issue: нужен вид `.../-/issues/<номер>`. Ссылка на merge request, доску или эпик не подходит. |
| Импорт прошёл, но «добавлено 0» | Метки не совпали ни с одной задачей, или у проекта нет открытых задач; попробуйте с пустым полем «Метки». |
| Файл из описания не открывается | Файл не скачался (нет прав, больше 200 МБ) — в описании осталась ссылка на GitLab, и она откроется только у того, кто вошёл в GitLab. Причина записана в лог. |

Сообщения приходят целиком в само окно импорта — их не нужно вылавливать из всплывающей
подсказки. Подробности запросов — в логах приложения (`logs/*.jsonl`, записи
`GitLabImporter`): какой адрес запрошен, откуда взят токен и какой он длины (само значение
в лог не пишется никогда), что ответил GitLab.

## Чем GitLab отличается от Trello в этом импорте

| | Trello | GitLab |
| --- | --- | --- |
| Секретов | два: ключ API + токен | один: личный токен |
| Как уезжает секрет | параметрами строки запроса | заголовком `PRIVATE-TOKEN` |
| Что задаёт источник | логин и фильтр по имени доски | адрес сервера, путь проекта, метки |
| Единица импорта | карточка доски | задача (issue) проекта |
| Вложения | отдельным списком у карточки | ссылками внутри текста статьи |
| Внешний ключ задачи | `trello:<id карточки>` | `gitlab:<сервер>:<проект>:<номер>` |
