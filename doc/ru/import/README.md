# Импорт задач: как устроен справочник источников

Каталог с документами видов источника: по файлу на каждый **вид**, имя файла — **код вида**
(`trello.md`, `github.md`, `gitlab.md`). Открывается кнопкой **«i»** рядом с полем «Вид»
в форме источника: **Настройки → Справочники → Импорты**.

Документ привязан к **виду**, а не к записи справочника: как получить ключи внешней
системы, одинаково для всех источников этого вида, и знать это нужно ещё до того, как
запись сохранена.

## Оглавление раздела

* [github](github.md) — Импорт задач из GitHub — инструкция по подключению
* [gitlab](gitlab.md) — Импорт задач из GitLab — инструкция по подключению
* [trello](trello.md) — Импорт задач из Trello — инструкция по подключению

## Что общего у всех видов

**Секретов бывает один или два.** У Trello их два — **API key** и **Token**, поэтому в форме
источника есть и кнопка «Установить ключ API», и кнопка токена. У GitHub и GitLab секрет
**один** — личный токен доступа; кнопки ключа API у них нет вовсе, и источник активируется
по одному токену. Ссылки на секреты вида `trello.*` принадлежат только Trello.

**Секрет принадлежит организации**: он шифруется её ключом и реплицируется на серверы
организации — вводить его на каждом компьютере не нужно.

**Импортов два вида:** массовый (по записи справочника — доска, репозиторий, проект) и
одиночный по ссылке на карточку или задачу. Одиночный выбирает процедуру **по самой
ссылке**, поэтому адрес задачи GitHub и старый вид адреса GitLab (без разделителя `/-/`)
различаются по имени сервера: GitLab принимает старый вид, только если в имени хоста есть
слово `gitlab`.

**Обновление из источника** тоже идёт по ссылке импортированной задачи — кнопка в её
карточке. Импортированная задача помнит, откуда приехала.

## Как добавить документ нового вида

Положите сюда файл `<код вида>.md` — ровно тем кодом, каким вид назван в справочнике
(`trello`, `github`, `gitlab`): имя файла собирает приложение, придумывать его нельзя.
Заведите такой же файл в `../../en/import/` и впишите оба в оглавление разделов
(скриптом `test/t18s1/mktoc.py`).

Внешние адреса в этих документах пишите **полными**, со схемой `https://` — они
открываются кнопкой «i» внутри страницы приложения, и относительная ссылка там мёртвая.

## Чего в этих документах нет

Порядок получения ключей описан по состоянию на день написания документа. Внешние системы
меняют интерфейс своих настроек молча: если названия кнопок разошлись с текстом, ищите
раздел с личными токенами (Personal access tokens) — сама последовательность действий
устойчивее, чем подписи.
