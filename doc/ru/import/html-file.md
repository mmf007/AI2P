# Импорт страницы HTML («Публичный HTML») — инструкция

Запись **«Публичный HTML»** уже есть в справочнике импортов — первой строкой. Настроек и
секретов у неё нет: заводить, вводить ключи и проверять подключение не нужно.

## Как импортировать

Список задач проекта → **«Импорт задания по URL»** → вставьте адрес страницы → **«Импортировать»**.
Вид адреса решает, что произойдёт:

| Адрес | Что импортируется |
| --- | --- |
| `file:///C:/папка/страница.htm` или полный путь `C:\папка\страница.htm` | Сохранённая на диске страница. Картинки из папки `…_files` рядом с ней (её кладёт браузер при «Сохранить как… → полностью») копируются внутрь задачи. Фреймы с локальными файлами разворачиваются. |
| `https://…` или `http://…` | Открытая страница сайта — **только она сама**, по ссылкам импорт не ходит. Картинки скачиваются и копируются внутрь задачи; все ссылки остаются рабочими и ведут на сайт-источник. |

Задача заводится черновиком: заголовок — из `<title>` (иначе из первого `<h1>`), описание —
текст страницы в Markdown. Если исходную страницу потом удалят, задача останется целой.

Адреса Trello, GitHub, GitLab и Figma по-прежнему уходят своим импортёрам — «Публичный HTML»
берёт только то, чего не узнал никто другой.

## Ограничения

* Страница, которую сайт рисует скриптом (одностраничные приложения), приходит почти пустой:
  импорт читает HTML как есть и скрипты не выполняет. Такую страницу сохраните из браузера
  («Сохранить как… → полностью») и импортируйте файл.
* Страница, закрытая входом, не прочитается: cookie браузера импорт не знает.
* Предел — 64 МБ на страницу, 50 МБ на картинку, не больше 300 картинок.
* Стили, формы, видео и звук не переносятся.
* Страница сайта не может забрать файлы этого компьютера: картинки `file:` в ней пропускаются.
* Агенту файл с диска доступен только в каталогах, открытых правилами безопасности задачи.

## Обновление

Кнопка «обновить» в карточке задачи перечитывает страницу по ссылке импорта.
