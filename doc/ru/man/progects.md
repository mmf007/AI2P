# Проекты

**Проект — контейнер всей работы:** задачи, шаблоны, объекты, правила безопасности, опыт и —
самое важное — **папка на диске**, в которой ИИ-агент читает и пишет файлы.

Список открывается кнопкой **«Проекты»** на левой полосе. Это же первое, что видит человек,
который ещё не выбирал проект. Клик по строке открывает **закладку «Проект»** — карточку с
вкладками; выбранный проект запоминается и подставляется во всё новое.

---

## Зачем он нужен

Проект отвечает на вопросы, которые иначе пришлось бы повторять в каждой задаче:

* **где файлы** — папка проекта; без неё агенту не дают файловых инструментов вовсе;
* **кто работает** — команда проекта, а от неё круг исполнителей задачи;
* **как выбирать исполнителя** — ползунок «цена ↔ качество»;
* **что агент уже знает** — опыт проекта, который подставляется в каждое задание;
* **что агенту нельзя** — правила безопасности проекта.

## Папка проекта — почему она пер-серверная

Проект целиком реплицируется между серверами кластера, а вот **каталог у каждого компьютера
свой**: на одном `D:\work\game`, на другом `~/projects/game`. Поэтому путь хранится **отдельной
строкой на каждый сервер** и правится только с этого сервера. В форме проекта каталоги
остальных серверов показаны для чтения — видно, где проект уже развёрнут.

Из того же правила следует то, что иногда удивляет: **признак «активен» тоже пер-серверный**
(в форме он так и подписан — «активен на этом сервере»), и проект, у которого здесь каталог
не указан, здесь активным сделать нельзя. Иначе задачи запускались бы «в никуда».

Путь можно набирать от домашнего каталога (`~/work/проект`) — «~» раскрывают и диалог выбора
папки, и сохранение; в базе он хранится уже раскрытым, потому что его получают инструменты
агента, песочница CLI и репликация файлов.

### Папка `Common`

Это путь **внутри** каталога проекта, содержимое которого реплицируется между серверами:
быстрый способ перегнать соседу результаты, в первую очередь медиа. Настраивается на каждом
сервере отдельно, пусто — не реплицируется.

Путь тут **только относительный** (`media`, `doc/common`): полный путь, `~/…` и выход наверх
`..` отвергаются с внятной ошибкой при сохранении. Внутри работает фильтр **`.repignore`** —
синтаксис как у `.gitignore`, правится кнопкой-фильтром рядом с полем.

### Имя и каталог хранилища

Имя проекта уникально (сохранение с занятым именем блокируется) и предлагается по пути папки.
А вот каталог **файлового хранилища** проекта назван его внешним кодом (`projects/PRJ-3`) и
переименование проекта его не трогает: файлы и относительные пути остаются на месте.

## Вкладки карточки

### Основное

Форма проекта: папка, `Common`, название, команда, «активен», ползунки настроек. Открывается
**в режиме чтения** — правку включает карандаш в правом верхнем углу, на его месте появляется
«сохранить».

Настройки, которые здесь живут, стоят того, чтобы их понимать:

| Настройка | Что делает |
|---|---|
| **цена ↔ качество** | 0.0 — автоподбор берёт тех, кто дешевле, 1.0 — тех, кто лучше; по умолчанию 0.5 |
| **время ↔ качество** | умолчание одноимённого поля задачи: 0.0 — «делай быстро, качеством можно поступиться», 1.0 — «не жалей времени»; по умолчанию 0.5 |
| **предел подстановки опыта** | сколько знаков опыта максимум уедет в задание — суммарно по общим правилам, опыту проекта и опыту узла шаблона; по умолчанию 100 000 |
| **кругов повторной проверки** | сколько раз задача-прогон проверок может вернуть соседей в доработку и дождаться их; по умолчанию 3 |
| **ответственный по умолчанию** | человек из команды, которого форма подставит новой задаче; можно оставить пустым |
| **формат ссылки на объект** | что кладут в буфер кнопки интерфейса: `@obj:OBJ-3` или `@obj:[Герой Вася]`. Читаются **обе** формы всегда |

Две тонкости про «ответственного по умолчанию»: подставляет его **форма**, а не сервер, —
поэтому задача, заведённая мимо формы (подзадача агента, импорт), ответственного не получает;
и смена команды снимает ответственного, не входящего в новую команду.

### Задачи

Тот же список задач (доска / таблица / иерархия, фильтр, поиск), отфильтрованный по этому
проекту. Новая задача, заведённая отсюда, получает **этот** проект и его команду.
Представление, сортировка и фильтр запоминаются, в том числе между запусками. Про саму
задачу — [Задачи](tasks.md).

### Команда

Участники команды проекта со статусами работы и кнопками «запустить»/«остановить» — те же,
что в списке команд (см. [Команды](teams.md)), только здесь, под рукой. Два представления:
иерархия (по умолчанию) и таблица.

### Объекты

Список объектов **этого** проекта: персонажи, локации, реквизит, стили, эталонные кадры,
адаптеры LoRA. Общего списка объектов у организации нет намеренно — объект принадлежит
проекту. Объект хранит **паспорт** — дословный текст для промпта, — а в описание задачи
ставится **ссылка `@obj:OBJ-3`**, которая при каждом запуске задания разворачивается в этот
паспорт и пути эталонных файлов.

Обо всём остальном — виды объектов, четыре представления списка, закладка объекта и его
субобъекты, две ссылки, «что уйдёт в модель», сервер-владелец — отдельная глава:
**[Объекты проекта](objects.md)**.

### Безопасность

Правила безопасности **этого проекта**: что агенту разрешено, что требует подтверждения
человека, что запрещено. Правила проекта уточняют правила организации (Настройки →
Безопасность), а правила задачи — правила проекта.

### Шаблоны

Тот же список шаблонов, что общий, но ограниченный этим проектом; кнопка «новый шаблон»
подставляет проект сама. Подробности — [Шаблоны](templates.md).

### Опыт

**Опыт проекта** — обобщение работы, которое получает **любая** его задача. Таблица: навык,
текст, кем и когда создана и изменена. Фильтр по навыкам множественный, а записи **без
навыка показываются при любом фильтре** — они общие.

Навык у записи означает буквально «эту запись прочитает только исполнитель с этим навыком»,
и это главный инструмент против раздувания промпта: узкий урок не должен ехать всем.
Записи опыта пишет и сам агент, когда выясняет что-то важное для будущих задач.

Три уровня опыта, от общего к частному: **общие правила организации** (Настройки → Общий
опыт) → **опыт проекта** (здесь) → **опыт узла шаблона** ([Шаблоны](templates.md)). Когда
всё вместе не влезает в предел, отбор идёт по прицельности: узел шаблона важнее проекта,
проект важнее общих правил.

### История

Тот же журнал работ, что общий экран «История работ», но жёстко ограниченный этим проектом:
фильтры по исполнителю и типу события, клик по коду задачи открывает её карточку, клик по
ячейке «Детали» показывает событие целиком с кнопкой «скопировать». Сюда же попадают запуск
работы команды и результат подключения каждого участника с текстом ошибки.

## Мелочи, которые экономят время

* **Текущий проект** переключается в верхнем тулбаре («Проект: …»), а не кнопкой «выбрать» в
  списке. Он определяет, куда попадёт новая задача.
* Один человек работает с несколькими проектами — поэтому список проектов остался просто
  списком, а работа идёт в закладках.
* **Неактивный проект** не подставляется в новые задачи.
* Заголовок закладки двухстрочный: вид («Проект») и либо начало названия, либо короткий код
  (`PRJ-2`) — переключается в Настройки → Основное.
