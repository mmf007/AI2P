# Расписание

**Расписание — календарь, по которому система заводит работу сама.**   
Например:  
* Раз в неделю развернуть шаблон «еженедельный отчёт»   
* раз в месяц — «закрыть месяц», раз в квартал — «квартальнаяревизия»  
* раз в ночь — унести старые задачи в архив.

Открывается кнопкой с календарём на левой полосе (и одноимённым пунктом меню).

---

## Что оно умеет запускать

Два разных рода срабатывания, и это видно прямо в форме:

1. **Копию шаблона задач.** Срабатывание разворачивает шаблон точно так же, как кнопка
   «Создать задачу» в его карточке: со всей иерархией подзадач, с подбором исполнителей и с
   базовой датой.
2. **Действие системы.** Задача при этом не заводится и исполнитель не подбирается, поэтому
   поля шаблона, проекта, смещения и правила подбора в форме прячутся целиком. Сегодня
   действие одно — **автоматическая архивация** (см. [Архивация](Archives.md)).

## Поля расписания

| Поле | Зачем |
|---|---|
| **Проект** | по умолчанию текущий; ограничивает выбор шаблона и показывается колонкой. Может быть пустым |
| **Шаблон** | верхнего уровня; в форме есть поиск по названию. Видны шаблоны выбранного проекта **и** шаблоны без проекта |
| **Смещение базовой даты** | часы и минуты; базовая дата созданных задач = момент срабатывания + смещение |
| **Правило поиска исполнителей** | «сначала ИИ, потом человек», «сначала человек, потом ИИ» или без автоподбора |
| **Однократно / периодически** | у однократного — дата и время запуска |
| **Период** | недельный (дни недели чипами + время, как будильник в телефоне), месячный (день месяца + время), квартальный (месяц квартала 1–3 + день + время, кварталы с января) |
| **Плановая длительность, мин** | для проверки перехлёста |
| **Сервер** | на нём расписание правится и на нём же срабатывает |
| **Активно** | выключенное расписание не срабатывает |

Времена периодов — **локальное время компьютера**. В коротком месяце день сжимается до
последнего: «31-е» в феврале сработает 28-го (или 29-го).

### Сервер — не формальность

Расписание реплицируется между серверами кластера, и **без поля «сервер» одно расписание
сработало бы на каждом сервере разом**. Поэтому у него есть владелец; не указан — расписание
ведёт дирижёр организации. В списке расписаний есть фильтр по серверам, и **по умолчанию он
показывает только текущий** — иначе картина выглядела бы вдвое гуще, чем есть.

### Проверка перехлёста

Если в шаблоне (в любом его узле) указан исполнитель, при сохранении система проверяет, что
он не занят другим активным расписанием в то же время: сравниваются окна занятости
(срабатывание + смещение, длина — плановая длительность) на ближайшие 62 дня. Перехлёст —
**ошибка сохранения** с указанием исполнителя, расписания и времени, а не тихое наложение.

## Два представления

Переключаются в тулбаре, выбор запоминается между запусками.

* **Таблица** — ID, проект, шаблон (или название действия), «когда» (сводка вида и периода),
  смещение, длительность, правило подбора, «активно». Сортировка кликом по любой колонке.
* **Календарь** — месячная сетка с листанием. В ячейке дня — чипы срабатываний: сначала
  время, затем код шаблона либо начало его заголовка (что именно — задаёт настройка «ячейка
  календаря расписаний» в Настройки → Основное). Подсказка чипа — «Проект — Название
  шаблона», клик открывает форму.

## Просроченные срабатывания

Главная особенность расписания в AI2P, и её стоит понять сразу: **AI2P — это программа на
вашем компьютере, а не служба в облаке.** Пока компьютер выключен, срабатывать нечему.

Поэтому при старте приложения система собирает всё, что было пропущено, в список
**просроченных срабатываний** — он показан **сверху** закладки: расписание, шаблон, сколько
пропущено, последнее время. По каждому человек решает сам: **«запустить сейчас»** или
**«удалить из списка»**.

Два следствия, из-за которых иначе бывает непонятно:

* срабатывания, наступающие **во время работы** приложения, запускаются автоматически
  (проверка раз в минуту) — решать ничего не надо;
* **пока у расписания висят просроченные, новые срабатывания ждут решения человека**. Если
  расписание «замолчало», сначала посмотрите наверх этой закладки.

Держать AI2P запущенным постоянно можно — для этого его делают [службой операционной
системы](service.md); тогда просроченных обычно не бывает вовсе.

## Мелочи, которые экономят время

* Событие срабатывания пишется в журнал (`schedule.triggered`) — в «Истории работ» видно, что
  и когда развернулось.
* Блокирующие задачи скопированных узлов работают как обычно: запуск подождёт их завершения.
* Расписание с пустым проектом видит все шаблоны без проекта — так удобно заводить общие
  регулярные процессы, не привязанные к одному проекту.
