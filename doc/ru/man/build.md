# AI2P — сборка, выкладка и устройство репозитория

> Главная страница репозитория — `Readme.md` в его корне; документация для пользователя —
> [краткое описание](../README.md) и [оглавление](../index.md). Здесь всё для того, кто
> собирает AI2P из исходников.

Система совместной работы ИИ-агентов и людей над задачами: планировщик работ, оркестратор ИИ-агентов, накопитель опыта. Работает локально (Windows 10–11, Linux, macOS), UI — через web-браузер.

Документация делится надвое: **проектная** — в каталоге `doc/` в корне репозитория (`doc/AI2P_ТЗ_v1.NN.md` — описание системы как она есть, предыдущие версии там же; с версии 1.60 номер ТЗ совпадает с версией приложения; `doc/AI2P_release.md` — версии, выкладка и обновление), и **поставляемая вместе с программой** — в `AI2P_app/doc/` рядом с кодом: документы моделей ([`models/`](../models/README.md)) и видов импорта ([`import/`](../import/README.md)), они открываются в UI кнопкой «i». Каталог `AI2P_app/doc` целиком копируется в релизную выкладку.

> Ссылки на файлы за пределами `AI2P_app/doc` в поставляемом документе не ставятся: он
> рисуется внутри приложения, и относительная ссылка наружу там никуда не ведёт (ТЗ гл. 14).

**Состояние: этап 1 — локальный планировщик задач.** Реализовано: SQLite + event log + файловое хранилище (ТЗ гл. 6), сущности (гл. 2), HTTP API (API-first, гл. 3), UI в стиле VS Code (гл. 11): доска задач (kanban, drag-n-drop), карточка задачи (описание .md, история, чат, артефакты, задания), списки/формы проектов, команд, исполнителей, история работ с фильтрами, Inbox человека, настройки; HumanConnector (человек-исполнитель через очередь заданий); мультиязычность ru/en (JSON-словари `i18n/`).

## Установка окружения сборки

Скрипты `install_required` проверяют и ставят инструменты сборки: **.NET SDK 8+**, **рантайм ASP.NET Core 8.x**, **CMake**, **компилятор C/C++**, затем инициализируют git submodules (если есть `.gitmodules`). Скрипты идемпотентны — уже установленное не переустанавливают; можно запускать повторно для проверки.

> **Почему нужен именно рантайм 8.x, даже если стоит SDK 9/10.** Приложение собирается под net8.0; более новый SDK его собирает, но запускать на рантайме 9/10 (roll-forward) нельзя: клиентский скрипт Blazor (`blazor.web.js`) берётся версии 8, а сервер работал бы на 9/10 — интерактивность (кнопки, события) молча перестаёт работать. Пример: brew-каск `dotnet-sdk` на macOS сейчас ставит .NET 10 — скрипт доставит рядом рантайм 8.0, и приложение будет запускаться на нём.

### Windows

Запускать в обычной консоли (cmd или PowerShell); возможны запросы подтверждения UAC. Требуется winget («App Installer» из Microsoft Store, есть в Windows 10/11 по умолчанию).

```bat
cd AI2P_app
install_required.bat
```
Запросит права админитратора. Но не сразу. Диалог может на фронте не появиться. Надо поискать среди активеных приложений   

Что делает:

1. **.NET SDK 8+** — если нет версии ≥ 8, ставит `Microsoft.DotNet.SDK.8` через winget; затем проверяет **рантайм ASP.NET Core 8.x** и при отсутствии ставит `Microsoft.DotNet.AspNetCore.8`;
2. **CMake** — если нет, ставит `Kitware.CMake`;
3. **Компилятор C/C++** — ищет MSVC через vswhere; если нет — ставит VS 2022 Build Tools с workload'ом VCTools (большая загрузка, несколько ГБ);
4. **git submodules** — `git submodule update --init --recursive` (пропускается, пока нет `.gitmodules`).

После установки откройте **новую** консоль (чтобы обновился PATH) и запустите скрипт ещё раз — он должен показать все `[OK]`.

### Linux (apt / dnf) и macOS (brew)

```sh
cd AI2P_app
chmod +x install_required.sh
./install_required.sh
```

Что делает: определяет ОС и пакетный менеджер (apt-get / dnf / brew), затем те же шаги:

1. **.NET SDK 8+** — `dotnet-sdk-8.0` (macOS: `brew install --cask dotnet-sdk`); затем **рантайм ASP.NET Core 8.x** — Linux: пакет `aspnetcore-runtime-8.0`; macOS: официальный `dotnet-install.sh` ставит рантайм 8.0 рядом с имеющимся SDK в тот же каталог dotnet (может запросить sudo);
2. **CMake**;
3. **Компилятор C/C++** — Linux: `build-essential` (apt) или `gcc gcc-c++ make` (dnf); macOS: Xcode Command Line Tools (`xcode-select --install` — появится диалог, после установки запустить скрипт повторно);
4. **git submodules** — как на Windows.

Установка пакетов может запросить пароль sudo. На macOS требуется заранее установленный [Homebrew](https://brew.sh/).

## Установка пакетов

Зависимости делятся на два вида (ТЗ, гл. 13.1):

1. **Бинарные (NuGet)** — MudBlazor, Microsoft.Data.Sqlite, Serilog, Microsoft.Extensions.AI, OpenAI SDK, Anthropic.SDK, ModelContextProtocol и др. Их **не нужно ставить отдельно**: `dotnet restore` (часть `dotnet build`) скачивает их автоматически по ссылкам из `.csproj`.
2. **Пакеты-подпроекты (исходники)** в `packages/` — sqlite-vec, gigachat-adapter (кандидаты, понадобятся на этапах 3+). Отдельных скриптов у них больше нет: `install_packages.bat` и `install_packages.sh` удалены в T-65-S0 как ненужные — списка пакетов в них не появилось за всю историю проекта, а работу, которую им приписывали, делают другие: инструменты сборки ставит `install_required.*`, пакеты для моделей (ComfyUI, musubi-tuner, Python) — сама программа при установке модели. Понадобится подпроект — он добавляется одной командой:

```sh
git submodule add <адрес> packages/<имя>
```

Каталога `packages/` в репозитории сейчас нет вовсе (пустой удалён в T-207): все текущие
зависимости — NuGet, а команда `git submodule add` заводит каталог сама. Так же удалён и
пустой `native/` — задел под C/C++ плагины (CMake).

## Язык вывода скриптов

Сборочные и установочные скрипты говорят **по-английски по умолчанию** (T-65-S0). Скрипт
по языкам не дублируется: тексты вынесены наружу, в каталог `i18n/`:

```
i18n/scripts.en.txt          сообщения, базовый язык
i18n/scripts.ru.txt          тот же набор ключей по-русски
i18n/loc.ps1                 загрузчик для PowerShell
i18n/loc.sh                  загрузчик для POSIX sh
i18n/help/<скрипт>.<язык>.txt  текст, который печатает --help
```

Язык выбирается по лесенке, первый непустой выигрывает:

1. ключ скрипта — `-Lang ru` (PowerShell) или `--lang ru` (sh);
2. переменная окружения `AI2P_LANG`;
3. `en`.

Ключ `"language"` из `config.json` намеренно НЕ спрашивается: язык интерфейса приложения
и язык консоли установки — разные вещи.

Справку печатает `--help` (у `.ps1` — `-Help`), и берётся она из отдельного файла:

```powershell
install.cmd --help
install.cmd D:\AI2P -Lang ru
.\makeAsServise.cmd --help
.\MakePackage.cmd --help
```

```sh
./install.sh --help
./install.sh ~/ai/AI2P --lang ru
./makeAsServise.sh --help
./MakePackage.sh --help
```

Обёртки `.cmd`/`.bat` сами ничего не переводят и написаны **чистым ASCII по-английски**:
`cmd.exe` декодирует файл в кодировке консоли, а позицию чтения держит в байтах, и один
многобайтовый символ сдвигает разбор всего дальнейшего (поймано живьём в T-34-S0). Весь
текст, включая `--help`, они пробрасывают в свой `.ps1`.

Новый язык — это **два файла и ни строчки кода**: копия `scripts.en.txt` с переведёнными
значениями и копия нужных файлов `help/`. Составы ключей обязаны сходиться посчётно, это
сторожит `T65S0Tests`.

Собственный вывод `build.*`, `buildRelease.*` и `install_required.*` не переведён
намеренно (ярус B разбора T-64-S0): их запускают на машине сборки, и они уже английские
либо смешанные. Справка `--help` у них есть.

## Сборка и запуск

Сборка всего решения (сейчас только C#; C/C++ добавится позже) одним скриптом:

```powershell
# Windows
cd AI2P_app
.\build.ps1              # Debug; вариант: .\build.ps1 -Configuration Release
build.cmd                # то же самое; запускается по Enter из проводника/FAR
                         # (у .ps1 в Windows ассоциация «редактировать», не «выполнить»);
                         # вариант: build.cmd Release
```

```sh
# Linux / macOS
cd AI2P_app
chmod +x build.sh
./build.sh               # Debug; вариант: ./build.sh Release
```

Запуск:

```sh
dotnet run --project src/AI2P.Server
```

Сервер поднимает UI на `http://localhost:5480` (порт и прочее — в `config.json`) и открывает браузер (`openBrowserOnStart`). Путь к конфигу можно переопределить: `dotnet run --project src/AI2P.Server -- --config <путь>`.

`config.json` с настройками по умолчанию копируется в каталог сборки **только если его там ещё нет** — локальные правки не затираются пересборкой (ТЗ гл. 10).

## Релизная выкладка в отдельный каталог

Выкладка — самодостаточный комплект файлов, который запускается без исходников и без `dotnet run`.
Нужна, чтобы рядом с разрабатываемой версией оставалась работающая старая.

```powershell
# Windows
cd AI2P_app
buildRelease.cmd                          # Release в builds\windows\release
buildRelease.cmd D:\AI2P_v1.45            # в указанный каталог
.\buildRelease.ps1 -Clean                 # очистить каталог (кроме данных) и выложить заново
.\buildRelease.ps1 -SelfContained         # с рантаймом внутри: ASP.NET Core 8 на машине не нужен
```

```sh
# Linux / macOS
cd AI2P_app
chmod +x buildRelease.sh
./buildRelease.sh                         # Release в builds/linux/release
./buildRelease.sh ~/ai/AI2P --clean
```

До T-285 эти скрипты назывались `publish.cmd` / `publish.ps1` / `publish.sh` — имя сменилось,
поведение прежнее.

Сам каталог `builds` лежит **внутри рабочего каталога** `AI2P_app` — рядом с `AI2P.sln` (T-131-S0);
до 1.114 он создавался на уровень выше, снаружи рабочего каталога.

Между `builds` и `release`/`releasefull` стоит **каталог операционной системы** (T-243):
`windows`, `linux` или `macos`. Систему задаёт RID полной выкладки (`-Runtime`/`--runtime`),
а у обычной — та, на которой идёт сборка; она же определяет, какие скрипты установки
кладутся в выкладку. Собранное под разные системы больше не затирает друг друга.

Запуск выложенной копии — `AI2P.Server.exe` (Windows) или `./AI2P.Server` из её каталога;
текущий каталог процесса значения не имеет.

**Сервер работает от ОБЫЧНОГО пользователя, не от root** (T-135). Каталог установки на
Linux и macOS — `~/ai/AI2P`: данные (`data/`), журналы (`logs/`), настройки и секреты лежат
внутри него, за пределы домашнего каталога сервер не пишет, а порт (5480) непривилегированный.
Права root нужны только установщику зависимостей (`install_required.sh`)
— это разовая операция уровня системы. Файл `secrets.json` приложение закрывает правами `0600`:
в нём пароль администратора сервера и ключи организаций.

Путь с `~` понимают и скрипты, и само приложение: `./install.sh ~/ai/AI2P`, каталоги в
`config.json` и в форме локального сервера (`~/ai`), каталог проекта, правила безопасности.

Что выкладка **не копирует** и при повторном запуске **не перезаписывает** — переносится руками:

* `data/` — база и файлы проектов;
* `logs/` — при необходимости;
* `secrets.json` — ключи API (без него облачные модели неактивны; рядом лежит `secrets.example.json`);
* `config.json` — создаётся из умолчаний только если его в каталоге ещё нет.

Две версии одновременно на одном порту не работают (проверка одного экземпляра, ТЗ гл. 3):
вторая увидит занятый порт, откроет браузер на первой и завершится. Чтобы держать обе запущенными,
поменяйте `ui.port` в `config.json` выложенной копии.

## Пакет установки одним файлом (T-285)

Выкладка — это каталог; отдавать её человеку неудобно. `MakePackage` делает из готовой
выкладки **один файл установщика**. Скрипт кладёт в выкладку сам `buildRelease`, и запускать
его надо **из каталога выкладки**; результат ложится в `../../packages` (то есть `builds/packages`).

```powershell
# Windows: нужен Inno Setup 6 (install_required.bat его ставит)
cd builds\windows\releasefull
.\MakePackage.cmd                    # -> ..\..\packages\AI2P_full_v_1_99_win64.exe
cd ..\release
.\MakePackage.cmd                    # -> ..\..\packages\AI2P_v_1_99_win64.exe
```

```sh
# Linux / macOS: нужен makeself (install_required.sh его ставит)
cd builds/linux/releasefull
./MakePackage.sh                     # -> ../../packages/AI2P_full_v_1_99_Linux.run
```

Имя файла складывается само из `version.json` выкладки — номер билда `NN` спрашивать не надо:

| выкладка | Windows | Linux | macOS |
|---|---|---|---|
| `releasefull` | `AI2P_full_v_1_NN_win64.exe` | `AI2P_full_v_1_NN_Linux.run` | `AI2P_full_v_1_NN_MacOs.run` |
| `release` | `AI2P_v_1_NN_win64.exe` | `AI2P_v_1_NN_Linux.run` | `AI2P_v_1_NN_MacOs.run` |

Расширение задаёт вид установщика: на Windows это Inno Setup (`.exe`), на Linux и macOS —
самораспаковывающийся архив makeself (`.run`), который внутри запускает тот же `install.sh`.
Пакет собирается на той системе, под которую собрана выкладка: собрать `.run` из Windows нечем,
и наоборот — скрипт об этом честно скажет.

Данные пользователя (`data/`, `logs/`, `secrets/`, `secrets.json`, опись `installed.json`)
в пакет не попадают, а при установке поверх прежней не трогаются: `config.json` кладётся,
только если его нет, рядом всегда ложится `config.new.json` — приложение сольёт их при
первом старте (`ConfigMerge`).

**Где лежат рабочие файлы (T-287).** Рядом с программой — но только если в её каталог можно
писать. Установка «для всех пользователей» (`C:\Program Files\AI2P`) обычному пользователю
на запись закрыта, поэтому `config.json`, `data/`, `logs/` и `secrets/` у неё лежат в общем
каталоге данных компьютера: на Windows `C:\ProgramData\AI2P`, на Linux и macOS `/var/lib/ai2p`
(а если и туда нельзя — в каталоге данных пользователя). Правило живёт в одном месте —
`AppHome` (`src/AI2P.Server/AppHome.cs`), скрипты его не повторяют, а лишь ищут уже заведённый
`config.json` в тех же местах. Каталог задаётся и вручную: переменной `AI2P_HOME` либо ключом
`--config`. Подробности — `doc/ru/man/install.md`.

```
├── AI2P.Core/        — ядро: сущности (гл. 2), события (п. 6.4.3), контракты API,

│                       карточка задачи, Inbox, история, справочники; ApiClient, i18n
└── AI2P.Server/      — ASP.NET Core host: HTTP API (/api/...) + Blazor Server UI,
                        config.json, Serilog (логи .jsonl)
tests/     — AI2P.Tests: тесты хранилища, event log, цикла человек-исполнитель
i18n/      — словари локализации (ru.json, en.json) и тексты сборочных
              и установочных скриптов (scripts.<язык>.txt, loc.ps1, loc.sh,
              help/<скрипт>.<язык>.txt, T-65-S0) — копируются в каталог сборки
doc/       — документация при коде
```

## Хранилище данных

Каталог `storage.dataDir` из `config.json` (по умолчанию `./data` рядом с приложением):
`ai2p.db` (SQLite, WAL) + `projects/<slug>/tasks/<T-N>/description.md`, `artifacts/`, `.trash/`.
Первичный источник истины по истории — журнал событий (таблица `events`); технические логи —
`logging.dir`, файлы `ai2p-YYYYMMDD.jsonl`. Второй экземпляр приложения обнаруживает занятый
порт, открывает браузер на работающем экземпляре и завершается (ТЗ гл. 3, принцип 5).
