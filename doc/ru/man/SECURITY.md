# Политика безопасности AI2P

## Поддерживаемые версии

Исправления безопасности выходят только для **последней выпущенной версии** AI2P
(страница Releases репозитория). Прежние версии не исправляются — обновитесь до последней:
установка поверх прежней сохраняет данные, настройки и ключи.

| Версия | Поддерживается |
|---|---|
| последний выпуск | да |
| все более ранние | нет |

## Как сообщить об уязвимости

**Не заводите публичный issue** и не пишите об уязвимости в Discussions: пока исправления
нет, публичное описание помогает тому, кто захочет ею воспользоваться.

Сообщайте закрыто одним из способов:

1. **GitHub → вкладка Security → Report a vulnerability** (Private vulnerability reporting) —
   основной способ. Сообщение видят только сопровождающие репозитория.
2. **Почта** — на адрес, указанный в профиле владельца репозитория на GitHub, с темой
   «AI2P security».

Что приложить к сообщению:

* версию AI2P (файл `version.json` в каталоге установки) и ОС;
* что именно уязвимо и чем это грозит;
* шаги воспроизведения или пример (запрос, файл, текст задачи);
* если знаете — предлагаемое исправление.

## Сроки ответа

* подтверждение получения — в течение **7 дней**;
* первая оценка (уязвимость или нет, насколько серьёзна) — в течение **30 дней**;
* исправление выходит в ближайшем выпуске; о сроке мы договоримся с вами, и до выхода
  исправления просим подробности не публиковать. Если хотите — укажем вас в описании выпуска.

## Модель угроз: что AI2P защищает, а что нет

AI2P — локальная программа: сервер работает на вашем компьютере, и ИИ-агенты, которых он
запускает, работают на нём же. Отсюда границы защиты, о которых надо знать заранее.

**CLI-агент работает под пользователем сервера.** Агент командной строки (Claude Code и
другие CLI-исполнители) запускается отдельным процессом от имени той же учётной записи ОС,
что и сервер AI2P, без песочницы и без отдельной изоляции. Правила безопасности задачи
(разрешённые и запрещённые каталоги, действия) действуют на инструменты самого AI2P и
передаются агенту в задании, но **ОС их не навязывает**: собственные средства агента
(чтение файлов, поиск, оболочка) рабочим каталогом проекта не ограничены. Значит, агент
**может прочитать файлы за пределами проекта** — всё, что доступно этой учётной записи,
включая ключи и токены в домашнем каталоге. Профайлы дистрибутива запускают агента в режиме
правки без подтверждений.

Что из этого следует на практике:

* запускайте сервер AI2P от **отдельной учётной записи ОС** без доступа к чужим и личным
  данным, если агенту доверено не всё на машине; на Linux можно запускать в контейнере,
  смонтировав внутрь только каталоги проектов;
* не держите на этой машине секретов, которые агенту видеть нельзя;
* правила «запретить»/«спросить» для CLI-агента — договорённость, а не барьер; барьер —
  права ОС;
* текст задачи, импортированной из внешней системы (Trello, GitHub, GitLab, Figma), — это
  ввод от постороннего: он может содержать указания, которые агент примет к исполнению
  (prompt injection). Проверяйте задачи из чужих источников, прежде чем отдавать их агенту.

**Сервер и сеть.** По умолчанию UI и API слушают `localhost`. Доступ к `/api` закрыт входом.
Открывая сервер в сеть (несколько серверов, доступ с телефона), включайте HTTPS (см. «HTTPS» в
руководстве администратора) и не публикуйте сервер в интернет без обратного прокси с
собственной защитой.

**Секреты.** Ключи API и пароль администратора хранятся на диске в каталоге установки
(`secrets.json`, `secrets/`) открытым текстом под правами пользователя сервера (на Linux и
macOS — `0600`). Их защита — права файловой системы и шифрование диска.

Уязвимостью мы считаем обход этих границ: доступ к API без входа, выход агента за правила
там, где AI2P обещает их соблюдать своими инструментами, утечку секретов в журналы, задачи
или реплику на другой сервер, выполнение кода от данных импорта или репликации и т. п.
То, что CLI-агент читает файлы своей учётной записи, — описанное выше свойство, а не уязвимость.
