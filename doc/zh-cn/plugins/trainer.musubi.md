# Musubi Tuner (LoRA) —— 插件 `trainer.musubi`

**它做什么：** 用 musubi-tuner（kohya-ss）训练 **LoRA** 适配器 —— 缓存 latents、缓存文本
编码器输出，以及训练本身。这项工作要跑好几个小时，因此由**单独的任务**以「自动软件」执行者
来完成，而不是由 AI 智能体的工具来完成。

**为什么需要它。** Kandinsky 官方的训练器要求多块显卡和 Linux；musubi-tuner 一块显卡就够，
能在 Windows 上运行，并且保存适配器文件时用的是 ComfyUI 认识的键名。LoRA 编辑器里的「训练」
按钮创建的任务，正是落在这个插件上。

训练器源码：https://github.com/kohya-ss/musubi-tuner

---

## 程序

这个插件有**两个**程序，而且两个都是必需的：

| 记录 | 这是什么 | 如何安装 |
|---|---|---|
| **Python 3.10–3.12** | 三个步骤都用它来启动 | 用「安装」按钮（我们的 `python` 软件包），或者指定已装好的 Python 的路径。musubi-tuner 在 3.13 上装不上，找到的 3.13 会被判为不合适 |
| **Musubi Tuner** | 训练器的脚本目录 | 用「安装」按钮（v0.3.4 源码），或者指定你解压到的目录：其中有 `kandinsky5_train_network.py`。它不在 `PATH` 里查找：那是目录，不是程序 |

带 torch 的环境由训练器首次训练时自行在 `.venv` 子目录中创建。

**插件记录通常是自动创建的** —— 在安装声明了训练软件包的模型时（Kandinsky 5 的两条记录都
声明了）。同一时刻，找到的程序会被写入空的路径字段。初始化仍然由人用「初始化」按钮来做：
它会创建动作名录条目，也就是安全规则挂靠的那些点。

## 长时间运行的操作

三个步骤，顺序就是这样：

| 操作 | 做什么 |
|---|---|
| `lora.cacheLatents` | 把数据集画面过一遍 VAE，把 latents 存入缓存 |
| `lora.cacheText` | 按画面说明计算文本编码器（Qwen2.5-VL 与 CLIP）的输出；这一步必需，没有它训练不会开始 |
| `lora.train` | 适配器训练本身；标有**「单实例」** |

训练上的「单实例」标记不是摆设：显卡只有一块，同时启动第二个训练，一分钟内就会因显存不足而
失败。第二个任务会在队列里**等待**。

训练的结果是工作目录中按适配器名称掩码**最新的那个** `.safetensors` 文件：轮次文件的名字事先
无从知晓。上限：沉默超时 15 分钟，总上限为一天。

## 记录的设置

在**「设置 → 插件与 MCP」**的记录表单里设定；在任务文本里无法更改。

| 键 | 默认值 | 含义 |
|---|---|---|
| `scripts` | 空 | musubi-tuner 的脚本目录 —— 必须填写 |
| `dit`、`vae` | 空 | 模型的权重文件 |
| `task` | `k5-lite-t2v-5s-sd` | 训练器任务；另一个选项是 `k5-lite-i2v-5s-sd` |
| `textEncoderQwen` | `Qwen/Qwen2.5-VL-7B-Instruct` | 文本编码器 |
| `textEncoderClip` | `openai/clip-vit-large-patch14` | 第二个文本编码器 |
| `steps` | `2000` | 训练步数 |
| `networkDim`、`networkAlpha` | `32`、`32` | LoRA 网络的规模 |
| `learningRate` | `1e-4` | 学习率 |
| `mixedPrecision` | `bf16` | 计算精度（`bf16`、`fp16`、`no`） |
| `outputName` | `lora` | 适配器文件名 |

训练器需要文本编码器的**原始**权重（Qwen2.5-VL 约 16 GB），而不是 ComfyUI 的精简版：用那些
是训练不起来的。

## 操作系统方面的限制

**Windows** —— 我们的 Python 和 musubi-tuner 软件包就是为它准备的。**Linux 与 macOS** ——
训练器支持它们，但我们没有实机验证过：在它们上面更稳妥的做法是自行安装 Python 和脚本，然后
手工指定路径。

无论如何都需要显卡：靠处理器，训练在合理时间内是算不完的。

---

## 这个插件不做什么

* **不向 AI 智能体发布工具** —— 训练是以任务的形式建立的，不是智能体的调用；
* **不组装数据集**：画面、说明和训练器的配置文件由 AI2P 自己按模型设置准备；
* **`.venv` 环境**由训练器创建，而不是插件；
* 目前这三个操作写在清单里，但 Kandinsky 训练的实际启动由模型配置档中的命令完成；插件依然
  提供与服务器的绑定、「单实例」标记，以及安全规则挂靠的那个点。
