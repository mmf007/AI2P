# Shotcut / Kdenlive（MLT XML）

**插件代码：** `editor.shotcut`
**类型：** 网关（`gateway`）
**交换格式：** MLT XML —— 同一个文件既能在 Shotcut 中打开（`.mlt`），也能在 Kdenlive 中打开
**软件：** 由我们安装（便携版 Shotcut），或者直接使用系统里已有的 `melt`
**功能：** 根据项目媒体库生成时间线，并**在无窗口的情况下按它算出成片**

## 为什么它是四个网关里的首选

本分支的四个编辑器（Shotcut/Kdenlive、DaVinci Resolve、Blender VSE、OpenShot）当中，只有它
有**无窗口、无人值守的渲染**：MLT 自带的 `melt` 程序读取我们生成的文件，直接写出成片 `mp4`。
Resolve 和 OpenShot 根本没有这条路；Blender 有，但要经由执行我们生成的 Python 脚本。

因此这里的链条是闭合的：智能体生成时间线 → 智能体算出成片 → 人拿到文件形式的结果。全程没有
一步需要鼠标。

第二个理由是**一个文件对应两个编辑器**。MLT XML 是 Shotcut 的原生格式，Kdenlive 同样能读
（`项目 → 打开`）。所以不必再为 Kdenlive 单做一个网关。

## 智能体的动作

| 工具 | 做什么 |
|---|---|
| `shotcut_timeline_write` | 根据项目媒体库生成 `ai2p_library.mlt` |
| `shotcut_render` | 用 `melt` 程序按生成好的时间线算出成片 |

`shotcut_timeline_write` 的参数（全部可选）：

| 字段 | 含义 |
|---|---|
| `scene` | 只取这一场景的资源 |
| `kind` | 只取这一类媒体（`video`、`audio`、`image`、`subtitle`、`project`） |
| `tag` | 只取带此标签的资源 |
| `file` | 文件放到哪里；默认是项目文件夹根目录下的 `ai2p_library.mlt` |

`shotcut_render` 的参数：

| 字段 | 含义 |
|---|---|
| `file` | 渲染什么；默认 `ai2p_library.mlt` |
| `out` | 结果放到哪里；扩展名 `.mp4`，编码 H.264 + AAC |

**渲染没有自己的命令行。** `melt` 的参数由插件清单固定，智能体只传两个路径。系统里根本没有
「执行任意命令」这种动作，而且是刻意为之：那等于在有写文件权限的前提下执行别人的代码，安全
规则收不住。

片段的顺序**与 `media_list` 打印出来的一致**：场景、次序（`order`）、条次（`take`）、对象代码。
看过列表的人，在编辑器里必须看到一模一样的顺序。

轨道分配：

| 轨道 | 放什么 |
|---|---|
| `V1` | `video`、`image`、`project` |
| `A1` | `audio`（该轨道带 `hide="video"` 标记） |

时长未知的资源（图片、字卡）会得到 **5 秒**，而不是零：零长度的片段就是一个悄无声息消失的镜头。

## 软件

插件首先**在本机查找程序**：在 `PATH` 中查找 `melt`、`qmelt`、`melt.exe`、`qmelt.exe`，用
`--version` 参数校验，可用的最低版本是 **7.0**。找到就直接用；找不到，**「安装」**按钮会下载
便携版 Shotcut 并自行解包。第三条路是在插件表单里手工指定路径（**设置 → 插件与 MCP →
Shotcut / Kdenlive (MLT XML)**）；程序文件和安装目录都可以。

Windows 版 Shotcut 里，该程序叫 **`melt.exe`**，而不是 `qmelt.exe` —— 两个名字都要找。Linux
的发行版构建和部分 macOS 构建里它叫 `qmelt`。

程序路径保存**在本服务器的 `config.json` 中**，从不复制：集群里邻居机器上的 Shotcut 装在别的
路径，而且有一半服务器上根本没有它。插件描述则相反，会复制到整个组织。

只要程序还没找到，插件在本服务器上的状态就是**「正在查找软件」**，它的动作不会发布给智能体：
一个注定回答「拒绝」的工具，只会白白浪费智能体的一轮。这正是「本服务器上未找到该程序」这条
拒绝的含义。

## 操作系统限制

| 系统 | 需要知道什么 |
|---|---|
| **Windows** | 没有任何附加条件。渲染程序叫 `melt.exe`，与 `shotcut.exe` 一起放在安装目录里。不需要、也不会设置 `QT_QPA_PLATFORM` 环境变量。 |
| **Linux** | 在**没有显示器**的服务器上，`melt` 根本起不来 —— 会以「could not connect to display」失败，因为它是 Qt 程序。因此插件用 `QT_QPA_PLATFORM=offscreen` 启动它；该变量**只在 Linux 上**设置（清单里的 `envOs`）。如果您手工调用 `melt`，请自己设置它。发行版构建里程序通常叫 `melt`，Shotcut 自带的那份叫 `qmelt`。 |
| **macOS** | 程序在**应用程序包内部**：`/Applications/Shotcut.app/Contents/MacOS/qmelt`。它不在 `PATH` 里，所以自动查找多半什么也找不到 —— 路径要手工指定。Homebrew 的构建（`brew install mlt`）会在 `PATH` 里留下 `melt`，同样可用。 |
| **所有系统** | 编码器的种类取决于 MLT 的构建。我们的默认值 —— 视频 `libx264`、音频 `aac` —— 在三个系统的 Shotcut 发行包里都有，但系统自带的精简版 MLT 可能没有；那时渲染会带着 `melt` 本身的报错拒绝，素材需要先用 `tool.ffmpeg` 插件处理。 |
| **Kdenlive** | 文件能打开，但 Kdenlive 在打开时会**按自己的项目配置重新换算**。如果我们时间线的帧率与 Kdenlive 的配置不一致，片段时长就会错位：请让两边的「每秒帧数」保持相同。 |

## 插件记录的设置

**设置 → 插件与 MCP → Shotcut / Kdenlive (MLT XML) → 「配置」：**

| 设置 | 默认值 | 含义 |
|---|---|---|
| 每秒帧数 | 25 | 时间线的帧率；片段时长也换算到这个帧率 |
| 帧宽 | 1920 | MLT 配置的画面尺寸 |
| 帧高 | 1080 | 同上 |

这些设置属于**组织的记录**，会参与复制：说好按 25 帧剪，就是整个集群都按 25 帧。程序路径则
相反，各服务器各有各的。

## 路径与安全

* **`.mlt` 里的所有路径一律是相对路径**（`resource` 属性）。绝对路径会毁掉可移植性：集群里
  邻居机器上同一段素材放在别处，时间线打开就是空的。
* 片段路径从**输出文件所在目录**算起。
* 组织存储中的资源（`store:`）位于项目文件夹之外，因此导出时会被**复制**到时间线旁边的
  `ai2p_media/` 子目录：否则引用要么是绝对路径，要么带 `..`。
* 智能体只写**自己的文件** `ai2p_library.mlt`。人的项目文件从不触碰：人可能正把它开在编辑器
  里，从编辑器保存会覆盖掉我们写的内容（反之亦然）。生成好的时间线由人自己导入。
* 可以写**项目文件夹**；如果任务的安全规则开放了外部目录，那些目录里也可以写。文件本身的路径
  和文件里的每一个路径都会被检查。

## 与「视频转换器（ffmpeg）」插件的配合

尺寸不同、帧率不同的素材，MLT 也能凑到一起，但要边播边换算 —— 也就是慢，而且未必准确。事先把
素材统一更划算：

1. `ffmpeg_uniform` —— 统一画面尺寸和帧率；
2. `ffmpeg_extract_audio` —— 如果需要单独的音轨，把声音抽成 WAV；
3. `media_add` —— 把得到的文件放进媒体库；
4. `shotcut_timeline_write` 和 `shotcut_render`。

转码是**明确的一步**，而不是导出内部悄悄施的魔法：智能体看得见自己在做什么，您也看得见结果
是什么。
