# OpenShot — 网关 `editor.openshot`（备选）

根据项目媒体库生成 **OpenShot 工程** `.osp`。`.osp` 格式是纯 **UTF-8 JSON**（自 OpenShot 2.0
起），因此文件可以直接写出：既不需要执行代码，也不需要人工导入外来格式——人工双击即可打开
现成的文件。

## 为什么这个网关是备选

按**形式标准**，OpenShot 是本分支四个候选里最好的：跨平台、免费、工程格式开放、可由程序写出，
而且文件一次就能完整打开。

按**可靠性**它更差，这一点还是直说为好：

* **它完全没有无窗口渲染。** `openshot-qt` 只能用自己的窗口计算成片；Shotcut/Kdenlive 有
  `melt`，成片可以无人渲染。因此本插件的清单里没有 `render` 块，也没有第二个动作：承诺一个
  并不存在的渲染，比干脆没有渲染更糟。
* **OpenShot 的稳定性口碑一般**——长工程崩溃的问题多年来一直存在。

**剪辑的首选是 `editor.shotcut`（Shotcut / Kdenlive）。** 只有当对方本来就用 OpenShot 工作，
或者那台机器上没装 Shotcut 时，才选 OpenShot。

## 需要安装什么

| 什么 | 怎么做 |
|---|---|
| OpenShot 2.0 及以上 | 自行安装并指定路径：设置 → 插件与 MCP → 插件 `editor.openshot` → 路径字段 |

**这里故意没有「安装」按钮。** Windows 上 OpenShot 只提供安装程序
`OpenShot-v4.0.0-x86_64.exe`（229 078 328 字节，2026-08-30 发布，
https://github.com/OpenShot/openshot-qt/releases），官方完全没有便携压缩包，而我们的软件包安装
器只解压压缩包、不运行第三方安装程序。因此清单里的软件包代码为空，插件显示的是「指定它已经装在
哪里」这个字段。

既可以指定程序文件，也可以指定你安装它的目录。OpenShot 不在命令行给出版本号，因此只检查
**可执行文件是否存在**：`openshot-qt.exe`（Windows）、`openshot-qt` 或 AppImage（Linux）、
`.dmg` 里的应用（macOS）。

程序路径是**这台计算机**的值：它保存在服务器的 `config.json` 里
（`plugins.editor.openshot.path`），不在集群内复制。插件的描述则相反，会被复制。

**重要且不显然：** 只要路径没有指定，本服务器上插件的状态就是「正在查找软件」，动作**不会**
发布给智能体——尽管生成 `.osp` 即使没装 OpenShot 也能工作（文件是我们自己写的）。这是插件内核的
通用规则，而不是本网关的特殊之处；`editor.resolve` 的行为完全一样。

## 智能体的动作

| 工具 | 做什么 |
|---|---|
| `openshot_timeline_write` | 根据项目媒体库生成 `ai2p_library.osp`：一条视频轨（图层 `L2`，编号 2000000）和一条音频轨（图层 `L1`，编号 1000000），顺序与 `media_list` 相同。可按 `scene`、`kind`、`tag` 筛选。文件名由 `file` 指定 |

工作顺序：素材先进媒体库（`media_add`），然后 `openshot_timeline_write`，接着由**人工**在
OpenShot 里打开文件；如果需要成片，再由人工自己启动导出。

人工创建的工程文件绝不改动：只写我们自己的 `ai2p_library.osp`。

## 生成的文件是怎么组织的

`.osp` 与 MLT 和 OTIO 的区别在于它的片段列表是**扁平的**：

* `files` — 素材列表：路径、媒体类型、读取器类型（视频和音频用 `FFmpegReader`，图片用
  `QtImageReader`）、时长，以及 `has_video` / `has_audio` / `has_single_image` 标志；
* `clips` — **整个文件只有一个数组**，每个片段自己用 `layer`（来自 `layers` 的图层编号）和
  `position`（距开头的秒数）说明所在轨道与位置。这里没有 MLT 那样的「轨道即序列」，因此每个
  片段的起点由我们计算；
* `layers` — 五个图层，其中两个有标签（`A1` 和 `V1`）；
* `profile` — OpenShot 的配置名，字符串形式（1920×1080、25 fps 对应
  `FHD PAL 1080p 25 fps`）；画幅与帧率来自插件记录的设置。

素材的场景、镜次和说明写进文件条目的 `metadata`（`ai2p_scene`、`ai2p_take`、
`ai2p_caption`）——OpenShot 不显示它们，但人工阅读文件时可以据此看出片段的来历。

## 路径与安全

**路径只能是相对的**——而且这正是该格式的原生做法：OpenShot 自己就用相对路径保存工程，并在打开
时从 `.osp` 所在目录展开。绝对路径会破坏集群内的可移植性：在另一台机器上同一个片段位置不同，
工程打开后所有片段都会显示「文件未找到」。JSON 里的键名就是 `path`，而且它出现**两次**：在
`files` 条目里，以及在片段的 `reader` 里。

片段路径是**相对于输出文件所在目录**计算的，而不是项目目录。组织存储（`store:`）里的素材位于项目
目录之外，因此会被复制到 `.osp` 旁边的 `ai2p_media` 子目录；任何其他只能用 `..` 才能寻址的素材
也照此处理。

目录限制是**字面生效的**：我们写的是 JSON，不执行任何代码，因此文件自身的路径和文件内部的路径都
会被检查。可以写入项目目录，以及任务安全规则开放的目录——别处都不行；指向外部的路径会得到明确的
拒绝，并且不会产生任何文件。

## 操作系统方面的限制

生成 `.osp` 就是写一个文本文件，这在**所有系统上都一样**。不同的只是在各系统上如何获得 OpenShot
本身。

* **Windows。** 只有安装程序 `OpenShot-v4.0.0-x86_64.exe`（229 078 328 字节）；另有 32 位的
  `OpenShot-v4.0.0-x86.exe`（224 873 009 字节）。没有便携压缩包，我们的软件包无法安装它。安装
  后的可执行文件是 `openshot-qt.exe`。**未做实机验证：本机没有安装 OpenShot。**
* **Linux。** `OpenShot-v4.0.0-x86_64.AppImage`（254 457 024 字节），或发行版软件包
  （`apt install openshot-qt`）。AppImage 像普通文件一样运行——指向它即可。OpenShot 始终需要
  自己的窗口：程序没有无界面模式，这正是它没有无窗口渲染的原因。**未做实机验证。**
* **macOS。** `OpenShot-v4.0.0-x86_64.dmg`（292 188 716 字节）。路径需手工指定。
  **未做实机验证。**
* **共同。** 以上数字是 2026-09-03 通过查询 GitHub 发布列表取得的（v4.0.0 发布于
  2026-08-30，`libopenshot` 1.0.0）。生成文件里的 `version` 块不是装饰：打开时 OpenShot 会据此
  运行针对旧工程的升级步骤。

## 这个网关不做什么

* **不渲染。** 成片要由人工打开工程后从 `.osp` 计算。需要无人成片就用 `editor.shotcut`（有
  `melt`）或转换器 `tool.ffmpeg`。
* **不改动人工的工程**——只写自己的 `ai2p_library.osp`。
* **不携带转场、特效和调色**——只有素材在两条轨道上的排布及其时长。
* **不转码素材。** 若各段格式不同，请先用转换器 `tool.ffmpeg`。
* **不使用 `libopenshot`。** 编辑器旁边还有 `libopenshot` 库，带 Python、C++ 和 Ruby 绑定——用它
  既能搭建工程，也能无窗口渲染。本次工作不包含它：那是一个有自己安装流程的独立外部依赖，而
  `.osp` 格式我们不用它也能直接写出。
