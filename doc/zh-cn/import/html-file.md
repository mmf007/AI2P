# 导入 HTML 页面（“公开 HTML”）— 说明

**“公开 HTML”** 条目已经在导入目录中，位于第一行。它没有设置，也没有密钥：无需创建、
无需输入密钥，也无需检查连接。

## 如何导入

项目任务列表 → **“按 URL 导入任务”** → 粘贴页面地址 → **“导入”**。
地址决定导入方式：

| 地址 | 导入内容 |
| --- | --- |
| `file:///C:/文件夹/页面.htm` 或完整路径 `C:\文件夹\页面.htm` | 保存在磁盘上的页面。旁边 `…_files` 文件夹中的图片（浏览器“另存为… → 完整网页”时生成）会复制到任务中。引用本地文件的框架会被展开。 |
| `https://…` 或 `http://…` | 公开网页——**只导入该页面本身**，不跟随链接。图片会下载并复制到任务中；所有链接保持可点击并指向来源网站。 |

任务以草稿创建：标题取自 `<title>`（否则取第一个 `<h1>`），描述是转换为 Markdown 的页面文本。
即使之后删除了源页面，任务内容也保持完整。

Trello、GitHub、GitLab 和 Figma 的地址仍由各自的导入器处理——“公开 HTML”只接收其他导入器都不识别的地址。

## 限制

* 由脚本绘制的页面（单页应用）导入后几乎为空：导入按原样读取 HTML，不执行脚本。
  请在浏览器中保存该页面（“另存为… → 完整网页”）后导入文件。
* 需要登录的页面无法读取：导入不知道浏览器的 cookie。
* 限制：每页 64 MB，每张图片 50 MB，最多 300 张图片。
* 样式、表单、视频和音频不会转移。
* 网页无法获取本机文件：其中的 `file:` 图片会被跳过。
* 对于代理，只有任务安全规则开放的文件夹中的磁盘文件才可读取。

## 更新

任务卡片中的“更新”按钮会按导入链接重新读取页面。
