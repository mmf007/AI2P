# 从 GitHub 导入任务 — 接入说明

导入把 **GitHub 的任务（issues）**搬进 AI2P 的任务（技术规格 2.10 节，第 11 章）。接入需要
GitHub 给出的一个字符串 — **个人访问令牌** — 以及导入源名录中的一条记录。按步骤来：

## 1. 获取令牌

GitHub 在账户设置中发放令牌。令牌有两种，两种都可以用。

**细粒度令牌（fine-grained，推荐 — 可以恰好给出所需的那点权限）：**

1. 登录 GitHub 并打开
   <https://github.com/settings/personal-access-tokens/new>。
2. **Token name** — 任意，例如 `AI2P import`；**Expiration** — 有效期。
3. **Repository access** — 选「All repositories」，或者选「Only select repositories」
   并列出您要从中导入的那些仓库。
4. **Permissions → Repository permissions → Issues** — 设为 **Read-only**。
   （**Metadata** 字段 GitHub 会自己开放读取权限 — 它是必需的。）
5. **Generate token** 并复制显示出来的字符串。它以 `github_pat_` 开头，
   而且**只显示一次**。

**经典令牌（classic）：**

1. 打开 <https://github.com/settings/tokens> → **Generate new token (classic)**。
2. 勾选 **`repo`** 范围（它给出访问私有仓库任务的权限）；
   对于公开仓库，**`public_repo`** 就够了。
3. **Generate token** 并复制字符串 — 它以 `ghp_` 开头。

令牌可以访问您的仓库 — 请像保管密码一样保管它。**对公开仓库同样需要令牌**：
没有它 GitHub 每个地址每小时只允许 60 次请求，导入会撞上这个上限。

## 2. 在导入源名录中创建源

**设置 → 「名录」标签页 → 「导入源名录」 → 「添加」：**

| 字段 | 填什么 |
| --- | --- |
| 源名称 | 任意，例如 `GitHub 工作源` |
| 类型 | GitHub |
| 仓库所有者 | 用户名**或组织名** — 也就是地址 `github.com/<所有者>` 中的那一段 |
| 筛选 | 仓库名称的子串，例如 `planner`；留空 — 该所有者的全部仓库 |
| 已启用 | 暂时不可用 — 完成第 3 步后会自行开启 |

点击 **「保存」**。输入令牌的按钮只在**已保存的**记录上出现：
值会立刻放进密钥库，所以在保存之前无法知道它属于谁。

## 3. 输入令牌

用 **「修改」** 按钮打开已保存的源，点击 **「设置令牌」** —
粘贴第 1 步得到的字符串并保存。

GitHub 没有 API 密钥：密钥只有一个，所以表单里只有一个按钮（Trello 有两个）。
旧值永远不会显示 — 要替换令牌，就输入一个新的。表单下方可以看到状态：
「令牌：已设置，来源 — 组织」。

表单会核对值的**形态**，如果它不像 GitHub 的令牌就会提出警告：
现在的令牌以 `github_pat_` 或 `ghp_` 开头，以前的是 40 个 `0–9 a–f` 字符。

**「检查连接」按钮**会向 GitHub 询问「我是谁」，并立刻用文字回答：
令牌是否被接受、它发放给了哪个账户、这个账户与源中指定的所有者是否一致。
在这里检查连接，比在第一次导入时才碰到拒绝要划算。

**令牌存放在哪里。** 在您组织的数据库中，用组织的密钥**加密**保存
（和模型的 API 密钥一样）：它会自己复制到组织的所有服务器上，
而只有拿到组织密钥的服务器才能解密它。不需要往 `secrets.json` 里写任何东西；
如果值还是用文件放好了，它同样会被读到 — 读取顺序是
「组织 → `secrets.json` → 环境变量」。

**在令牌没输入之前，源不能处于启用状态** — 「已启用」开关被锁住。
只要令牌输入了，源就**自行启用**；之后启用与否由您来切换。

**两个 GitHub 账户。** 每个源都有**自己的**令牌引用 — 创建第二个源
并在其中输入另一个值即可。

## 4. 启动导入

1. 选择**项目** — 导入总是进入当前项目。
2. 在任务列表中点击**带箭头的云**图标按钮（「导入任务」） —
   它只在选定了项目时才可见。
3. 在对话框中选择源和复选框：
   * **添加新的**（默认开启） — 还不存在的任务会变成 AI2P 的任务；
   * **更新已有的** — 先前导入的任务会更新标题、
     描述和期限（这些字段的本地修改会被覆盖）。
4. 点击 **「导入」**。结果会以消息显示：「新增 X，更新 Y，
   跳过 Z，讨论消息 N」；「作业历史」中会出现一条 `import.run` 记录。

## 究竟会导入什么

* 取该所有者各仓库中的**开放任务**；仓库按名称子串筛选
  （筛选留空 — 全部）。
* **合并请求（pull requests）不会被导入。** 在 GitHub 的 API 中它们看起来像
  任务，但不算任务，会被跳过。
* GitHub 任务 → 状态为**「草稿」**的 AI2P 任务：标题、**任务全文放进描述** +
  底部的来源附注（「从 GitHub 导入：仓库 …，任务 #N」，带链接）。
  执行者和优先级由您在 AI2P 里填。
* **任务的讨论会转入 AI2P 的任务聊天**：每条评论变成一条
  消息，作者名就用他在 GitHub 中的名字 — `github:<登录名>`，消息时间
  为评论的时间，因此时间顺序得以保留。再次导入只会
  添加**新**消息：已经搬过来的按外部 id 认出。
* GitHub 的任务没有**期限**。如果任务被归入带日期的**里程碑（milestone）**，
  这个日期就成为 AI2P 任务的期限。
* **不会产生重复**：任务的内部 id 记在 AI2P 的任务里（`github:<id>`）；
  再次导入同一个任务时会跳过或更新它 — 取决于复选框。
* **附加在 GitHub 任务上的文件不会被下载。** GitHub 没有单独的附件
  列表 — 图片和文件以链接的形式活在正文之中，它们也就保持为链接。
  对公开仓库来说这样的链接能打开，图片也看得见；
  指向**私有**仓库文件的链接，不登录 GitHub 就打不开。
* GitHub 任务的标签、指派人和状态**不会被搬运**：它们在 AI2P 里维护。

## 5. 按链接导入单个任务

在任务列表中，批量导入按钮旁边有一个 **「按 URL 导入任务」** 按钮：

1. 粘贴形如 `https://github.com/<所有者>/<仓库>/issues/<编号>` 的链接
   （带尾巴的地址也行 — `#issuecomment-…` 和 `?…` 会被丢掉）。只有当合适的
   已启用 GitHub 源有多个时才会再问用哪一个：
   **源的类型由链接本身决定**，因此粘贴进来的 GitHub 地址不会落到
   Trello 的导入程序手里。
2. 任务的内容会填入**新任务表单**：标题、描述、期限。
3. 补全表单（执行者、优先级）后保存 — 讨论会在保存之后立刻进入任务聊天。
   再次导入同一个任务不会产生重复。

AI 智能体也能用 `import_task_from_url` 工具执行同样的动作（动作代号
`AI2P.Tasks.ImportFromUrl` — deny/confirm 安全规则照常适用）。
由哪个程序来处理这个链接，是由链接的形态决定的，所以智能体对所有源
只需要一个工具。

## 6. 从 GitHub 更新任务

通过导入进来的任务填有**「导入链接」**字段（可以在卡片顶部
和任务表单的「扩展」一节中看到）。按这个链接可以**从源重新读取**任务：

1. 打开任务卡片并点击 **「刷新」**。
2. 会出现一个有三种结果的追问：
   * **「从导入源」** — 重新读取 GitHub 任务，把新的标题、期限和
     **完整描述**放进 AI2P 的任务，讨论中的新消息也会进入聊天；
   * **「仅本地」** — 就是从数据库中普通地重新读取任务，不去访问 GitHub；
   * **「取消」**。

更新**不会**动的东西：验收标准、执行者、状态、优先级、标签、
子任务和各种关联 — 它们在 AI2P 里维护，而不是在 GitHub。**描述会被整体重写**：
从源更新的目的正是让任务里变成 GitHub 现在的样子。
已经搬过来的讨论消息不会重复。

导入链接可以**手工填写** — 这样在 AI2P 里不经导入建立的任务也能更新；
也可以**清空这个字段**，把任务与源解绑（「刷新」按钮就变成普通的重新读取）。

## 如果有什么不工作

| 消息 | 原因和处理办法 |
| --- | --- |
| 「按引用 … 未找到 GitHub 令牌」 | 令牌没有输入：打开源并点击「设置令牌」（第 3 步）。密钥文件的路径直接写在消息里。 |
| 「本服务器尚未收到组织密钥…」 | 服务器接入了别人的组织，但申请尚未被其指挥服务器确认 — 没有组织密钥就无法加密这个值。请确认接入（设置 → 服务器）。 |
| 「GitHub 未接受**令牌**…」（响应 `Bad credentials`） | 令牌不正确、已被吊销，或者有效期已过。消息会显示所输入值的长度和前缀 — 由此可以看出字段里是不是放错了东西。请重做第 1 步。 |
| 「GitHub 拒绝访问…」（403） | 令牌被接受了，但它对该仓库没有权限：细粒度令牌需要 **Issues: Read** 权限，并且该仓库要在「Repository access」列表里；经典令牌需要 **repo** 范围。 |
| 「GitHub 暂时拒绝服务：请求次数上限已用尽」 | 触发了 API 的 rate limit。请等几分钟；并检查导入是不是**带着令牌**进行的 — 没有令牌上限要低 80 倍。 |
| 「GitHub 未找到所请求的内容（404…）」 | 所有者、仓库名称或任务编号不对。令牌无权访问的私有仓库，GitHub 会显示为不存在 — 那也是同一个 404。 |
| 「该链接不像是 GitHub 任务…」 | 地址形态不对：需要 `https://github.com/<所有者>/<仓库>/issues/<编号>`。指向 **pull request** 的链接（`/pull/<编号>`）不行 — 只导入任务。 |
| 导入完成了，但「新增 0」 | 筛选没有命中任何仓库，或者仓库里没有开放的任务，又或者所有开放的记录都是合并请求。请试试留空筛选。 |
| 私有账户的仓库没有全部导入 | 令牌是发给**另一个**账户的：别人的私有仓库它看不见。请用「检查连接」按钮核对 — 它会说出令牌所属的账户，并在与所有者不一致时提出警告。 |

消息会完整地出现在导入窗口本身。请求的细节在应用日志中
（`logs/*.jsonl`，`GitHubImporter` 记录）：令牌是按哪个引用、从哪个存储取的，
它有多长、前缀是什么（值本身永远不会写进日志），GitHub 返回了什么。

## 限制

* 一次导入每类最多取 **10 页、每页 100 条**记录 — 仓库、
  仓库的任务、任务的评论。这够用于 1000 个仓库、每个仓库 1000 个开放
  任务、每个任务 1000 条评论；撞上上限时日志里看得出来。
* 支持 **github.com**。目前不支持带自有服务器地址的 GitHub Enterprise。
