# 导入任务：源名录是怎样组织的

这是存放各种源**类型**文档的目录：每个**类型**一个文件，文件名就是**类型代号**
（`trello.md`、`github.md`、`gitlab.md`）。用源表单中「类型」字段旁的 **「i」** 按钮打开：
**设置 → 名录 → 导入源**。

文档绑定的是**类型**，而不是名录中的某条记录：如何获取外部系统的密钥，对该类型的所有源都
一样，而且这件事在记录保存之前就需要知道。

## 本节目录

* [github](github.md) — 从 GitHub 导入任务 — 接入说明
* [gitlab](gitlab.md) — 从 GitLab 导入任务 — 接入说明
* [trello](trello.md) — 从 Trello 导入任务 — 接入说明

## 所有类型的共同之处

**密钥可能是一个，也可能是两个。** Trello 有两个 — **API key** 和 **Token**，所以源表单中
既有「设置 API 密钥」按钮，也有令牌按钮。GitHub 和 GitLab 只有**一个**密钥 — 个人访问令牌；
它们完全没有 API 密钥按钮，只凭一个令牌就能启用源。形如 `trello.*` 的密钥引用只属于 Trello。

**密钥属于组织**：它用组织的密钥加密，并复制到组织的各服务器上 — 不需要在每台计算机上重复
输入。

**导入有两种：**批量导入（按名录记录 — 看板、仓库、项目）和按卡片或任务链接的单条导入。
单条导入**按链接本身**选择处理程序，因此 GitHub 任务地址和 GitLab 的旧式地址（不带 `/-/`
分隔符）靠服务器名区分：只有当主机名中含有 `gitlab` 字样时，GitLab 才接受旧式地址。

**从源更新**同样按已导入任务的链接进行 — 用它卡片中的按钮。导入的任务记得自己是从哪里来的。

## 如何添加新类型的文档

请把文件 `<类型代号>.md` 放到这里 — 代号要与该类型在名录中的名字完全一致（`trello`、
`github`、`gitlab`）：文件名由应用拼装，不能自行编造。请在 `../../en/import/` 中也建立同名
文件，并把两者都写入各节目录（用脚本 `test/t18s1/mktoc.py`）。

这些文档中的外部地址要写**完整**，带上 `https://` 协议 — 它们是用应用页面内的「i」按钮打开
的，相对链接在那里是失效的。

## 这些文档中没有什么

获取密钥的步骤是按撰写文档当天的情况描述的。外部系统会悄无声息地改动自己的设置界面：如果
按钮名称与正文对不上，请去找个人令牌（Personal access tokens）那一节 — 操作步骤本身比标签
文字更稳定。
