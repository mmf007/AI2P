# 从 Trello 导入任务 — 接入说明

导入把 Trello 的卡片搬进 AI2P 的任务（技术规格 2.10 节，第 11 章）。接入需要
Trello 给出的两个字符串 — **API key** 和 **Token** — 以及导入源名录中的一条记录。
按步骤来：

## 1. 获取 API key

Trello 通过集成页面（Power-Ups）发放密钥：

1. 在浏览器中登录 Trello，打开 <https://trello.com/power-ups/admin>。
2. 点击 **「New」**（创建新集成）。填写必填字段：
   * **Name** — 任意，例如 `AI2P import`；
   * **Workspace** — 您的工作区；
   * **Email / Author** — 填您自己的。
   「Iframe connector URL」字段可以留空。
3. 打开创建好的集成 → **「API key」** 标签页 → 按钮
   **「Generate a new API key」**。
4. 复制 **API key** 字段的值（一串字母和数字）。

## 2. 获取 Token

在同一页面上、API key 字段的右侧，有一个 **「Token」** 链接
（在文字「you can manually generate a Token」中）：

1. 点击它 — 会打开 Trello 的授权页面。
2. 点击页面底部的 **「Allow」**（允许）。
3. 复制显示出来的**令牌**（一个长字符串）。

令牌可以访问您账户的看板 — 请像保管密码一样保管它。

## 3. 在导入源名录中创建源

**设置 → 「名录」标签页 → 「导入源名录」 → 「添加」：**

| 字段 | 填什么 |
| --- | --- |
| 源名称 | 任意，例如 `Trello 主源` |
| 类型 | Trello |
| Trello 登录名 | 您的 **username** — 在 Trello 个人资料中显示为 `@名字`（填写时不带 `@`） |
| 筛选 | 看板名称的子串，例如 `AI2P`；留空 — 全部看板 |
| 已启用 | 暂时不可用 — 完成第 4 步后会自行开启 |

点击 **「保存」**。输入密钥和令牌的按钮只在**已保存的**记录上出现：
值会立刻放进密钥库，所以在保存之前无法知道它属于谁。

## 4. 输入 API 密钥和令牌（v1.65）

用 **「修改」** 按钮打开已保存的源 — 表单中出现了两个按钮：

1. **「设置 API 密钥」** — 粘贴第 1 步得到的字符串，「保存」。
2. **「设置令牌」** — 粘贴第 2 步得到的字符串，「保存」。

每个按钮只询问**一个字段**。旧值永远不会显示 — 要替换密钥，就输入一个新的。
表单下方可以看到状态：「API 密钥：已设置，来源 — 组织」，令牌也一样。

**密钥和令牌很容易弄反**，而 Trello 对此的回应是含糊的「invalid key」。
所以表单会核对它们的形态并提出警告：**API 密钥正好是 32 个** `0–9 a–f` 字符，
**令牌是 64 个**同样的字符，或者是以 `ATTA` 开头的字符串。这两者都
**不是「Secret」**：同一页面上集成的 secret 不是令牌，AI2P 也不需要它。

**「检查连接」按钮**（在输入按钮旁边，两个值都填好后才能用）会向 Trello 询问「我是谁」，
并立刻用文字回答：密钥是否被接受、令牌是否被接受、令牌发放给了哪个账户、
它和源中的登录名是否一致。在这里检查连接，比在第一次导入时才碰到拒绝要划算。

**这些值存放在哪里。** 在您组织的数据库中，用组织的密钥**加密**保存（和模型的 API 密钥一样）：
它们会自己复制到组织的所有服务器上，而只有拿到组织密钥的服务器才能解密它们。
不需要再往 `secrets.json` 里写任何东西了。

**在两个值都没输入之前，源不能处于启用状态** — 「已启用」开关被锁住。
只要两者中的最后一个被输入，源就**自行启用**；之后启用与否由您来切换。

**那些已经把密钥写进 `secrets.json` 的安装**照常工作：值按
「组织 → `secrets.json` → 环境变量」的顺序读取，而在新版本首次启动时会从文件迁入组织 —
表单会立刻显示「已设置」。环境变量 `TRELLO_API_KEY` / `TRELLO_TOKEN` 同样照旧有效，
也不会被迁走：它们是有意从外部设定的。

**两个 Trello 账户。** 从 v1.65 起创建的每个源都有**自己的**密钥/令牌对 —
创建第二个源并在其中输入另一组值即可。v1.65 之前就已存在的源共用一对
（记录参数中的 `trello.apiKey` / `trello.token` 引用）：要把它们分开，请重新创建源。

## 5. 启动导入

1. 选择**项目**（在顶栏或项目标签页中） — 导入总是进入当前项目。
2. 在任务列表中点击**带箭头的云**图标按钮（「导入任务」） —
   它只在选定了项目时才可见。
3. 在对话框中选择源和复选框：
   * **添加新的**（默认开启） — 还不存在的卡片会变成任务；
   * **更新已有的** — 先前导入的任务会从 Trello 更新标题、
     描述和期限（这些字段的本地修改会被覆盖）。
4. 点击 **「导入」**。结果会以消息显示：「新增 X，更新 Y，
   跳过 Z」；「作业历史」中会出现一条 `import.run` 记录。

## 究竟会导入什么

* 取指定登录名下**公开看板中的开放卡片**；看板按名称子串筛选
  （筛选留空 — 全部）。
* 卡片 → 状态为**「草稿」**的任务：标题、期限（due）、卡片的描述 +
  底部的来源附注（「从 Trello 导入：看板 …，卡片」，带链接）。
  执行者和优先级由您在 AI2P 里填。
* **不会产生重复**：卡片的外部 id 记在任务里（`trello:<id>`）；
  再次导入同一张卡片时会跳过或更新它 — 取决于复选框。

## 如果有什么不工作

| 消息 | 原因和处理办法 |
| --- | --- |
| 「未找到 Trello 密钥（…）」 | API 密钥或令牌没有输入：打开源并点击「设置 API 密钥」/「设置令牌」（第 4 步）。旧安装 — 请检查 `secrets.json`：文件路径直接写在消息里。 |
| 「本服务器尚未收到组织密钥…」 | 服务器接入了别人的组织，但申请尚未被其指挥服务器确认 — 没有组织密钥就无法加密这些值。请确认接入（设置 → 服务器）。 |
| 「Trello 未接受 **API 密钥**…」（Trello 回应「invalid key」） | 密钥不对：最常见的是密钥字段里放的是**令牌** — 消息会直接指出这一点并显示所输入值的长度。请重做第 1 步并重新输入密钥。 |
| 「Trello 未接受**令牌**…」（「invalid token」） | 令牌不正确、已被吊销，或者它的字段里放进了密钥/「Secret」 — 请重做第 2 步。 |
| 「Trello 拒绝访问…」 | 密钥和令牌都被接受了，但令牌所属账户对该看板或卡片没有权限。 |
| 「Trello 未找到所请求的内容（HTTP 404…）」 | 登录名（username）不存在，或者卡片对令牌账户不可见 — 请与 Trello 个人资料核对。 |
| 导入完成了，但「新增 0」 | 筛选没有命中任何看板，或者该成员没有开放的卡片；请试试留空筛选。 |

消息会完整地出现在导入窗口本身 — 不必从悬浮提示里去捞。请求的细节在应用日志中
（`logs/*.jsonl`，`TrelloImporter` 记录）：密钥和令牌是按哪个引用、从哪个存储取的，
它们有多长（值本身永远不会写进日志），Trello 返回了什么。


## 按链接导入单张卡片（v1.50）

在任务列表中，批量导入按钮旁边有一个 **「按 URL 导入任务」** 按钮：

1. 粘贴形如 `https://trello.com/c/<代号>` 的卡片链接（Trello 卡片上的「分享」按钮）。
   只有当已启用的 trello 源有多个时才会再问用哪一个 — 密钥就从它那里取。
2. 卡片的内容会填入**新任务表单**：标题、描述、期限。
   **卡片的附件文件会被下载**到项目存储中，并以链接插入描述（图片显示预览）；
   链接型附件仍然是链接。大于 200 MB 的文件不下载 — 保留为带标注的链接。
3. 补全表单（执行者、优先级）后保存。再次导入同一张卡片不会产生重复。

AI 智能体也能用 `import_task_from_url` 工具执行同样的动作（动作代号
`AI2P.Tasks.ImportFromUrl` — deny/confirm 安全规则照常适用）。
