# AI2P 的安装以及它的数据放在哪里

本章回答两个问题：**程序装到哪里**，以及**装好之后它的工作文件放在哪里** —
配置、任务数据库、日志和密钥。第二个问题比看上去更重要：工作文件要挺过版本升级，
迁移到另一台计算机时要复制它们，而且正是它们不能丢失。

---

## 1. 三种安装方式

| 方式 | 这是什么 | 何时方便 |
|---|---|---|
| **安装包** | 单个文件 `AI2P_v_1_NN_…`（或 `AI2P_full_v_1_NN_…` — 内含运行时），双击安装 | Windows 上的常规情况 |
| **安装脚本** | 部署包目录中的 `install.cmd` / `install.sh` | 部署包已经下载好、并且要手工选择目录时 |
| **直接用部署包** | 解压出来的目录，运行 `AI2P.Server.exe` | 试用、放在 U 盘上的便携安装 |

Windows 上的安装包会询问是**为所有用户**安装还是**仅为我**安装。程序目录取决于此：

* **为所有用户** — `C:\Program Files\AI2P`（需要管理员权限）；
* **仅为我** — `C:\Users\<您>\AppData\Local\Programs\AI2P`。

Linux 和 macOS 上安装到主目录：默认为 `~/ai/AI2P`。

---

## 2. 工作文件放在哪里

规则只有一条：**只要程序目录可写，工作文件就放在程序旁边。**

程序旁边指的是 `config.json`、数据目录 `data/`（服务器数据库、各组织的数据库、
项目文件）、日志 `logs/` 和密钥 `secrets/`。

普通用户**不能**往 Windows 的程序目录（`C:\Program Files`）里写，这不是故障，
而是系统的规矩：否则这台计算机上的任何用户都能替换掉随后由管理员运行的
`AI2P.Server.exe`。因此「为所有用户」的安装把工作文件放在别处：

| 安装方式 | 程序 | 工作文件 |
|---|---|---|
| Windows，「为所有用户」 | `C:\Program Files\AI2P` | **`C:\ProgramData\AI2P`** |
| Windows，「仅为我」 | `…\AppData\Local\Programs\AI2P` | 在程序旁边 |
| 部署包放进自己的文件夹（`D:\AI2P`） | `D:\AI2P` | 在程序旁边 |
| Linux/macOS，`~/ai/AI2P` | `~/ai/AI2P` | 在程序旁边 |
| Linux/macOS，`/opt/ai2p` | `/opt/ai2p` | `/var/lib/ai2p`，若无权限则为 `~/.local/share/ai2p` |

`C:\ProgramData\AI2P` 是**本台计算机**的公共目录：安装只有一份，数据是共用的，
服务（它以系统身份运行）看到的数据和人看到的是同一份。安装程序会建立这个目录
并对本机所有用户开放写入；卸载程序时它会**保留下来** — 这是您的数据。

### 怎样确切地知道

启动时程序自己就会说出它的工作文件在哪里：

```
AI2P：程序目录 C:\Program Files\AI2P\ 不可写 —
工作文件（config.json、data、logs、secrets）放在 C:\ProgramData\AI2P
```

同一行也会进入技术日志（`logs/ai2p-<日期>.jsonl`），而配置和数据目录的完整路径
在启动后立刻就能在日志中看到。

### 怎样自己指定目录

| 方式 | 作用 |
|---|---|
| `AI2P.Server.exe --config D:\myAI2P\config.json` | 就用这个 `config.json`；`data/`、`logs/` 和 `secrets/` 会放在它旁边 |
| 环境变量 `AI2P_HOME=D:\myAI2P` | 效果相同，但只需为服务、容器或快捷方式设置一次 |

这样指定的目录强于任何规则：程序不会去干预它。

## 3. 版本升级

覆盖旧版本安装**不会动**工作文件：`config.json`、`data/`、`secrets/` 保持原样。
程序旁边会放上 `config.new.json` — 新版本的配置，首次启动时程序会把两者合并：
以新的为底（其中含有全部新参数及其默认值），再把您的取值盖上去。合并这件事它会在
控制台里说一行，而工作用的 `config.json` 旁边会留下已应用文件的副本
（`config.new.json.applied`） — 由它可以看出什么时候来了什么。

合并**每个版本只做一次**：再次启动不会重写任何东西。

### 留在程序旁边的数据

如果您以前把 AI2P 装在 `C:\Program Files\AI2P` 并且**以管理员身份**运行它，
数据可能就直接建在那里了。那么升级之后程序会说：

```
AI2P：程序旁边还留有以前工作时的数据目录 C:\Program Files\AI2P\data —
现在数据放在 C:\ProgramData\AI2P；如有需要请手动把它迁过去
```

它自己**不会搬运**这些数据：不能背着人把数据库挪走。而设置（旧安装的 `config.json`）
这时会被带上 — 端口、主机名和各个目录是您设定的，没有理由丢掉它们。要把数据也搬过去：
停止 AI2P，把 `data` 目录（如果那里有 `secrets`，也一并）复制到新的工作文件目录，
然后重新启动。

### 在 Linux/macOS 上更新时出现 `AI2P_HOME: parameter not set`

**1.100 和 1.101** 版本会在这一行上中断更新：

```
./install.sh: 147: AI2P_HOME: parameter not set
```

什么都没有被复制，已安装的版本仍然照旧。责任在安装脚本本身：它读取了 `AI2P_HOME` 变量，
而普通安装并没有这个变量。从 **1.102** 版起不会再出现这种情况。

如果您手上只有 1.100 或 1.101 的发布目录，用它仍然可以完成更新 —
只要把这个变量设成空值即可：

```sh
AI2P_HOME= ./install.sh ~/ai/AI2P
```

同样的办法也适用于这些版本的 `makeAsServise.sh`。

## 4. 操作系统服务

服务和普通启动使用**同一个**工作文件目录 — 它是按程序目录选定的，
而不是按启动者的权限。这就是说，把安装做成服务（`makeAsServise`，见
[service](service.md)）不会得到第二个「给系统用的」数据库。

---

## 5. 如果程序无法启动

用 AI2P 快捷方式启动的是一个普通的控制台程序：启动出错时它会**用文字写明原因并把窗口留住**，
直到您按下按键为止（窗口本身一分钟后会自行关闭）。可能遇到的情况：

| 看到什么 | 这是什么 | 怎么办 |
|---|---|---|
| `AI2P：启动失败 — Access to the path … is denied` | 工作文件被指定到了不能写入的目录 | 指定另一个目录（`AI2P_HOME`、`--config`） |
| `AI2P 的工作文件无处存放` | 程序目录和两个数据目录都不可写 | 同上：明确指定目录 |
| `AI2P 已在运行（…） — 打开浏览器并退出。` | 这不是错误：本机只有一个实例，而它已经在运行了 | 什么都不用做 |
| 窗口立刻无声地关闭 | 版本**早于 1.100**：那时启动出错会把窗口连同消息一起带走 | 更新版本，或者从控制台运行 `AI2P.Server.exe` 并读取输出 |
