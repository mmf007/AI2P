# 计划

**计划就是一份日历，系统按照它自己安排工作。**   
例如：  
* 每周展开一次「周报」模板   
* 每月一次「月度结算」，每季度一次「季度盘点」  
* 每天夜里把旧任务搬进归档。

用左侧栏上带日历的按钮打开（菜单中也有同名的一项）。

---

## 它能启动什么

有两种不同的触发方式，在表单里就能直接看出来：

1. **任务模板的副本。** 触发会像模板卡片上的「创建任务」按钮那样展开模板：带上整棵子任务
   层级、带上执行者挑选和基准日期。
2. **系统动作。** 这时不会创建任务，也不会挑选执行者，因此表单里模板、项目、偏移和挑选规则
   等字段会整块隐藏。目前动作只有一个 — **自动归档**（见[归档](Archives.md)）。

---

## 计划的字段

| 字段 | 用途 |
|---|---|
| **项目** | 默认为当前项目；它限定模板的选择范围，并作为一列显示。可以为空 |
| **模板** | 顶层模板；表单里可以按名称搜索。可见的是所选项目的模板**以及**没有项目的模板 |
| **基准日期偏移** | 小时和分钟；所建任务的基准日期 = 触发时刻 + 偏移 |
| **执行者查找规则** | 「先 AI，后人」、「先人，后 AI」，或者不自动挑选 |
| **一次性 / 周期性** | 一次性的要填启动日期和时间 |
| **周期** | 每周（用小标签选星期几 + 时间，就像手机上的闹钟）、每月（每月第几天 + 时间）、每季度（季度中的月份 1–3 + 日 + 时间，季度从一月算起） |
| **计划时长（分钟）** | 用于冲突检查 |
| **服务器** | 计划在它那里修改，也在它那里触发 |
| **已启用** | 关闭的计划不会触发 |

周期中的时间都是**计算机的本地时间**。在天数不足的月份里，日期会压缩到最后一天：二月的
「31 号」会在 28 号（或 29 号）触发。

### 服务器不是走形式

计划会在集群的各服务器之间复制，而**没有「服务器」字段的话，同一个计划就会在每台服务器上
同时触发**。所以它有一个归属者；没有指定时，计划由组织的指挥服务器来负责。计划列表里有一个
按服务器筛选的过滤器，而且**默认只显示当前服务器** — 否则画面看上去会比实际情况密一倍。

### 冲突检查

如果模板中（它的任何一个节点上）指定了执行者，保存时系统会检查他在同一时间没有被另一个
已启用的计划占用：比较的是未来 62 天内的占用窗口（触发时刻 + 偏移，长度为计划时长）。冲突
会是一个**保存错误**，并指明执行者、计划和时间，而不是悄悄地叠加。

## 两种视图

在工具栏上切换，所选视图在两次启动之间会被记住。

* **表格** — ID、项目、模板（或动作名称）、「时间」（种类和周期的摘要）、偏移、时长、挑选
  规则、「已启用」。点击任意一列即可排序。
* **日历** — 可翻页的月度网格。日期格子里是触发的小标签：先是时间，然后是模板代号或它标题
  的开头（究竟显示哪个，由 设置 → 基本 中的「计划日历格子」选项决定）。小标签的提示是
  「项目 — 模板名称」，点击会打开表单。

## 逾期未触发

这是 AI2P 中计划最主要的特点，值得马上弄明白：**AI2P 是运行在您计算机上的程序，而不是云端的
服务。** 计算机关着的时候，没有什么可以触发。

因此应用启动时，系统会把所有错过的触发收集成一份**逾期未触发**列表 — 它显示在这个选项卡的
**最上方**：计划、模板、错过了多少次、最后一次的时间。每一条都由人自己决定：**「立即启动」**
还是**「从列表中删除」**。

由此带来两个后果，不知道的话会让人摸不着头脑：

* 在应用**运行期间**到点的触发会自动启动（每分钟检查一次）— 不需要做任何决定；
* **只要某个计划还挂着逾期未触发，它的新触发就会等着人来决定**。如果某个计划「不说话了」，
  先看看这个选项卡的最上方。

让 AI2P 一直保持运行是可以的 — 为此可以把它做成[操作系统服务](service.md)；那样通常就完全
不会有逾期未触发了。

---

## 省时间的小细节

* 触发事件会写进日志（`schedule.triggered`）— 在「工作历史」里能看到什么在什么时候被展开了。
* 被复制节点上的阻塞任务照常起作用：启动会等它们完成。
* 项目为空的计划能看到所有没有项目的模板 — 这样便于建立不绑定到单个项目的通用例行流程。
