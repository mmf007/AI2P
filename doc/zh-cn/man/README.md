# AI2P 用户手册 — 本节目录

`man/` 一节是**用户手册**：在 AI2P 中如何做那些人们安装它就是为了做的事。与 `models/` 和
`import/` 两节不同，这里的文档不与名录记录绑定 — 它们是按章节组织的连续正文，文件名可以是
任意的。

手册可以从文档窗口阅读（左侧栏和导航器底部的文档图标），也可以直接从已安装应用旁边的
`doc/` 目录中阅读。

## 里面有什么

本节可以按两种顺序阅读。**新手**按顺序读：快速开始、项目、任务。**按需**则从需要的那一章
开始；每一章都是自足的，并在结尾指出相邻的章节。

### 从哪里开始

**[快速开始](quickstart.md)**

* 从下载发行包到第一个 AI 代理产出结果的最短路径：两个安装包该选哪一个、首次启动向导的六个
  步骤、如何给系统提供模型（订阅、API 密钥或本地权重）、如何下达第一个任务，以及点击「启动」
  之后会发生什么。

### 管理员手册

**[安装 AI2P 及其数据存放位置](install.md)**

* 三种安装方式，回答「为所有用户」会改变什么，工作文件（`config.json`、`data/`、`logs/`、
  `secrets/`）放在哪里、为什么「为所有人」安装时它们会转到 `C:\ProgramData\AI2P`，如何自己
  指定该目录（`AI2P_HOME`、`--config`），版本更新对配置做了什么，以及留在程序旁边的数据该
  怎么处理。

**[以操作系统服务方式运行 AI2P](service.md)**

* 如何把一个安装变成操作系统服务（Windows、Linux 和 macOS 上用 `makeAsServise`；服务名为
  `AI2P`），服务方式与控制台方式有什么不同，如何管理服务，在 Windows 上它应该以谁的身份运行
  （DPAPI 与组织密钥），以及版本更新时会发生什么。

**[配置](config.md)**

* 设置存放的两个地方以及为什么是两个；如何打开设置界面，它的每个选项卡上有什么（基本、模型、
  名录、动作、安全、用户、组织、服务器、通知、通用经验）；只能在 `config.json` 中修改的内容 —
  地址前缀、监听接口、第二地址、HTTPS — 以及关于密钥、平台目录和版本更新的三条规则。

**[HTTPS](https.md)**

* 如何把服务器切换到 https：证书从哪里来（`.pfx` 文件、PEM 对，或计算机的证书存储），如何用
  PowerShell 和 openssl 自己制作证书，程序本身在保存前和启动时会检查什么，如何在浏览器中
  **一次性放行**自己的证书（Windows、macOS、Linux、Firefox、手机），使用自建 CA 证书的集群
  该怎么办，以及服务器起不来时该做什么。

**[执行者](performers.md)**

* 人和 AI 作为同一个概念；账户与执行者有什么不同；配置档和能力声明；启用状态、忙碌状态、
  窗口限额和响应超时；自动挑选和备用执行者是怎样工作的；为什么本地模型会把执行者绑定到某台
  服务器。

**[团队](teams.md)**

* 任务的执行者范围、代理的交流语言、层级和团队负责人、两种参与启用状态、启动团队工作和逐个
  启动成员、模型的本地服务器，以及如何读懂连接错误。

**[计划](schedule.md)**

* 模板副本还是系统动作、计划的各个字段和周期、为什么计划有自己的服务器、冲突检查、两种视图
  （表格和日历），以及最重要的 — 逾期未触发列表。

**[多台服务器](servers.md)**

* 集群有什么用、它不做什么；指挥服务器和服务器代号；记录的归属；如何接入第二台计算机、把它
  移出集群以及更换指挥服务器；数据库复制和文件复制是怎样工作的；诊断界面、重试队列和冲突。

**[归档](Archives.md)**

* 把数据从工作环境转移到归档环境：为什么需要它、归档的四种状态（当前、已打开、已关闭、
  已删除）、如何创建归档以及如何打开、关闭、删除它和从其他服务器下载回来、手动转移任务、
  模板、对象、经验记录和整个项目、归档规则（通用的和归档自己的）、用计划动作实现自动归档、
  用顶部栏的「环境」字段查看归档，以及从当前归档恢复数据。

**[插件与 MCP](plugins.md)**

* 外部程序和 MCP 服务器是怎么接进来的：一条插件记录由什么组成（动作、经验、程序、文档）、
  网关与 MCP 连接有什么不同、插件的五种状态以及为什么它们各服务器各不相同、初始化的顺序、
  「本服务器上未找到该程序」是什么意思，以及为什么绕过 AI2P 配置的 MCP 会绕开全部安全规则。

### 用户手册

**[项目](progects.md)**

* 项目文件夹以及它为什么是按服务器各自独立的、`Common` 文件夹和 `.repignore`、项目卡片的各个
  选项卡（基本、任务、团队、对象、安全、模板、经验、历史）、「价格 ↔ 质量」和「时间 ↔ 质量」
  设置、项目对象和 `@obj:` 引用、三个层级的经验。

**[项目对象](objects.md)**

* 对象有什么用、为什么 `@obj:` 引用胜过复述；对象的种类；列表及其四种视图；对象标签页、它的
  工具栏和「子对象」选项卡；对象表单、指向它的两个引用，以及 LoRA 适配器上带两个字段的「将进入
  模型的内容」窗口；对象的宿主服务器、在别的服务器上的只读模式，以及训练好的适配器如何传给
  邻居。

**[模板](templates.md)**

* 工作流程的样板以及经验存放的地方；模板与任务有什么不同；「经验」和「统计」选项卡，按技能和
  标签筛选经验；展开模板的三种方式，以及复制时阻塞任务会怎么样。

**[任务](tasks.md)**

* 把任务描述当作提示词；列表的四种视图、筛选和排序；表单的三个部分；卡片、作业控制台和暂停
  原因；聊天、代理的提问以及工作过程中的打断；手动、自动和层级启动；子任务和自动拆分；处理
  属于其他服务器的任务。

**[任务执行算法](TaskDo.md)**

* 整个层级启动的顺序：队列按优先级自下而上的遍历，任务何时等待、被跳过或被启动，队列何时
  关闭；「条件」「循环（先判断）」「循环（后判断）」如何融入这个顺序，轮数上限与停止。

**[经验](experience.md)**

* 系统关于"该怎样工作"的记忆：三个范围（组织通用规则、项目经验、模板节点经验）及其划分规则；一条
  经验有哪些字段、它如何进入委托——活动状态、技能、"始终加载"、作为信号的标签、层级配额与插入上限；
  "使用过的经验"页和使用统计；经验检索及其找不到的东西；在范围之间迁移条目与通用经验盘点；关停条目
  与"全部停用条目"的归档规则；经验套件（工作风格）以及放进计划的"经验分析"模板。

**[LoRA 编辑器](LoRAEditor.md)**

* 如何使用 LoRA 编辑器：训练前需要先建立什么、适配器描述和画面说明中该写什么、这两段文字中
  哪一段进入训练、哪一段进入生成提示词、如何启动和停止训练、数据集画面的顺序是否重要、常见
  错误，以及编辑器不做什么。这一页也可以用编辑器中带书本图标的按钮打开。

**[使用音频模型](audio.md)**

* 如何用音乐、歌曲、特定人物的说话声和噪声拼成一个声音场景：名录中有哪些音频模型、各自能做什么，
  为什么一个任务就是一层声音，语音合成需要什么样的声音样本以及如何传入，为什么歌手的声音要用文字
  描述，音效从哪里来，如何拼接和混合各层，常见错误。
