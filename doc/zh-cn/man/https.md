# HTTPS

默认情况下 AI2P 使用 **http** 通信：密码、API 密钥和任务内容都以明文在网络上传输。在一台计算机上
这与任何人无关 —— 流量不会走出回环。而一旦有人从别的机器访问服务器（集群、手机、同事），这场对话
就该加密了。

本章讲的是如何启用 **https**：证书从哪里来、设置里要填什么、有什么事必须**在浏览器里**做一次，
以及有什么事要在集群的**邻居服务器上**做。

---

## 1. 简要步骤

**最简单的办法是按一个按钮。** 在本机服务器表单里，协议选 `https`、来源选「文件」时会出现
**「创建证书」**按钮（见第 3 节）：程序会为自己签发一个证书颁发机构，并用它签发涵盖本服务器
所有名称和地址的服务器证书，文件字段也会自动填好。剩下的只是把颁发机构文件装入浏览器
（见第 5 节）。本章其余内容是给已经有证书、或者需要别的证书的人看的。

1. 取得证书：从证书颁发机构（Let's Encrypt 之类）、从您所在网络的管理员那里 —— 或者自己做一个
   （第 3 节）。
2. 把它作为文件放在 `config.json` 旁边，**或者**安装到计算机的证书存储中。
3. 设置 → **服务器** → 本地服务器表单：协议选 **https**，下面就是 **「HTTPS 证书」**一节。保存并
   **重启** AI2P。
4. 证书不是全球证书颁发机构签发的 —— 就要**在浏览器里**放行它（第 5 节）。集群邻居不会因此受阻：
   **「信任集群邻居的证书」**自 1.129 版起默认勾选（第 6 节）。

证书这一节**只有在选了 https 协议时**才可见：http 服务器没有证书，也就没什么好谈的。「信任集群邻居的证书」开关是个例外：它在这一节的**下方**，本机用哪种协议都能看到（见第 6 节）。

---

## 2. 证书从哪里来

来源有两种，在同一个表单里用字段**「来源」**选择。

### 文件

常见情况。可以用：

| 是什么 | 表单字段 |
|---|---|
| `.pfx` / `.p12` —— 证书和私钥在同一个文件里，通常有密码 | **证书文件**、**.pfx 文件的密码** |
| PEM 对 —— `cert.crt`（或 `fullchain.pem`）和单独的 `privkey.pem` | **证书文件**和**私钥文件** |
| 私钥就在同一个文件里的 PEM | 只填**证书文件** |

路径可以写**相对**的 —— 它是从 `config.json` 算起的（也就是从安装的工作目录算起，见
[安装](install.md)）；绝对路径和 `~/…` 按原样使用。

**`.pfx` 的密码永远不会进入 `config.json`** —— 它进密钥库（`secrets/https.certPassword.json`），
配置里只留下一个引用。保存时密码字段留空表示「不修改」，和邮件密码一样。

### 系统存储

**已经安装到这台计算机上的**证书：

* **Windows** —— 「证书」管理单元（用户用 `certmgr.msc`，计算机用 `certlm.msc`）；
* **macOS** —— 钥匙串（Keychain）；
* **Linux** —— 当前用户的 .NET 存储（`~/.dotnet/corefx/cryptography/x509stores`）。

在私钥**不应当以文件形式躺在磁盘上**的地方，就这么做 —— 例如证书由域颁发、由组策略续期。字段：

* **存储位置** —— `CurrentUser`（默认）或 `LocalMachine`。在 Linux 和 macOS 上，普通用户通常访问不了
  `LocalMachine`：请把证书放进**运行 AI2P 的那个用户**的存储里（对于服务，那就是它的账户，见
  [以服务方式运行](service.md)）。
* **存储分区** —— `My`（个人证书），常见情况。
* **证书中的名称（CN）** —— 名称的一部分；留空 —— 按本服务器的**主机名**查找。
* **指纹** —— 比名称更精确，而且当同一个名称有多个证书时（旧的和续期的）不会搞混。指定了指纹 ——
  就不再看名称。

只取**带私钥的**证书；如果符合条件的有多个 —— 取有效期最晚的那个。

## 3. 如何自己做证书

### 用程序里的按钮（最简单）

设置 → **服务器** → 本机服务器表单 → 协议选 **https** → 「来源」选 **文件** → 点
**「创建证书」**。程序会一次做出两份证书，正是浏览器所要求的：

* `certs/ai2pCA.crt` 和 `certs/ai2pCA.key` —— **自建证书颁发机构**。它要装入浏览器
  （见第 5 节），也要装入邻居服务器的受信任根证书（见第 6 节）；按钮旁边的
  **「下载自建颁发机构证书」**链接会把这个文件直接交给浏览器。
* `certs/ai2p.crt` 和 `certs/ai2p.key` —— 由该机构签发的**服务器**证书：`CA:FALSE`、
  `extendedKeyUsage=serverAuth`，`subjectAltName` 里写全了服务器的各个名称——设置里的名称、
  第二个（对外）名称、机器名、它在网络中的地址、`localhost` 和 `127.0.0.1`。有效期 825 天。

「证书文件」和「私钥文件」两个字段会自动填好，接下来只需**保存表单并重启** AI2P。再次点击
按钮只会重新签发服务器证书，**颁发机构会被复用**：不必再挨个去改浏览器。要给证书添加新的
名称或地址也是这样做：在表单里改好服务器名称，再点一次按钮。

> **这不需要运行任何证书颁发机构服务。** 浏览器不会「去问颁发机构」，也不会向它申请许可：
> 它用颁发机构的公钥在本地校验网站证书的**签名**，全程不联网。所以这里的「自建颁发机构」
> 只是两个文件，而不是需要在某处启动并一直开着的服务。对人来说要做的只有一件事：把颁发
> 机构文件装入浏览器一次。

当服务器在局域网内，全球证书颁发机构无法为它签发任何东西时（`ai2p.local`、`192.168.1.10`），
就需要自己的证书。

### Windows —— 用自带的 PowerShell

```powershell
$cert = New-SelfSignedCertificate -DnsName "ai2p.local","192.168.1.10" `
        -CertStoreLocation "Cert:\CurrentUser\My" -NotAfter (Get-Date).AddYears(3)
$pwd = ConvertTo-SecureString -String "密码" -Force -AsPlainText
Export-PfxCertificate -Cert $cert -FilePath "C:\ai\AI2P\ai2p.pfx" -Password $pwd
```

证书会立刻**既进入存储**（`CurrentUser\My`），**又成为文件** —— 两种来源用哪个都行。指纹由
`$cert.Thumbprint` 打印出来。

### Linux / macOS —— openssl

```sh
# 请把下面这两行换成你自己服务器的名称和地址——也就是你在浏览器地址栏里输入的那个。
# 原样照抄会把证书签发给别人的名称，浏览器会因名称不匹配而拒绝，无论你多么信任它
HOST=ai2p.local
IP=192.168.1.10

# 1) 自己的证书颁发机构 —— 装进浏览器的正是它
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
    -keyout ai2pCA.key -out ai2pCA.crt \
    -subj "/CN=AI2P local CA" \
    -addext "basicConstraints=critical,CA:TRUE" \
    -addext "keyUsage=critical,keyCertSign,cRLSign"

# 2) 服务器自己的证书，由上面这个机构签发
openssl req -newkey rsa:2048 -nodes -keyout ai2p.key -out ai2p.csr -subj "/CN=$HOST"
cat > ai2p.ext <<EOF
basicConstraints=critical,CA:FALSE
keyUsage=critical,digitalSignature,keyEncipherment
extendedKeyUsage=serverAuth
subjectAltName=DNS:$HOST,IP:$IP,DNS:localhost,IP:127.0.0.1
EOF
openssl x509 -req -in ai2p.csr -CA ai2pCA.crt -CAkey ai2pCA.key -CAcreateserial \
    -days 825 -out ai2p.crt -extfile ai2p.ext

# 3) 检查证书里写的是你自己的名称，而不是文档中的示例
openssl x509 -in ai2p.crt -noout -text | grep -A1 "Alternative Name"
```

会得到 `ai2p.crt` 和 `ai2p.key` —— 这就是表单要用的 PEM 对（「证书文件」和「私钥文件」），而
`ai2pCA.crt` 是装进浏览器的那一张（第 5 节）。`ai2p.csr` 是中间的「签名请求」文件：任何设置里都
不填它，证书签发之后也完全不再需要。把服务器的这一对合成一个 `.pfx` 文件是这样做的：

```sh
openssl pkcs12 -export -out ai2p.pfx -inkey ai2p.key -in ai2p.crt -passout pass:密码
```

`openssl` 由脚本 `install_required.sh` 安装（在 Windows 上是 `install_required.bat`，那里它不是必需
的：PowerShell 能做同样的事）。

> **`subjectAltName` 是必须的。** 浏览器已经很多年完全不看 `CN` 了：没有名称列表（`DNS:` 和 `IP:`），
> 证书即便被放行过也仍然会被拒绝。

> **只有一张自签名证书，浏览器是不认的。** `openssl req -x509` 生成的是「证书颁发机构」证书
> （`basicConstraints=CA:TRUE`），浏览器拒绝把这样的证书当作「网站」证书——即使这张证书本身已经加入
> 受信任的颁发机构。Firefox 把它叫作 `MOZILLA_PKIX_ERROR_CA_CERT_USED_AS_END_ENTITY`，屏幕上却只写
> 「您与该网站的连接不安全」，什么也不解释。所以要做两张证书：颁发机构，以及由它签发的服务器证书。
> AI2P 自己也会提醒这一点——在本地服务器表单中「证书可读取」那一行下面。

> **必须用证书里的名称来访问。** `subjectAltName` 列出了可以用来称呼服务器的名称，而 `localhost`
> 通常不在其中——所以浏览器会因名称不匹配拒绝 `https://localhost:5480`，而 `https://ai2p.local:5480`
> 可以打开。从 1.125 版起，AI2P 自己打开浏览器时用的就是设置中的服务器名称，而不是回环地址；如果您想
> 手工输入名称，请把它加入 SAN 以及 `hosts`（或 DNS）。

### Let's Encrypt 的证书

如果服务器在互联网上有真实的名称，就签发一张普通证书（`certbot`）并指定它的文件：`fullchain.pem` ——
「证书文件」，`privkey.pem` —— 「私钥文件」。每次续期之后都要**重启** AI2P：证书只在启动时读取一次。

## 4. 程序自身会检查什么

同样的检查在三个地方进行，这是特意这么做的。

* **本地服务器表单**不允许在证书不可用的情况下保存「https」。原因会用文字写出来：「证书文件不存在：
  …」、「证书没有私钥」、「存储 … 中没有符合 … 条件的证书」、「对于 .pfx，常见原因是密码不正确」。
  否则下一次启动就起不来了，而那时已经无法登录进去修改。
* **首次启动向导**同样会拒绝 —— 就在人这辈子看到的第一个界面上。
* **服务器启动**时会打印找到的证书（「证书 CN=…，有效期至 …，指纹 …」）或者拒绝的原因并停止：
  在要求 https 的时候悄悄退回 http，比起不来更糟。

在表单里，只要选了 https，还会显示一行**状态**：绿色 —— 「证书可读取：…」，黄色 —— 「没有证书：…」。
它在重启之前、而不是之后，回答「到底行不行」这个问题。

地址、端口和**协议只在重启后生效** —— 进程已经在监听原来的端口。

## 5. 浏览器设置

全球证书颁发机构签发的证书不用向浏览器解释。**自己的**证书（或者域的、或者其他非全球证书颁发机构的）
就得解释：否则每次访问浏览器都会用「您的连接不是私密连接」页面来迎接您。

正确的做法是**一次性**把证书（或者您的证书颁发机构的证书）加入受信任列表。这要在**查看用的那台
计算机上**做，而不是在服务器上。

> **装进浏览器的只有证书颁发机构的文件 `ai2pCA.crt`。** 服务器证书 `ai2p.crt` 既不需要导入，也
> 导入不了：浏览器的「证书颁发机构」里只接受 `CA:TRUE` 的证书，而服务器证书是特意做成 `CA:FALSE`
> 的，Firefox 会回答「这不是证书颁发机构的证书，因此无法导入到证书颁发机构列表」。服务器自己就
> 会把正确的文件交出来：「创建证书」按钮旁边有**「下载自建证书颁发机构的证书」**链接。如果证书
> 不是用按钮、而是用 `openssl` 做的，那么机构文件就是第一条命令产生的 `ai2pCA.crt`（第 3 节），
> 绝不是 `ai2p.crt`。

**Windows（Chrome、Edge、系统里的任何浏览器）。** 把 `ai2pCA.crt` 复制到计算机上 → 双击 →「安装证书」
→「本地计算机」→「将所有的证书都放入下列存储」→ **「受信任的根证书颁发机构」**。
用管理员身份运行的 PowerShell 做同样的事：

```powershell
Import-Certificate -FilePath ai2pCA.crt -CertStoreLocation Cert:\LocalMachine\Root
```

**macOS（Safari、Chrome）。** 双击 `ai2pCA.crt` → 证书进入钥匙串 → 打开它 →「信任」→「使用此证书时」
→ **「始终信任」**。

**Linux（Chrome/Chromium）。** 设置 →「隐私和安全」→「安全」→「管理证书」→「颁发机构」选项卡 →
「导入」→ 勾选「信任此证书以标识网站」。对整个系统：

```sh
sudo cp ai2pCA.crt /usr/local/share/ca-certificates/ai2pCA.crt && sudo update-ca-certificates
```

**Firefox** 有**自己的**存储，不读系统存储：设置 →「隐私与安全」→「证书」→「查看证书」→
「证书颁发机构」→「导入」。

> **导入窗口里的复选框必须勾上。** 选好文件后，Firefox 会问「信任此 CA 来标识网站吗？」
> （*Trust this CA to identify websites*），而这个框默认是**没有勾选**的。不勾它，证书照样
> 会进入「证书颁发机构」列表、也看得见，但它并不被信任用于网站，页面依旧会出现警告。这就是
> 「装了 CA，Firefox 还是报错」最常见的原因。不重新导入也能检查和修复：在「证书颁发机构」
> 列表里选中自己的 CA →「编辑信任」→ 勾选「此证书可以标识网站」。

**到底是什么错误。** 在警告页上按「高级」，底部会打印错误码，据此就知道该修什么：

| 代码 | 含义 | 怎么办 |
|---|---|---|
| `SEC_ERROR_UNKNOWN_ISSUER` | 存储里没有该 CA，**或者**没有勾选信任网站 | 安装 `ai2pCA.crt` 并勾选复选框（见上） |
| `SSL_ERROR_BAD_CERT_DOMAIN` | 你输入的名字不在 `subjectAltName` 里 | 用证书里的名字访问，或在服务器设置里加上该名字后再按「创建证书」 |
| `MOZILLA_PKIX_ERROR_CA_CERT_USED_AS_END_ENTITY` | 服务器给出的是 **CA** 证书而不是服务器证书 | 见 § 3：需要两张证书，最简单的办法是用按钮 |
| `SEC_ERROR_EXPIRED_CERTIFICATE` | 已过期 | 重新签发（按钮） |

同一处还有两个细节：证书是**启动时**读取的，所以按过「创建证书」之后要保存表单并**重启**
AI2P，否则浏览器看到的还是原来的文件；之前为这个地址加过的「例外」在设置 →「隐私与安全」
→「查看证书」→**「服务器」**里清除。

**Android / iOS。** `.crt` 文件在系统设置里打开（「安装证书」/ 配置描述文件）；在 Android 上，为了
Chrome 能用，必须把证书装成「CA 证书」，否则它会被装成「用于 VPN」，浏览器就看不见它。

最容易绊倒人的三件事：

1. **名称必须相符。** 如果您访问的是 `https://192.168.1.10`，而证书里只有 `DNS:ai2p.local`，那么
   即使证书已被放行也救不了您。请在 `subjectAltName` 里写上两个名称 —— 或者就按证书签发的那个名称
   访问。
2. **「仍然继续」不是解决办法。** 例外只活到浏览器重启为止，而且有一部分浏览器这样做会破坏界面赖以
   生存的 WebSocket 连接：界面能打开，然后就僵住。
3. **设置里的服务器名称必须和证书里的一致**：指向任务的链接是用「主机名」字段生成的
   （见 [多台服务器](servers.md)）。

## 6. 走 HTTPS 的集群

> **该开关始终可见，不只在本机使用 `https` 时。** 这项设置针对的是**发出的**调用：本机即使
> 使用 `http`，同样会用 `https` 去呼叫邻居，同样会撞上对方的自制证书（「The remote
> certificate is invalid because of errors in the certificate chain: UntrustedRoot」）。
> 1.126 之前这个开关放在证书小节里——在 http 服务器上根本看不到它，只能靠手工改
> `config.json` 才能打开。它保存后**立即生效**，无需重启。

服务器是**自己**互相访问的，那里没有人能确认例外：只要证书不是全球证书颁发机构签发的 —— 复制就会
因校验失败而永远停摆，直到有人改设置为止。

因此这一节里有一个复选框 **「信任集群邻居的证书」**（`ui.https.trustAnyPeer`，**自 1.129 版起默认
勾选**）。勾上之后，它**只对服务器之间的调用**取消证书校验 —— 申请、复制和文件传输；它不涉及浏览器，
也不涉及对模型提供方的访问。

默认值之所以改变：我们服务器上的证书几乎总是自建的（§ 3）。复选框不勾时，接入已启用 https 的集群的
第一台服务器就会以「远程证书被拒绝」停住，而且根本无从判断该去哪里找原因。何况服务器本来也只能凭
共同的密钥才能加入集群。若需要严格校验证书链，请把自建证书颁发机构的证书分发到集群的所有机器上
（§ 5），并**取消**勾选：取消后的设置能在升级后保留。

关于集群还有两条规则：

* 协议是**服务器记录的属性**。在服务器列表里写着 `https` 的邻居就按 https 访问；把某台服务器切到
  https 时，请把它在邻居那里的记录也改好（通常它会靠复制自己传过去）。
* **通过回环访问自己时不校验证书。** 界面是按 `localhost` 访问自己的 API 的，而没有任何证书与这个
  名称相符 —— 那里没什么可校验的，另一端就是同一台计算机。这同样适用于 AI 智能体使用的命令行客户端
  `ai2p`。

## 7. `config.json` 中可改的内容

用表单改的是同样的东西；需要文件是在进不了系统的时候。修改之前请**停止**程序。

```json
{
  "ui": {
    "protocol": "https",
    "port": 5480,
    "hostname": "ai2p.local",
    "https": {
      "source": "file",
      "certFile": "ai2p.pfx",
      "keyFile": "",
      "passwordRef": "https.certPassword",
      "storeLocation": "CurrentUser",
      "storeName": "My",
      "subject": "",
      "thumbprint": "",
      "trustAnyPeer": true
    }
  }
}
```

* `source` —— `file`（默认）或 `store`。留空以及不认识的值都按 `file` 读：以前版本的配置里只有两个
  路径，那样的配置照旧工作。
* `passwordRef` —— 是密钥库中密码的**引用**，而不是密码本身。取值在表单里输入，或者手工放进
  `secrets/https.certPassword.json`。
* 解析取决于扩展名：`.pfx`/`.p12` 按 PKCS#12 读，其余一切按 PEM 读。

## 8. 如果没起来

| 看到什么 | 这是什么 | 怎么办 |
|---|---|---|
| 「HTTPS：未指定证书」 | 协议是 `https`，而这一节是空的 | 指定文件或选择存储 |
| 「HTTPS：证书文件不存在：…」 | 路径不对 | 路径是**从 `config.json`** 算起的；请核对消息里给出的完整路径 |
| 「HTTPS：无法读取证书 …」 | `.pfx` 的密码不对，或者文件不是 PKCS#12 | 检查密码；PEM 文件需要 `keyFile` |
| 「HTTPS：证书没有私钥」 | 只指定了一个不带私钥的 `.crt` | 加上 `keyFile`，或者改用 `.pfx` |
| 「HTTPS：存储 …/… 中没有证书 …」 | 分区不对、用户不对，或者没有私钥 | 核对存储位置和指纹；服务查看的是**它自己**账户的存储 |
| 浏览器里显示「您的连接不是私密连接」 | 浏览器不认识这个证书 | 第 5 节 |
| 界面打开后僵住 | 浏览器因临时例外断开了 WebSocket | 不要「仍然继续」，而要按第 5 节放行证书 |
| 复制因证书错误停摆 | 邻居不信任我们的证书颁发机构 | 第 6 节 |
