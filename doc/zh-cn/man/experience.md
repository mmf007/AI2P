# 经验

**经验是系统关于"该怎样工作"的记忆。** 一条任务总结出的简短教训，会被插入到其他任务的委托文本中——
于是下一个执行者不会再踩同一个坑。

经验条目由人和 AI 智能体共同积累。人在经验列表里维护（项目卡片的"经验"页、模板节点的"经验"页、
**设置 → 通用经验**）；智能体则在工作过程中用 `create_experience` 和 `update_experience` 工具写入。

---

## 三个范围

一条经验只属于一个范围，范围决定了谁能收到它。

| 范围 | 谁收到 | 讲什么 |
|---|---|---|
| **组织的通用规则** | 组织内所有项目的每一个任务 | 我们怎样工作：流程、报告、检查纪律 |
| **项目经验** | 本项目的任务 | 这个产品：结构、坑、决策、实体名称 |
| **模板节点经验** | 由该节点（及其子节点）创建的任务 | 流程中的这一步 |

划分规则一句话——同样的文字会显示在条目表单和迁移窗口里：

> 通用规则讲的是**我们怎样工作**：它在组织的任何项目里都成立，不提任何文件、任务编号或产品名称。
> **项目**经验讲的是这个产品。**模板节点**经验讲的是流程中的这一步。

这条规则不是装饰：通用规则会发给组织的**每一个**任务，误入其中的项目条目会挤占所有人的位置。因此
写入通用经验时，系统按四个迹象检查文本——**任务编号**（`T-241`、`T-12-S0`）、**文件路径**、
**源码扩展名**、**项目名称**：

* 对 AI 智能体**直接拒绝**，并建议把条目写进项目经验。悄悄改换范围会让随后按标识符查找该条目的
  智能体迷失方向；
* 对人在表单里显示**警告**和**"仍然保存"**按钮——你可能比检查更清楚；
* 随插件带来的条目完全跳过检查：安装插件的人已经做过决定了。

检查作用于：创建通用条目、编辑通用条目、以及把条目迁**入**通用规则。

### 通用经验盘点

积累的垃圾不是一条条清理的。在**设置 → 通用经验**页的列表上方有**"通用经验盘点"**区块：它提示
"在通用经验中看起来像项目经验：N 条"，逐行说明**被哪个迹象抓到**，并把勾选的条目成批迁到所选项目。
迁移逐条进行，因此某一条被拒（他机服务器的条目、发行版自带规则）不会影响其余条目。

### 在范围之间迁移条目

列表行里的**"迁到另一个范围"**按钮打开选择窗口：先选范围，再选项目或模板节点。

迁移**只改变归属**。标识符、文本、标签、技能、作者、创建时间以及"始终加载"和"启用"标记都保持不变——
条目不会被重建，指向它标识符的引用也不会失效。

不能迁移的：

* **他机条目**——由集群中另一台服务器创建的：别人服务器上的垃圾在那边清理；
* **发行版自带的规则**——每台服务器各自播种，迁移会产生同一行的第二份副本。碍事的自带规则要用活动
  标记**关掉**，而不是迁移或删除。

## 一条经验有什么

* **文本**——教训本身。一条只讲一件事，用祈使语气，不复述常识。
* **技能**——写给谁的（`code-test`、`text-docs`……）。**既没有技能、又没有"始终加载"标记的条目根本
  进不了委托**——模板节点经验除外，那里没有技能的条目仍然对该节点的所有任务通用。
* **标签**——条目的主题。自 1.135 版起，标签**不再筛掉**条目（见下文），而是在分配篇幅时把条目往前排。
* **"始终加载"**——不论执行者的技能是什么，条目都会进入委托。这个标记很贵：它给**每一个**任务的提示词
  上税，所以只应给对任何执行者都成立的规则使用。
* **"启用"**——条目的开关（见"活动状态与归档"）。
* **作者与属主服务器**——只有条目自己的服务器才能编辑、迁移和开关它。

## 条目如何进入委托

系统为执行者组装委托文本时，会打印经验区块：先是"通用工作规则"，然后是"项目经验"，然后是模板节点经验。
并非全部都能进去——筛选分三步。

### 第一步：谁有资格

1. 条目处于**启用**状态——关掉的条目永远不会进入委托，即使带着"始终加载"标记；
2. 条目带**"始终加载"**标记——无条件取用；
3. 否则条目必须有**技能**，并且与执行者的技能相符。

**标签在这里不再参与。** 以前标签不匹配的条目在任何计算之前就被丢弃——而智能体会给新条目打上任务的
标签，久而久之这个过滤器就会因为一个词的形式不符而丢掉真正需要的东西。现在标签是**信号**：匹配给条目
加半步相关度，不匹配不会让它出局。

### 第二步：模板祖先节点的经验

由模板节点创建的任务，**不只**得到本节点的经验，还得到沿链向上直到根节点的全部经验。模板中相邻分支的
经验仍然与它无关，不会被取用。

### 第三步：上限与配额

一次委托中的经验总量受项目设置限制（默认 **100 000 个字符**）：否则经验区块会把任务本身挤出模型窗口。
篇幅这样分配：

1. **"始终加载"**的条目最先取用——不参与竞争，也不占配额；
2. 余下的篇幅按**层级配额**划分：模板节点经验 **50 %**、项目经验 **30 %**、通用规则 **20 %**。
   层级内部按相关度排序：本节点 → 父节点 → 祖父节点 → 项目 → 通用规则，标签匹配再加半步；
3. **未用完的配额会流向**相邻层级：空层级不会占着位置。

配额的意义在于不让某一个话多的层级吃掉全部预算：没有配额，项目经验会同时挤掉通用规则和最贴切的节点经验。

条目**整条**插入：半截教训会被读成另一条教训。打印顺序仍按时间先后，与列表一致。

**这解决不了什么。** 上限被填满时，离题的条目仍然到不了——它不再因规则被丢弃，只是被更贴切的条目超越。
这样的条目只能用检索取回（见下文）。

如果有条目没放下，系统会在委托里说明，并告诉执行者检索工具的名字——被舍弃的内容不会消失，而是可以按需
取用。

## 任务使用过的经验

系统**实际**给智能体插入了哪些条目，可以在任务卡片的**"使用过的经验"**页看到。该页只在列表非空时出现
（从未运行过的任务无内容可显示）。

顶部是**汇总**：有多少条目进入了委托、合计多少字符——既给出数字，也给出占经验插入上限（项目设置）的
比例。由此可以看出上限定得是否合适。

列与"经验"页相同（文本、范围、技能、标签、活动状态、最近使用时间），每行右侧还有**"修改记录"**按钮：
这里保存的是指向条目的链接，因此修改直接落到条目本身，无需再到经验列表里重新查找。已删除或已归档的
条目显示为"条目 … 不可用"，也无可修改：使用痕迹只保存标识符，比条目本身活得更久。

同一份日志的另一面是**条目的统计**：有多少个**任务**收到过它、最近一次是什么时候。由此可以看出哪些经验
真正在起作用，哪些只是躺着占用提示词的篇幅。

## 检索经验

每个经验列表的筛选器上方都有一行**"按文本检索"**。与按技能、标签、活动状态筛选不同，检索还决定**顺序**：
结果按排名给出，而不是按日期。排名融合三个信号——词面命中、条目新旧、与任务标签的匹配数量；但**只有词面
命中才能找到东西**，新旧和标签只是重排已找到的结果。

AI 智能体用的是同一套检索——`search_experience` 工具（范围
`project` / `template` / `general` / `all`，默认只搜启用的条目）和命令

```
ai2p experience-find "查询词" --scope project --limit 10
```

因上限而没能进入委托的内容，正是靠检索取回的。

### 检索找不到什么——说实话

1. **含义。** 如果条目里没有"打包"和"构建"这些词，"怎么打包"就找不到写着 "MakePackage" 和 "Inno Setup"
   的条目。
2. **同义词和缩写。** "技术规格" ≠ "规格书"，"库" ≠ "数据库"。
3. **复杂词形。** 词尾只做粗略截断，前缀完全不剥离（"重新索引" ≠ "索引"）。
4. **拼写错误。**

### 重复条目的防护

智能体创建新条目时，系统会把它与**同一范围**里已有的条目比较：

* 重合度**非常高**时不创建：把找到那条的标识符和文本返回给智能体，并建议去修改它；
* 重合度**明显**时创建，但打上 `similar:<id>` 标签——留给人工盘点的记号。

同一个意思**换一套词**复述出来，词面比较是抓不到的——这是任何词面比较的原理性上限。

## 活动状态与归档

条目可以**关掉**而不删除。关掉的条目仍留在列表里，看得见也能恢复，但不会进入委托。

* 列表里的**"活动状态"**筛选器：**启用 / 停用 / 全部**，默认"启用"。
* **"启用"列**和行内的切换按钮——权限与编辑、删除相同。
* 条目表单里的**"启用"**开关。

**发行版自带的规则**也可以关掉——否则就没有办法移除它们：播种不会把删掉的内容找回来，而关掉的条目一键
即可复原。

**AI 智能体不删除经验。** 盘点只**关掉**条目（`set_experience_active`），关掉的内容随后由归档带走——
这是刻意的：关掉的总能恢复，删掉的不能。智能体无权关掉发行版自带的规则：那是它自己据以工作的规则。

### "全部停用条目"的归档规则

在归档规则中，数据种类**"经验"**支持"仅停用"筛选：停用的和已删除的条目都在其中。

与之配套还有第三种期限——**"不限时间"**。旧的规则表单要求期限严格大于零，因此"归档**全部**停用条目"这条
规则根本写不出来。现在可以了：选数据种类"经验"、筛选"仅停用"、期限"不限时间"——表单会自动隐藏数字字段，
规则列表把这种期限显示为"任意"。

这条规则刻意**不**放进新归档的默认值：系统不应该未经允许就把别人的经验搬进归档。想要定期清理，请自己创建它。

关于归档、规则和按计划自动归档的更多内容，见**[归档](Archives.md)**一章。

## 经验套件：工作风格

**套件是一包现成的经验条目，一个按钮装上、一个按钮卸下。** 工作纪律（"怎样做评审"、"怎样写测试"、
"怎样写报告"）由此开箱即得，而不必在每个组织里重新发明。

页签：**设置 → 经验套件**。

### 安装

1. 选择**安装范围**：组织通用规则、项目经验或模板节点（后两者还要选具体的项目/节点）。范围不保存在套件
   文件里：这是你的选择，界面也不允许跳过。
2. 按**"安装"**。系统会建立套件的条目并告诉你建了多少条。
3. 套件行里的**"i"**按钮打开**套件文档**——这是什么风格、给谁用、安装后智能体的工作会发生什么变化。
   随附套件的文档放在 `doc/<语言>/packs/`。

### 卸下与重新安装

**"卸下"**按钮只移除本套件的条目——安装时会给它们打上服务标签 `pack:<代码>`。你自己的条目和你对文本的
修改不会被动：你改过的条目仍然是你的，重新安装**不会覆盖**它。

### 导出自己的套件

**"导出条目到套件"**区块用**你自己的**条目做一个套件：用筛选器和勾选框挑出条目，填上代码、名称和描述，
就得到一个可以装到另一处安装上的套件文件。条目标识符会被保留，因此反向安装得到的是**同样的行**，而不是
它们的副本。

### 关于语言，需要知道的

随附套件的文本用界面的五种语言都写了，但**一条经验只以一种语言存在**：安装时取服务器的语言。因此在另一种
语言的委托里，区块标题会被翻译，而条目文本仍是安装时的语言。这是套件的构造方式，不是翻译缺陷。

### 发行版自带哪些套件

| 代码 | 名称 | 讲什么 |
|---|---|---|
| `style.strict-review` | 严格代码评审 | 先看委托、后看差异；每条意见都有分量；结论必须给出 |
| `style.tdd` | 测试驱动开发 | 先写红色的测试，再做最小的改动 |
| `style.research-report` | 调研与报告 | 来源、数字和"哪些没做"一节的纪律 |
| `style.experience-analysis` | 经验分析 | 不是风格，而是用于盘点已积累经验的**任务模板** |

套件文件放在数据目录的 `packs/` 子目录，与 `plugins/` 和 `models/` 并列；随附套件由程序在打开组织时自己
放进去。

套件总览及其文档见**[经验套件：工作风格](../packs/README.md)**。

## "经验分析"模板

经验积累的速度快于它老化的速度：条目会重复、会过时、会待在错误的范围里。这些没有人会手工去整理——所以
盘点被安排成**交给 AI 智能体的任务**，按计划运行。

`style.experience-analysis` 套件会一并带来**任务模板节点**：

* **"经验分析"**——根节点，含完整说明：读什么（使用统计 → 分页列出条目 → 需要时检索）、做什么（归并、
  拆分、打标签、迁移、按统计关停）、**不**做什么（不删除、不动他机条目、不关自带规则、归并时不改写原意），
  以及报告里要写什么——标识符和"原有 / 仍启用"的数字；
* **"组织通用经验分析"**——通用规则的子节点；
* **"项目经验分析"**——项目的子节点；有几个项目就复制几份。

按统计关停的规则是**用文字**写在根节点的委托里的，没有写死在代码里：若一条经验三个月没有进入任何委托，
**而且**这段时间确实有它主题的任务，就把它关掉。"没进入是因为根本没有这类任务"不构成关掉的理由。请直接在
模板里按你自己的流程调整这段措辞。

### 怎样把盘点放进计划

1. **设置 → 经验套件 → "经验分析" → "安装"**，范围选**项目**或**模板节点**。"组织通用规则"范围根本没有
   项目，而 AI2P 里的任务模板离不开项目——那样节点不会建立（条目照常安装）。
2. **项目模板**——根节点"经验分析"已经出现，带两个子节点。把"项目经验分析"子节点按项目数量复制，并为每份
   指定各自的项目。
3. **设置 → 计划**——创建周期性计划（每周或每月），模板选**"经验分析"**节点。

计划只接受模板的**根**节点：子节点会随根节点一起复制过来，不需要各自的计划。安装套件刻意**不**创建计划——
运行任务要在模型上花钱，这应由人来决定。

关于周期、计划所属服务器和逾期触发的更多内容，见**[计划](schedule.md)**一章。

## AI 智能体能对经验做什么

| 工具 | 作用 | CLI 命令 |
|---|---|---|
| `create_experience` | 创建条目 | `ai2p experience` |
| `update_experience` | 修改文本、技能、标签、"始终加载"、活动状态 | `ai2p experience-update` |
| `search_experience` | 按词检索条目 | `ai2p experience-find` |
| `list_experience` | 分页列出某范围的条目 | `ai2p experience-list` |
| `experience_usage` | 使用统计 | `ai2p experience-usage` |
| `move_experience` | 把条目迁到另一个范围 | `ai2p experience-move` |
| `set_experience_active` | 启用或停用条目 | `ai2p experience-active` |

`update_experience` 中**没有传入的字段不会被改动**：改文本不会清掉人设置的标记。

**智能体没有删除经验的能力，将来也不会有。** 以上动作都登记在动作目录里，因此受任务和团队的安全规则约束——
见**[设置](config.md)**一章的"动作"页签。

## 常见问题

**条目存在，但委托里没有它。** 按顺序检查：它**启用**了吗？有**技能**吗，执行者有这个技能吗？如果没有技能
——有没有"始终加载"标记？如果这些都成立，那多半是没放进上限：看看最近一次运行的"使用过的经验"页。

**智能体拒绝创建通用规则。** 文本里出现了任务编号、文件路径、源码扩展名或项目名称——这是**项目**经验，不是
通用规则。要么写进项目经验，要么改写成不带这些迹象的表述。

**通用经验里堆了项目垃圾。** 设置 → 通用经验 → "通用经验盘点"区块：勾选并成批迁到相应项目。

**某条自带规则碍事。** 用活动标记关掉它。不需要删除——播种不会把删掉的内容找回来。

**经验太多了。** 把盘点放进计划（"经验分析"模板），并创建一条"经验 + 仅停用 + 不限时间"的归档规则。
