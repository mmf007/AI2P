# LoRA 编辑器

**LoRA** 适配器是一个不大的文件，里面是给模型权重的附加量。它只教会模型一件具体的事：某个
角色的脸、某种材质的质感、某种绘画的笔法。训练完成后，适配器会在生成期间挂载到模型上 —
于是角色不再一个镜头一个样地「走样」，哪怕在只靠一份文字档案已经不够用的地方也是如此。

**LoRA 编辑器**就是这样一个表单：在其中收集数据集（带说明的画面）、建立要为之训练适配器的
模型清单，并启动训练本身。这一页讲的就是它。

这份说明可以直接从编辑器里打开：表单右上角带书本的按钮。

---

## 1. 开始之前

训练不是一个按钮，而是一个训练程序在干活，而这个程序住在 **AI2P 之外**。要让编辑器能够启动
它，需要四样东西：

| 什么 | 在哪里设置 | 怎么检查 |
|---|---|---|
| 本服务器上的项目文件夹 | 项目卡片，「基本」选项卡 | 没有它就会被拒绝：「项目在本服务器上没有文件夹：无处收集训练数据集」 |
| 能够使用适配器的模型 | 设置 → 模型，记录上的 LoRA 标记 | 编辑器「模型」选项卡中，不合适的记录的「训练」按钮是灰的 |
| 该模型的训练命令 | 模型配置档，`lora.train.start.command` 一节 | 没有它就会被拒绝：「模型名录中没有说明用什么训练：未设置训练命令」 |
| 模型仓库 | 设置 → 服务器 → 本地服务器表单，「模型仓库」字段 | 训练好的适配器会放到那里的 `loras` 子目录中 |

还有三样东西不需要单独设置，但同样参与工作：**训练器插件**、**「自动软件」执行者**和
**训练任务的模板**。训练器随模型安装一起到来，而执行者和模板由训练启动窗口自己用一个按钮
创建 —— 见第 5 节「训练以任务的形式进行」。

您的模型究竟能做什么，在它的名录记录里可以看到：**设置 → 模型**，「LoRA」一列（打勾 — 可以
用，带提示的横杠 — 说明为什么不行），而在记录表单本身里则有「适配器的挂载方式」、「训练」、
「训练好的适配器存放位置」几行，以及**「如何训练该模型的适配器」**这个链接。应当从它开始：
那里放着发布这个模型的人写的说明。

关于训练命令要单独说一句。**Kandinsky 5 的两条记录**在发行包中**都带有**训练命令，什么都不用
填：训练由 musubi-tuner 完成，而训练器连同 Python 都是**在安装模型时**送来的 — 用模型表单里
的「安装」按钮，就在下载权重的同一个地方（详情见模型文档，「i」按钮）。第一次启动训练时，
只需要准备配置文件（`dataset.toml`、`train.cmd`）：带 torch 的 `.venv` 环境、训练器依赖以及
Qwen2.5-VL-7B 和 CLIP 文本编码器（约 18 GB）都随模型安装一起装好，安装窗口里能看到进度，
而不是训练中途偷偷下载。如果这台计算机
上已经装了 Python 3.10–3.12，安装程序不会去下载它，而是用您的。其余记录的命令则是**有意留空
的**：训练用仓库的目录、环境和启动参数每个都不一样，凭空编一条命令比留空更糟 — 请顺着模型
表单里的链接把它拼出来，一次性写进配置档（`lora.train.start.command`）。

除了命令，配置档还可以带上**训练器的配置文件**（`lora.train.files`）：数据集的配置、启动
脚本。它们会在每次启动前被放到数据集旁边，并且每次都被**覆盖** — 要改它们得改模型的配置档，
而不是改磁盘上的文件；您自己的文件请用自己的名字命名，没有人会去动它们。

对于那些**在系统外**训练的名录记录（llama.cpp 的本地文本模型），从 AI2P 启动训练会得到拒绝：
「模型 …… 的适配器在系统外训练 — 请手工放置现成的文件并填写它的路径」。这不是故障：这类模型
在编辑器里做数据集、维护清单，而训练要用您自己的手段完成，然后把现成文件的路径填进对象表单
的「适配器文件」字段。

## 2. 如何打开编辑器

1. 打开项目卡片 → **「对象」**选项卡。
2. 建立一个类型为 **「LoRA 适配器」**的对象（「新建对象」按钮，「类型」字段）并**保存**它。
   在对象保存之前，设置按钮根本就不存在：数据集画面和训练行需要一个归属者，而尚未建立的对象
   还没有编号。
3. 打开这个对象并点击 **「LoRA 设置」**。

「LoRA 适配器」这一节和这个按钮只有类型为「LoRA 适配器」的对象才有。角色、场景和道具没有
自己的适配器 — 但它们可以有一个**现成的**适配器：把它的文件路径填进同一个表单的「适配器
文件」字段，那么每当有任务描述引用这个对象时，适配器就会挂载到模型上。

编辑器表单由 **「描述」**字段和两个选项卡 — **「数据集」**和 **「模型」** — 组成。

---

## 3. 「描述」字段：该写什么

这就是对象表单里叫做 **「档案（会进入提示词）」**的那同一段文字 — 对象没有第二份描述。它
**不参与训练**，它进入的是**生成**的提示词：当任务描述里有 `@obj:OBJ-7` 这样的引用时，替换
上去的正是这段文字。

该写什么：

* **逐字描述适配器学会了什么**，而不是给自己写的备忘：「30 岁女性，及肩红发，绿眼睛，雀斑，
  灰色夹克」— 而不是「玛莎，我们的主角，见画面」；
* **关键词（触发词）**，如果它在画面说明中用到了的话 — 模型正是靠它想起学到的东西：
  「`m4sha_rf`，30 岁女性，……」；
* **能力与边界**：适配器**不会**什么（「只有半身，没有全身的画面」）— 这能省下好几次失败的
  生成；
* 要用**写任务描述所用的那种语言**来写：这段文字会原样进入提示词，与镜头描述的其余部分混在
  一起。

不需要写的东西：诸如「在 40 个画面上训练了 2000 步」这类备注 — 它们对生成没有帮助，却要占
提示词的位置。这类信息有「模型」选项卡：那里能看到为哪个模型、在什么时候训练过。

描述**不是在这里保存的**。「应用」按钮把它送回对象表单，而保存它的是对象表单 — 连同表单的
其余部分一起。画面和训练行则相反，每一次操作都立即保存：训练要跑好几个小时，不能因为一次
误按「取消」就丢掉。

## 4. 「数据集」选项卡

数据集就是一组画面：**图片 + 说明**。适配器正是照着它们学的。

**数据集是一个独立的对象**（1.98 版）。当您打开编辑器时它会自动建立，名叫「数据集」，作为
您的适配器的子对象存在；而画面已经是它的子对象了。这样做是为了层级：当画面还是对象的直接
子项时，几十张图片和有意义的子对象混在一起，那份列表根本没法看。

### 4.0. 当前数据集，以及为什么会有好几个

选项卡的最上方是 **「当前数据集」**字段和 **「+」**按钮。

* 选项卡上的一切都属于**所选的**数据集：画面列表和图片的限制设置都是。新的画面也放进它里面。
* **「+」**按钮会询问名称并建立又一个数据集，并立刻把它设为当前的。
* 数据集之所以有好几个，是因为**不同的模型对图片的要求不同**：一个在 768×512 的 PNG 上训练，
  另一个要 1024×1024。给它们共用同一组画面，就意味着每换一次模型都要重新收集一遍。

选择是记在**对象**上的，而不是记在窗口里：之后启动的训练也会按当前数据集进行。

### 4.0.1. 图片限制的设置

**「数据集图片的限制」**一节，就是画面在被加进**这个数据集**时会被压缩到的那些上限：宽度、
高度、以 KB 计的大小、格式，还有最少需要多少画面、最多取多少才有意义。

* 建立数据集时，它们会**从应用的通用设置中抄过来**（**设置 → 基本 → 「LoRA 数据集画面」**），
  此后各过各的日子。
* **「从模型填入」**按钮会填上模型在名录中声明的值。列表里只有本对象「模型」选项卡上那些
  在名录中填了限制设置的模型：从沉默不语的模型那里没什么可填的。如果模型报出了好几种格式，
  填入的是 **PNG** — 它是无损的。
* 改动过的值用 **「保存」**按钮写入；已经添加过的画面不会因此重做 — 新的上限对下一个画面
  才生效。

### 4.1. 如何添加画面

「+」按钮会打开画面的表单。接下来是两步，而且这两步都不多余。

**第 1 步。取来原图。** 要么用 **「按地址」**（`http://…`，图片由服务器下载），要么用
**「本机文件」** — 带文件夹的按钮会打开对本机各磁盘的浏览。浏览的起点是：

* 路径字段里已经填好的那个目录，如果那里有的话；
* 否则是**上一次取文件时用的那个目录**；
* 否则是**项目文件夹**；
* 只有以上都没有时，才从磁盘列表开始。

上一次选择的目录是永久记住的（既能挺过窗口关闭，也能挺过下一次登录），所以从同一个文件夹里
成批添加画面时，不必重新在磁盘上乱转。那个目录也可能已经不在了 — 那么浏览会从最近的一个还
存在的上级目录开始，而不是给您看一个空列表。

点击 **「加载」** — 原图会进入存储，并出现裁剪框。

**第 2 步。裁出画面。** 拖动方框的左上角和右下角：框里的部分会成为画面。裁切、压缩和格式
转换都是**在浏览器里**做的 — 送到服务器上的已经是做好的图片。方框下面写着画面会被压缩到多少：
上限取自**这个数据集的图片限制设置**（见 4.0.1），而不是应用的通用设置 — 通用设置只是它们在
建立那天的一份快照。长宽比不会改变，缩放系数取两者中较小的那个。没能塞进尺寸上限 — 那就把
方框缩小，或者在数据集的设置里把上限提高。

画面会放进**组织的数据目录**的 `projects/<项目代号>/objects/<对象代号>/<数据集代号>/` 子目录中，
并建立成一个类型为「参考帧」的对象 — 它是**数据集**的子对象。因此这些画面在项目对象的总列表里
也能看到。

这个位置不是随意选的：组织的数据目录会**参与复制**，所以在这里收集好的数据集在集群的其他服务器上
也能看到 — 在那里可以打开它、查看画面并据此启动训练。项目文件夹是每台服务器各自的，不会在集群里
流转，所以放在其中的画面（1.112 版之前就是这样）在邻近服务器上根本看不到。早先版本积累的画面，
程序会在新版本首次启动时自己搬过去；项目文件夹里的原始文件不会被删除 — 那个文件夹属于您。

### 4.2. 画面的说明：该写什么

**「画面描述」**字段是**训练唯一能看到的文字**。在数据集目录中，它会以同名的 `.txt` 文件放在
每张图片旁边（有些模型用的是一个共同的 `captions.json` 文件；具体用哪种，写在模型的配置档
里）。

以下是 LoRA 训练实践检验过的建议：

* **描述这个画面，而不是描述角色本身。** 训练会学到所有画面中相同的那部分 — 而这部分不需要
  写说明。要写说明的是一个画面一个样的东西：视角、景别、光线、背景、衣着、表情；
* 如果您有关键词，就**从关键词开始写**：`m4sha_rf, 特写, 左侧半侧面, 日光, 虚化的街道背景`；
* **不想让它学会的东西就不要写。** 凡是在说明中被点名的，模型都当作可变的部分并学着去控制
  它；凡是没有点名的，它就熔进适配器本身。由此得出常规的规则：角色恒定不变的外貌不写说明，
  而背景和衣着要写 — 否则适配器会把夹克和砖墙一起死死地学进去；
* **用逗号分隔的短列举来写**，而不是成段的文字：训练脚本会按长度截断说明，长句子会丢掉尾巴；
* **整个数据集用一种语言。** 说明里混用语言，是拿到一个时灵时不灵的适配器的可靠办法；
* **不要让说明留空**：空的 `.txt` 意味着「什么都没变」，训练会把整个画面连同背景一起熔进
  适配器。

画面编辑表单里的 **「名称」**字段是**对象**的名称，而不是文件名：文件已经用自己的名字躺在
项目文件夹里，不会被改名。而在添加时正相反，名称会成为文件名（后面会加上对象代号，免得不同
角色的文件重名）。

「修改」按钮只能改名称和说明。已经添加的画面无法重新裁切：为此要把它删掉，再从同一张原图重新
添加。「删除」按钮把画面从数据集里去掉，**项目文件夹里的文件本身会留下** — 它未必是从编辑器
进去的。

### 4.3. 画面的顺序有没有关系

简短的回答：**对训练本身来说没有，对挑选来说有。**

列表中的顺序就是**添加**的顺序（画面像对象一样编号：OBJ-12、OBJ-13、……），而它们也按同样的
顺序以 `001.png`、`002.png`、`003.png`…… 的名字进入数据集目录。在编辑器里没有办法给画面
重新排序：要让某个画面排到第一位，就得把它删掉再重新添加。

顺序真正重要的地方有两处：

1. **按上限截断。** 模型在配置档里规定了它取多少画面（`dataset.maxItems`；发行包中的
   Kandinsky 记录是 60）。如果画面更多，取的是**前面的** — 其余的会悄悄不参与。也就是说，
   最好、最有代表性的画面应该**更早**添加。
2. **文件的编号。** 之后您要靠 `001…NNN` 这个编号，把画面和在训练脚本日志里看到的内容对上。
   编号的顺序 = 添加的顺序。

顺序不重要的地方：训练过程本身要把数据集过很多遍并且会打乱它 — 「第一个」画面对结果的影响
并不比「最后一个」大。另外值得记住下限（`dataset.minItems`；Kandinsky 是 10）：少于它就会被
拒绝：「数据集中有 N 个画面，而这个模型的训练要求不少于 M 个」。

还有一条挑选规则：只有**已启用**的画面才进入训练。画面可以不删除而关掉 — 把它作为对象打开
（项目的「对象」选项卡）并去掉「已启用」的勾。这是把失败的视角从训练中扔出去而又不丢掉文件的
唯一办法。

## 5. 「模型」选项卡与启动训练

适配器是**针对某个具体的模型**训练的：各个模型的权重不一样，为一个模型训练出来的文件对另一个
不适用。因此，您要为多少个模型训练适配器，就有多少行训练。

训练永远是**按当前数据集**进行的 — 也就是在「数据集」选项卡上选中的那个。

1. 「+」按钮 — 选择模型。列表里是那些配置档中声明了 LoRA 相关功能的**已启用**名录记录；
   已经建了行的不会被第二次提供。列表为空只意味着一件事：这台服务器上没有合适的、已启用的
   记录。
2. 行里的 **「训练」**按钮 — 开始。训练**不会直接从这个表单里启动**：它会被安排成一个单独的
   **任务**。系统先问关于数据集的问题，然后建议选择一个**任务模板**，并询问接下来怎么办 ——
   「创建并运行」、「只创建」还是「取消」。详细顺序见下文。
3. 该行转入 **「训练中」**状态，而训练本身要跑好几个小时。表单可以关掉 — 训练不会因此中断；
   再打开它时，您会看到当前的状态（只要列表里还有正在训练的行，它就会每五秒自己重读一次）。
4. **行的状态是通往任务卡片的链接**，而且不只是「训练中」时如此：对一个跑挂了的训练，人过一
   天回来找的正是日志。停止也在那里：现在停止训练就等于停止任务。
5. 已经训练好的行要重新训练，会有一次确认询问：重新训练会**覆盖掉现成的**适配器文件，而它
   可能已经被填进模型里了，并且无法撤销。

行的状态：**未训练 → 训练中 → 已训练**，或者**出错**。出错时，提示里（把鼠标移到「出错」
这个词上）放着训练程序或提供商所说的话 — 没有这个，光一个「出错」毫无用处。

### 启动前系统会问什么

除了关于重新训练的确认之外还有两个 — 而且都是关于「否则训练就会悄悄做出您并不期待的事」。

* **「数据集不对」。** 训练行记得它里面那个文件是按哪个数据集得到的。如果现在选的是另一个，
  系统会把两个都说出来并问按哪个启动：「用当前的」还是「用原来的」。在另一批画面上训练出来的
  适配器，本质上是另一个角色，不能悄悄地把它换掉。
* **「设置比模型声明的大」。** 数据集的图片限制设置会与模型在名录中声明的值比对，而且只朝
  **偏大的方向**看：画面更大、更重、画面数更多 — 或者格式不是模型接受的那种。设置值**小于**
  声明值的数据集是合法的，不会问您。问题中会列出究竟是哪里对不上，而答案有**三个**：
  「训练」（就这样训）、「取消」和 **「创建/切换到所需的数据集」**。

这两个条件是**服务器**在检查，而不只是表单：训练也会从这个窗口之外被启动。

### 「创建/切换到所需的数据集」

这个按钮免去了「建一个数据集 — 把模型的设置抄进去 — 压缩几十张图片」这样的手工活。它是这么
做的：

1. **先在对象已经建好的数据集中找合适的**：设置要落在模型声明的范围内，而且里面躺着同样的
   那些画面（按不带扩展名的文件名比对）。找到了 — 它就直接成为当前的，什么也不压缩。
2. 没找到 — 就建立一个**新的**数据集，设置从模型填入，名称形如「角色 768×512 PNG」。它立刻
   成为当前的。
3. 原数据集的画面会被**压缩**进去。压缩的规则是：长宽比不变，而且**不能裁切图片** — 它按
   较长的一边缩小，放在画面的中央，剩下的留白用「设置 → LoRA 数据集画面 → 留白颜色」这个
   设置里的颜色填上（「#RRGGBBAA」，默认 `#FFFFFF00` — 全透明的白色：PNG 的留白是透明的，
   而 JPEG 根本没有透明通道，所以是白的）。系统不会把小的原图放大。
4. 之后训练就按新的数据集启动；关于数据集换了这件事不会问第二遍 — 这本来就是您的回答。

那些没能压缩成功的画面（文件不在、塞不进千字节上限）会用一条单独的消息说出来：由其余画面
组成的数据集仍然会照样生成。

### 训练以任务的形式进行：模板、控制台和日志

训练不是一分钟的活，在系统里它看起来就是一个普通任务：有执行者、有控制台、有日志、有历史、
有结果。它的执行者属于第三种类型 —— **「自动软件」**（见[执行者](performers.md)）：一对
「训练器插件 + 训练操作」。

按下「训练」之后依次发生的事：

1. **关于数据集的问题** —— 就是上面写的那些：它们问的是「用什么来训练」，因此排在最前面。
2. **系统查看能用什么、按哪个模板启动**：一次请求就问清楚有没有训练器插件、有没有「自动
   软件」执行者、有没有合适的任务模板。您看到什么取决于答案：

| 缺什么 | 表单会提议什么 |
|---|---|
| 完全没有训练器 | 用话说明拒绝：请到「设置 → 插件与 MCP」里安装程序 |
| 插件有，但没准备好 | 打开插件安装窗口，把程序补齐 |
| 没有执行者 | 从「插件与 MCP」的记录出发创建它 —— 一个按钮就行 |
| 没有任务模板 | 用这个执行者创建一个模板节点 —— 一个按钮就行 |
| 一切齐备 | 模板选择窗口和三个回答 |

3. **选择窗口**：任务模板，以及三个回答之一 —— **「创建并运行」**、**「只创建」**或
   **「取消」**。「只创建」适用于训练应当在夜里或在别的工作之后进行的情况：任务被创建下来，
   等待通常的启动。
4. **标题、描述、执行者和标签您在任何地方都不用写** —— 它们由模板节点连同它的经验一起带过
   来。要改就改模板，一次改完，对所有训练都生效。
5. 训练器插件由系统**按模型指明的训练软件包**来查找 —— 与安装模型时创建插件记录用的是同一
   条规则。操作它自己选：选那个标着「单实例」的（在训练器里那正是训练 —— 显卡只有一块）。

这种任务不需要、也不必有自己的参数字段：训练行记着自己的任务，而通过任务又能找到那一行 ——
行里已经有对象、数据集、模型和全部训练设置了。

**去哪里看进展。** 在任务卡片里：控制台实时显示训练器的输出，作业日志把它完整保存下来。此后
错误会同时出现在三个地方 —— 控制台里、作业产物里，以及训练行中「出错」一词的提示里。

**防止「同一件事做两遍」的守卫有两个，而且各管各的**：已经在训练的行，按钮当场就拒绝；
而针对训练器同一个操作的第二个任务，则在显卡忙碌期间于队列里**等待**。

### 行处于「训练中」时系统在做什么

1. **把数据集收集**到模型配置档所指定的目录中（Kandinsky 是从项目文件夹算起的
   `lora/<对象代号>/dataset`）。目录在收集之前会被**清空**：否则被撤下的画面还会继续参与
   训练。图片被复制成 `001.<ext>`、`002.<ext>`……，说明则是旁边同名的 `.txt`。取的是
   **启动时所依据的那个数据集**的画面；它的代号也可以替换进命令里 — `{datasetId}`。
2. **检查模型点名的训练用软件包**（`lora.train.packages`）— Kandinsky 是 `musubi-tuner`
   和 `python`。训练不负责安装它们：它们随模型的安装一同到来，那里有一个带进度的窗口。缺了
   什么，拒绝会在按下按钮的那一刻立即到来，并且写明该打开什么、该点什么。
3. **写入训练器的配置文件**（`lora.train.files`）到数据集旁边 — Kandinsky 是 `dataset.toml`
   和 `train.cmd`。它们在每次启动时都会被覆盖。
4. **启动**模型配置档中的训练命令（在一个单独的隐藏进程里），或者通过 HTTP 访问训练服务。
   命令和配置文件中会被替换的有：`{object}` — 对象代号，`{name}` — 它的名称，`{dataset}` —
   数据集目录，`{output}` — 结果目录，`{steps}` — 步数，`{width}`/`{height}` — 数据集设置
   里的画面尺寸，以及模型的安装路径：`{modelsRepo}`、`{groupDir}`、`{model:<文件>}` — 权重
   文件，`{package:<代号>:<文件>}` — 已安装软件包中的文件。**对象的描述不会被替换进去** —
   训练能看到的全部文字都在画面的说明里。
5. **等待**工作结束。超过配置档中的期限（默认 720 分钟，也就是 12 小时）就不再等：卡住的
   训练总得在某个时候变成错误，而不是永远停在「训练中」。返回码非零同样是错误，输出的最后
   几行会进入它的文本。
6. **取走适配器文件**并把它放进模型仓库 — 也就是引擎自己去取它的地方（ComfyUI 是 `loras`
   子目录，默认的名字是 `<对象代号>.safetensors`）。
7. **给对象填上**这个文件的路径和「就绪」状态 — 也就是说，从这一刻起适配器会自己挂载到模型上。

第 4–7 步是**在任务的作业内部**进行的：训练器的输出被不间断地读取，进入卡片的控制台，而不是
积在管道里。等待上限有两个 —— 总的上限（默认 720 分钟）和**沉默超时**（默认 30 分钟：读取
文本编码器权重就可能花这么久）。超过这个时长一行都没说的程序会被认为卡死并被结束 —— 十二个
小时的沉默，在任何设置下都不会再出现了。

## 6. 哪个字段去了哪里

| 字段 | 在哪里填写 | 去了哪里 |
|---|---|---|
| 适配器的「描述」（也就是「档案」） | 编辑器表单、对象表单 | 进入**生成的提示词**，替换 `@obj:` 引用 — **不会**进入训练 |
| 「画面描述」 | 数据集画面的表单 | 进入**训练**：图片旁边的 `NNN.txt` 文件（或共同的 `captions.json`） |
| 适配器对象的「名称」 | 对象表单 | 训练命令中的 `{name}` 替换；`@obj:[名称]` 引用 |
| 对象代号（OBJ-N） | 自动分配 | `{object}` 替换：数据集目录、适配器文件名 |
| 画面的「名称」 | 画面表单 | 项目文件夹中的文件名（在添加时）以及画面对象的名称 |
| 「适配器文件」和「适配器状态」 | 对象表单 | 生成时把适配器挂载到模型上；训练成功后它们会自动填好 |

## 7. 训练好的适配器如何进入生成

没有单独的「挂载适配器」这个动作。起作用的是引用的规则：在媒体任务的描述里放一个对象引用
（`@obj:OBJ-7` 或 `@obj:[名称]`），启动作业之前系统就会决定什么会进入模型：

* 指向**「LoRA 适配器」类型对象**的引用 — 适配器是**必需的**：模型必须能接受它，而它本身
  必须已经训练好。否则作业会以错误告终；
* 指向**任何带现成适配器的对象**的引用（角色的「适配器文件」已填写）— 适配器会挂载：人训练
  它就是为了这个；
* 适配器**还在处理中**（「已计划」、「训练中」）— 只在作业控制台里给一条提示：画面按档案来做；
* 没有适配器的角色、场景、风格 — 和从前一样：档案进提示词，子对象的参考帧成为起始帧的候选。

把它做成错误是有意的：一个悄悄地在没有适配器的情况下生成出来的画面看上去很正常，会作为完成的
结果交出去 — 而上面的角色是别人。

## 8. 常见错误

| 消息 | 发生了什么、该怎么办 |
|---|---|
| 「项目在本服务器上没有文件夹」 | 项目在**进行训练的那台服务器上**没有设置文件夹；文件夹是按服务器各自独立的，在项目卡片里设置 |
| 「模型名录中没有说明用什么训练」 | 模型配置档中的训练命令是空的 — 请把它填上（配置档里有指向说明的链接） |
| 「模型 …… 的适配器在系统外训练」 | 这条记录的训练是外部的：请用自己的手段训练，并把文件路径填进「适配器文件」字段 |
| 「数据集中有 N 个画面，而训练要求不少于 M 个」 | 请添加画面：发行包中 Kandinsky 记录的下限是 10 |
| 「项目文件夹中没有该画面的文件」 | 画面的文件被绕过 AI2P 删掉或改名了 — 请删掉这个画面并重新添加 |
| 「画面大小为 N KB / 画面为 N×M 像素」 | 这个数据集的上限小于送来的图片；请缩小方框，或者在「数据集图片的限制」里把上限提高 |
| 「未找到数据集，或者它属于另一个对象」 | 所选的数据集被删掉了，或者它是别人的：请重新选择数据集 |
| 「上一次是按数据集 …… 训练的」 | 数据集自上次训练以来变了 — 请回答按哪个启动 |
| 「数据集的设置比模型声明的大」 | 与名录的比对发现了超出或者不认识的格式：可以照样训练、点「创建/切换到所需的数据集」，或者从模型填入设置并手工重新收集画面 |
| 「数据集的画面只能是图像」 | 指定的路径下放着的不是图片 |
| 「训练在 N 分钟内没有结束，已被中断」 | 配置档里的期限不够 — 请提高 `wait.timeoutMinutes`，或者减少步数 |
| 「训练以代码 N 结束」 | 训练程序本身倒下了；它最后几行输出在「出错」这个词的提示里 |
| 「训练没有留下适配器文件」 | 命令跑完了，但 `result.path` 路径下没有文件：请把配置档里的路径与您的脚本实际放结果的地方核对一下 |
| 「训练在 N 分钟内一行都没有打印」 | 沉默超时被触发：程序卡住了。请看任务控制台和作业日志里的最后几行；时长由模型配置档中的 `wait.idleMinutes` 设定 |

## 9. 编辑器不做什么

这个版本的限制清单，如实列出 — 免得您去找不存在的东西：

* **画面的顺序不能改** — 只能靠删除再重新添加；
* **已添加的画面不能重新裁切** — 裁剪框只在添加时可用；
* **不能从编辑器里关掉画面** — 「已启用」的勾住在画面对象的表单里，而被关掉的画面在编辑器的
  列表中没有任何标记（不过它确实不会进入训练）；
* **把数据集发给提供商**（把画面打包上云训练）没有做：训练是用自己的进程，或者通过 HTTP 访问
  自己的训练服务；
* **画面不能用按钮在数据集之间搬** — 数据集就是普通的对象，画面要在「对象」选项卡的「层级」
  视图里拖动搬运；
* **改动限制设置并不会重做已经添加的画面** — 新的上限对下一个画面才生效；
* **没有按百分比显示的训练进度** — 有的是行的状态、错误文本，以及任务卡片控制台里训练程序
  本身的实时输出（完整的作业日志也在那里）；
* **同时用好几个适配器**模型通常是不接受的（`apply.maxCount`，发行包中的记录是 1）：如果
  任务描述里点了不止一个带适配器的对象，作业会以错误回应，而不是悄悄取第一个。
