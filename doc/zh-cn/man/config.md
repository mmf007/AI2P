# 设置

AI2P 的设置分放在两个地方，这不是疏忽，而是规矩。

* **「设置」界面** —— 属于**组织**和**这台计算机**的东西：语言、名录、AI 模型、安全规则、用户、
  服务器、通知。
* **文件 `config.json`** —— 决定程序**能否启动**的东西：端口、地址、目录、邮件。它是在系统之外修改
  的，用于进不了系统的时候：比如端口被占用，服务器起不来。

凡是在界面上改的，都会落到同一个 `config.json` 里 —— 但反过来不成立：有一部分参数是故意没有显示在
界面上的（见 [第 3 节](#3-只能在-configjson-中修改的内容)）。

---

## 1. 如何打开

左侧竖条（竖排动作栏）最下方的齿轮图标，在文档按钮下面。同样的「设置」也在菜单 **AI2P → 视图** 里，
以及资源浏览器的最后一行。这个界面没有自己的地址 —— 按链接是打不开的。

设置是作为**工作区标签页**打开的，就像任务或项目一样：可以让它和工作内容并排开着，来回切换。

谁能看到什么：组织的各个部分（名录、动作、安全、用户）由**所有者**或**管理员**修改，而服务器自身
的表单则需要单独的**服务器管理员本地登录**（右上角的用户按钮 →「服务器管理员本地登录」）。它是
真正意义上的本地：只接受来自这台计算机的登录。

## 2. 各个选项卡

### 基本

本次安装和本组织的设置：

| 是什么 | 特点 |
|---|---|
| **界面语言** | 同时改变界面和**系统消息的语言**；不影响智能体接收作业时所用的语言 —— 那是给团队设定的（见 [团队](teams.md)） |
| **UI/API 端口** | **重启后**生效 —— 进程已经在监听原来的端口 |
| **启动时打开浏览器** | 在操作系统服务下不起作用：服务没有桌面 |
| **标签页第二行** | 在「任务」/「项目」字样下面写什么 —— 名称的开头还是短代号（`T-17`、`PRJ-2`） |
| **日志输出级别** | Debug / Info / Warning；**立即**生效，对技术日志和工作日志都有效 |
| **计划日历单元格** | 时间 + 模板代号，或者时间 + 标题开头 |
| **模型仓库**、**安装包目录**、**软件包安装目录** | **这台计算机**的目录；由服务器管理员修改 |
| **LoRA 数据集画面** | 把图片压到什么尺寸以内，以及用什么填充留白 |
| **应用版本**、**启动方式** | 只读：构建号，以及服务器是用控制台还是操作系统服务起来的 |

这三个硬件相关的目录要马上弄明白，否则它们看起来很神秘。它们的默认值是**相对的**（`./models`、
`./distribs`、`./packages`），并且是**从程序目录的上一级**算起的：AI2P 在 `C:\ai\AI2P` → 模型权重
在 `C:\ai\models`，软件包在 `C:\ai\packages`。这是特意这么做的：本地模型的权重是几十 GB，不能把它们
放进重装时会被清掉的程序目录里。表单会显示实际得到的路径（「当前：…」）—— 相对值本身说明不了任何
问题。安装包目录留空表示「临时目录」，软件包目录留空表示「`<模型仓库>/packages`」。

### 模型

**AI 模型**名录 —— AI 执行者归根到底是由什么做出来的。一条记录 = 某个提供方的一个模型：名称、
提供方、API 地址、密钥引用、价格、技能、参数配置档以及 LoRA 训练设置。

在东西还没出毛病之前就值得了解的几个特点：

* **没有 API 密钥的云端模型不能处于启用状态，没有下载文件的本地模型也一样。** 这条规则消除了一整类
  莫名其妙的拒绝 ——「模型明明有，作业却跑不起来」。密钥用模型那一行的钥匙按钮输入，文件用「安装」
  按钮下载。
* 行里的**「i」**按钮会打开模型文档：能做什么、接入需要什么、多少钱。完整列表见
  [AI 模型](../models/README.md)。
* **登录 Claude CLI** —— 列表上方的一个单独按钮。「订阅制」模型（`*_cli`）不需要密钥，但需要已经
  完成登录；登录过期时，作业不会以错误告终，而是进入「等待登录」的暂停 —— 而这就在这里治。
* 本地模型是**在具体某台服务器上启用**的：它实际躺在某一台计算机上。这种模型的执行者也绑定在同一台
  服务器上。

### 名录

其余一切东西赖以组装的小列表：**技能**（skills）、**任务状态**、**团队中的角色**、
**输入输出格式**、**导入源类型**、**默认归档规则**。记录分为**内置的**（随安装包而来，不能删除）
和**自定义的**。

技能是这里最重要的东西：执行者自动挑选就是靠它们工作的。创建自己的技能时，请确认它已经在某个人的
能力声明里声明过，否则带这个技能的任务永远也找不到执行者。

### 动作

一份名录，规定 AI 智能体可以借系统之手做些什么：读写项目文件、读取相邻作业、创建子任务、向人提问、
写经验、修改模板、移动任务等等。

这个选项卡最重要的一点：**提示词就放在这里** —— 也就是向智能体描述工具的那些文本。它们不在代码里。
内置动作只能修改提示词，而且改动可以用按钮回退到出厂文本；自定义动作可以整体修改。文本以多种语言
维护，并按团队的语言代入。

动作代号（`AI2P.Files.Write`、`AI2P.Tasks.Create`、…）是分层的，用点分隔。安全规则操作的正是它们，
所以在写规则之前值得先来这里看一眼。

### 安全

「智能体可以做什么」的规则：对某个动作（或者一整支动作分支）在某个范围内 —— 整个组织、项目、任务 ——
**允许 / 再问一次 / 禁止**。「再问一次」规则意味着，在调用之前系统会向任务负责人征求确认。

有一个细节能省下好几个小时的排查：只有当工具**在动作名录中有记录**时，规则才会挡住这个动作。名录里
根本没有的工具，规则完全管不着。

除了动作之外，规则还有**「插件与 MCP」**这一类：它回答的不是「做什么」，而是「允许使用哪些
插件」—— 样式为 `trainer.musubi` 或 `trainer.musubi:lora.train`，操作为「使用」（智能体调用
插件的工具）和「运行」（「自动软件」任务启动程序）。**默认全部允许**，禁止要显式建立。详情
见[插件与 MCP](plugins.md)。

### 用户

登录账户及其角色：`owner`（整个组织的所有者）、`admin`（集群中一台计算机的主人）、`project_admin`、
`editor`、`reader`。账户是用来登录的；人**干活**靠的不是账户，而是引用这个账户的执行者
（见 [执行者](performers.md)）。

### 组织

本服务器上的组织列表以及它们之间的切换。组织是一个独立的数据库、独立的目录、独立的名录，以及自己的
加密密钥。**归档**也住在这里：它们以组织记录的子行形式显示（见 [归档](Archives.md)）。

### 服务器

自己的服务器、集群里的邻居以及接入申请。**本地服务器表单**就是服务器自身的设置：地址、端口、
第二个（对外的）地址、监听的网络接口、这台计算机的目录、服务器管理员密码。只有服务器管理员能修改
它们，其他人只能只读查看；**地址和端口在重启后生效**。选择了协议 `https` —— 下面就会出现
**「HTTPS 证书」**一节（见 [HTTPS](https.md)）。详情见 [多台服务器](servers.md)。

### 通知

「什么事要通知人」的规则：任务转入某状态、任务需要检查、期限临近。列表上方是**邮件服务器**设置
（这是计算机的设置，不是组织的设置）和**试发邮件**按钮：没有它，「配好了就等着」就会变成「等着，
但不知道到底行不行」。

规则里执行者列表或项目列表为空，意味着**「全部」**，而不是「一个都不」。

### 通用经验

对组织的**所有**项目都起作用的经验记录 —— 也就是会代入到智能体每一份作业里的通用工作规则。具体项目
的经验住在项目卡片里，模板节点的经验住在模板里（见 [项目](progects.md)、[模板](templates.md)）。

## 3. 只能在 `config.json` 中修改的内容

这个文件和安装的工作文件（`data/`、`logs/`、`secrets/`）放在一起 —— 具体在哪里，
[安装](install.md) 里有说明。修改之前必须**停止**程序：它自己也在往这个文件里写。

```json
{
  "ui": {
    "protocol": "http",
    "port": 5480,
    "basePath": "/ai2p",
    "hostname": "localhost",
    "hostname2": "",
    "port2": null,
    "bindAddress": "0.0.0.0",
    "https": {
      "source": "file",
      "certFile": "",
      "keyFile": "",
      "passwordRef": "https.certPassword",
      "storeLocation": "CurrentUser",
      "storeName": "My",
      "subject": "",
      "thumbprint": "",
      "trustAnyPeer": true
    },
    "openBrowserOnStart": true
  },
  "storage": {
    "dataDir": "./data",
    "dbFile": "ai2p.db",
    "distDir": "./distribs",
    "packagesDir": "./packages",
    "docDir": "",
    "modelsRepo": "./models",
    "serverDbFile": "server.db"
  },
  "logging": { "level": "Warning", "dir": "./logs", "rotation": "day" },
  "language": "ru",
  "serviceMode": false
}
```

这是文件**随安装包而来时的样子**。随着时间推移，里面的小节会增多：邮件（`mail`）会在「通知」选项卡
上配置好之后出现 —— 不需要手工去建它。

这里有哪些重要的、界面上又没有的东西：

* **`basePath`** —— 端口之后的地址前缀（`/ai2p`）。所有指向任务的链接都取决于它；把 AI2P 装在公共
  反向代理后面时才会改它。
* **`bindAddress`** —— 监听哪个网络接口。`0.0.0.0` —— 全部（集群就是这么工作的），`127.0.0.1` ——
  只有这台计算机。对单机安装来说后者更安全。
* **`hostname2` / `port2`** —— 服务器**第二个、对外的**地址：公网名称或做了端口转发的路由器地址。
  留空 —— 没有第二个地址。
* **`https`** —— 服务器证书：它连同 `protocol: "https"` 就是切换到 HTTPS 的全部内容。也可以在界面上
  改 —— 在本地服务器表单里，一旦选了协议 `https`，这一节就会出现。详情（证书从哪里来、怎么在浏览器
  里放行它、集群该怎么办）见 [HTTPS](https.md)。
* **`dataDir`、`logging.dir`** —— 相对路径是**相对 `config.json`** 算的，而 `~/…` 是相对主目录算的。
  路径按输入时的样子保存：文件仍然是可移植的。
* **`docDir`** —— 文档目录；留空（通常情况）—— 程序会自己找到它。填了不存在的路径 —— 文档就不显示，
  界面会直说这一点。
* **`serviceMode`** —— 标记「本次安装以操作系统服务方式运行」；它由 `makeAsServise` 写入，由安装程序
  读取，以便在更新期间停止服务。

三条值得事先知道的规则：

1. **`config.json` 里永远没有密钥。** API 密钥以加密形式存放在组织的数据库里，组织密钥和服务器管理员
   账户存放在 `secrets.json` 里，而邮件密码存放在 `secrets/mail.password.json` 里。配置里留下的只有
   **引用**（`mail.passwordRef`）。子目录 `secrets/` 既不参与复制，也不进部署包，也不进更新；它里面
   放着一个 `readme.txt`，用安装语言作了说明。
2. **目录在启动时会按平台归一。** 从 Windows 带到 Linux 的配置，不会在系统里留下路径 `C:\ai`：不属于
   本平台的路径会被换成默认值，而这次改动会在控制台以一行文字说明。形如 `~/ai` 的路径永远不算外来
   路径。
3. **版本更新不会丢掉您的取值。** 旁边会放一个带有新默认值的 `config.new.json`，首次启动时两个文件
   会合并（新的底子 + 您的取值），而被采用的文件会留下一份副本 `config.new.json.applied`。
