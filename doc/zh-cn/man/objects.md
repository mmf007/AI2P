# 项目对象

**对象就是任务所引用的东西：**短片中的角色、场景、道具、风格、参考帧、LoRA 适配器。每个项目
都有自己的对象列表；组织没有全局的对象列表，这是有意为之 — 对象属于项目。

列表由项目卡片的**「对象」**选项卡打开。点击某一行会打开**「对象」标签页** — 一张带选项卡的
卡片，和任务的卡片一样。

---

## 它们为什么有用

用媒体短片里的固定角色最容易解释。如果在每个画面里都用自己的话描述主角的外貌，他就会在镜头
之间「走样」 — **复述本身就是原因**。

因此对象有一份**档案** — 用于提示词的原文 — 还有参考文件，而在任务描述里放的是**引用
`@obj:OBJ-3`**。**每一次**启动作业时，该引用都会展开成档案和文件路径：改了档案 — 下一个画面
就会用上这次修改，不必重写任务。

关于引用的三条规则，能省不少时间：

* **两种**形式都能读 — `@obj:OBJ-3` 和 `@obj:[瓦夏主角]`；界面按钮往剪贴板里放哪一种，由项目
  设置「对象引用的格式」决定；
* 未知的引用会原样留在文本里，并且引用**够不到别的项目的对象**；
* 档案内部的引用不会展开 — 没有嵌套。

## 对象的种类

| 种类 | 用途 |
|---|---|
| **角色** | 短片的主角；外貌放在档案和参考帧里 |
| **场景** | 情节发生的地点 |
| **道具** | 画面里的物件 |
| **风格** | 画法、外观上的限制 |
| **参考帧** | 样板图片；通常是角色或场景的子对象 |
| **参考音频** | 语音或声音样本：连接器像传递参考帧一样把它的文件传给模型 |
| **数据集** | 带说明文字的画面文件夹，用于训练适配器；画面是它的子对象 |
| **LoRA 适配器** | 训练出来的、附加到模型权重上的小文件（[LoRA 编辑器](LoRAEditor.md)） |
| **文件** | 任务所引用的文件 |
| **设备** | 与工作相关的硬件 |
| **媒体资源** | 拍摄的镜头、音轨、字幕、剪辑工程文件：项目媒体库就是按此类型筛选出的对象 |

## 对象列表

**四种视图**：表格（带方形预览）、表格（简略）、层级、标签；所选视图按项目记住。还有按类型和
按标签的筛选，以及搜索。

* **层级用的是与任务树相同的引擎**，因此其中的鼠标和手指拖动、边缘自动滚动和**「移到根」**的
  粘性条都能用；
* **没有自己图片**的对象（角色、场景、风格），预览取自更深处的子对象 — 外貌放在参考帧里；
* 筛选挑选的是**行**，而不是行所显示的内容：「只看角色」的筛选不会让角色失去脸；
* 行尾有「修改」（铅笔）和「删除」按钮：虽然点击整行会打开标签页，从列表里修改仍然只要一个
  动作；
* **对象有自己的一组标签**，与任务标签分开。

## 对象标签页

对象**在标签页里阅读**，而创建和修改仍在窗口表单里进行。

* **表头**和任务卡片的一样：带项目名称的标牌、代号 `OBJ-N` 和名称；下面是对象的种类、「未启用」
  标记和适配器状态。
* **标签页的标题**是「对象」加上代号或名称的开头；它由与任务和项目**同一个**设置计算（设置 →
  基本，三者共用一个设置）。
* **工具栏**是一排图标：修改（打开窗口表单）、更换服务器、引用、LoRA 设置（仅适配器有）、
  「将进入模型的内容」、删除、刷新。每一个都与表单内部的按钮是同一个动作。
* **有两个选项卡**：「基本」（同样的字段，只读，档案按 Markdown 渲染）和**「子对象」** — 带
  预览的子对象列表，行尾是「修改」和「删除」，点击会打开新的标签页，「添加」按钮则直接在已打开
  的对象内部创建对象。

## 对象表单

名称、种类、父对象（「所属对象」）、标签、参考文件、档案、「启用」，而「LoRA 适配器」种类的
对象还有适配器区块和**「LoRA 设置」**按钮（[LoRA 编辑器](LoRAEditor.md)）。

文件对话框的按钮**只在项目文件夹内部**活动，并返回相对于它的路径。对象名称在项目范围内唯一。

### 两个引用 — 它们是两回事

表单在两个字段里给出**两个**引用：

* **`@obj:OBJ-3`** — 用来插入任务描述；启动作业时会展开成档案；
* **标签页地址** `…/object/{id}` — 用于外部链接。对象是按自己的 uuid 寻址的，所以这种链接能
  **跨项目**使用，并且不会改变当前项目。地址和任务一样有两个 — 本机的和外部的。

### 「将进入模型的内容」

这个按钮会完整显示展开结果 — 正是生成会收到的东西。**LoRA 适配器**的数据有两份，而且并不相同，
所以窗口里有两个字段：

* **「使用时」** — 带文件路径的档案；这份会进入提示词；
* **「训练时」** — 当前数据集的画面及其说明文字，正是训练器将收到的内容。没有说明文字的画面
  会显示为空行 — 在开始耗时数小时的计算之前就能看到。

普通对象没有第二个字段。

## 对象的宿主服务器

在集群里，对象和任务一样有且只有**一台宿主服务器**：在它上面修改对象，也在它上面训练该对象的
LoRA 适配器。卡片上有「所属服务器的对象 …」标牌，工具栏里有**「更换服务器」**按钮（只有当组织
中的服务器多于一台时，标牌和按钮才会出现）。

* **在别的服务器上对象是只读的**：修改、删除、LoRA 设置、创建子对象、列表行上的按钮以及树里的
  拖动手柄都被禁用；
* 对象会**连同整棵子树一起迁移** — 子对象、数据集和画面：它们都是对象的内容；
* 更换服务器时**编号不变**，而新对象的编号带上服务器代号（`OBJ-5-S1`；指挥服务器上没有后缀）
  — 否则两台服务器会各自建出一个 `OBJ-5`，引用 `@obj:OBJ-5` 就会指向不同的东西；
* 新对象会自己得到服务器：子对象取父对象的服务器，顶层对象取本服务器；
* 从旧版本的伙伴那里传来的、没有服务器的对象，由指挥服务器在打开组织时接管。

**训练好的适配器会传给邻居。** 完成的 LoRA 文件会有一份副本放进组织的数据目录，而该目录是整体
复制的；在接收方服务器上，这个文件会被自动找到，并在生成之前放入该服务器自己的模型仓库。也就是
说，「在一台服务器上训练、在另一台上使用」无需手工复制即可工作。更新之前训练好的适配器不会被
搬运：副本只会出现在更新之后训练的适配器上。

关于行的归属和复制的更多内容 — [多台服务器](servers.md)。
