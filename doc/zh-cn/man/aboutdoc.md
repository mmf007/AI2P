# AI2P 的文档是怎样组织的

这一页讲的是文档本身：它放在哪里、由什么组成、如何往里面添加新文档，以及如何让各语言保持
一致。文档清单请见[目录](../index.md)。

## 放在哪里，以及哪些内容随发行包提供

目录位于 `AI2P_app/doc/` — 和代码放在一起，因为它是**随程序一同提供的**：构建部署包时会把
`AI2P_app/doc` 整个复制到发行版的根目录，而应用直接从界面里显示这些文档。所有语言的布局都
相同（`doc/<语言>/<小节>/…`）。

**每种语言有两个首页，而且这不是重复：**

* **`index.md` — 目录。**「文档」按钮正是指向它：阅读要从页面清单开始。目录是**手写**的，
  并按含义分组（管理员手册、用户手册、示例），因此目录生成脚本不会去动它。发行包里有的所有
  文档，都能从这里通过链接到达。
* **`README.md` — 系统的简要说明。** 就是人在 GitHub 上最先看到的东西：这是什么、有什么用、
  接下来该去哪儿。对于还没有建立 `index.md` 的语言，它同样是入口点 — 文档按钮会自动回落
  到它。

语言清单在 `AI2P_app/readme.md` 中 — 它是语言调度页，除了图标、名称和链接列表之外，里面
什么都没有。

图片放在 `doc/images/`（所有语言共用）和 `doc/<语言>/images/`（与语言相关的 — 带文字的
屏幕截图）。一个连一个 `.md` 都没有的目录不算作语言 — 既不要求为它做目录，也不要求翻译。

项目文档（技术规格、研究报告、部署流程）不在这里 — 它们放在仓库根目录的 `doc/` 中，不进入
发行包。

## 小节是怎样组织的

小节就是语言目录里的一个子目录。每个小节都有**自己的 `README.md`** — 它是该小节的目录：
列出小节的所有文档，并说明这个小节的共同之处。

目前有三个小节：

* `man/` — [用户手册](README.md)：按章节组织的连续正文，文件名任意；
* `models/` — [AI 模型名录中每条记录一个文档](../models/README.md)；
* `import/` — [每种任务来源一个文档](../import/README.md)。

文档的文件名由应用**自己算出**：模型的文件名是名录中的模型名称，导入的则是来源种类的代号。
名称按原样取用，文件名中不允许的字符替换成 `_`。如果某个文档在任何语言下都不存在，「i」
按钮会打开一条提示，里面写着应该把它放到哪个完整路径下。

## 如何添加文档

1. 放一个文件 `<小节>/<名称>.md` — 名称按该小节的规则来（见它的 `README.md`）。
2. **手工**把它写进语言的目录（`index.md`）— 那里的文档是按含义分组的，脚本猜不出该放哪一组。
   至于**小节**的目录，它会自动进去：小节目录由脚本 `test/t18s1/mktoc.py` 按目录的实际内容
   生成；`python test/t18s1/mktoc.py --check` 会显示它们是否与文件对不上。
3. 引用相邻文档时用**相对**链接（`models/GLM-5.2.md`、`../import/trello.md`）— 文档窗口能
   解析它们。在用**「i」**按钮打开的文档（模型、导入）中，外部地址请写完整，带上 `https://`
   协议。

目录文件在所有目录中都叫 `README.md` — 名称的大小写不需要改。

## 新章节放在哪里

新章节是一个独立的文件 `man/<名称>.md`。请把它写进[语言目录](../index.md)（它是手写的，按
含义分组），而在这里，也就是小节目录中，它会自动出现 — 这份清单是脚本生成的。同时请在
`../../en/man/` 中建立**同名的翻译**：各语言的内容必须一个文件对一个文件地对上。

有一条值得遵守的规则：手册里的数字、字段名称和按钮标题会悄无声息地过时。核对它们不要凭
记忆，而要照着界面词典（`i18n/ru.json`）和代码来 — 例如模型名录的选项卡叫**「模型」**，
而不是「AI 模型」。

## 翻译

其他语言的文档放在相邻的目录里（`doc/en/…`），并且一比一地重复同样的布局：`ru` 里有多少个
文件，`en` 里就有多少个。这一点由脚本 `test/t18s1/cmp.py` 核对 — 它会打印出哪种语言缺了
什么。

如果某个文档在界面语言下不存在，应用会显示俄语版本；如果连它也没有 — 则显示英语版本。
