# 在 VS Code 中使用 AI2P

AI2P 可以在 VS Code 内工作：项目卡片、工作环境、设置、文档和任务卡片会以编辑器面板的形式
打开，紧挨着项目代码。界面与浏览器中的 AI2P 相同，只是没有顶部菜单、标签栏、左侧工具栏和
导航器；浅色或深色主题取自 VS Code。

这一切通过 VS Code 的 **AI2P** 扩展实现。扩展随 AI2P 一起提供（程序目录中的
`ai2p-<版本>.vsix` 文件），其版本始终与 AI2P 版本一致，并由 AI2P 自行安装——无需从
Marketplace 下载任何内容。

## 前提条件

* AI2P 与 VS Code 在**同一台计算机**上：面板通过 `http://localhost` 访问服务器。
* 项目在本服务器上设置了**项目目录**。每台服务器的目录各不相同：
  如果本服务器上没有该目录，就无法在此将 VS Code 连接到项目，也不会显示连接按钮。
* VS Code 以常规方式安装（见「限制」）。

## 连接项目

1. 在 AI2P 中打开项目卡片的 **「设置」** 标签，进入编辑模式。
2. 点击 **「连接 VS Code」**。如果计算机上有多个 VS Code 副本，会先弹出选择窗口。所选副本
   **仅在本服务器上**为该项目记住，不会同步到集群中的其他服务器——不同项目可以使用不同副本。
3. 随后 AI2P 会：
   * 在所选 VS Code 中安装或更新扩展；
   * 在项目目录中创建 `.ai2p/link.json`：服务器地址、组织代码、项目和服务器路径。
     **该文件不包含任何机密**；
   * 签发**设备令牌**，并通过 `vscode://ai2p.ai2p/link` 链接交给 VS Code。VS Code 会询问是否
     允许扩展打开该链接——请允许。令牌保存在 VS Code 的安全存储（SecretStorage）中，而不是
     项目文件里；
     链接使用所选副本的协议（`vscode-insiders://`、`vscodium://`、`cursor://`、`windsurf://`），
     因此令牌会准确送达该副本；
   * 根据连接窗口中的复选框（把 `.ai2p/` 加入 `.gitignore`、在 VS Code 中打开项目）更新
     `.gitignore` 并打开项目目录。

创建项目时也可以直接连接：如果找到了 VS Code 且目录已设置，新建项目表单中会有「连接 VS Code」
复选框。

扩展**只会**在含有 `.ai2p/link.json` 的文件夹中启用；在其他项目中它不可见。

## 首次打开文件夹：「Trust Folder」

VS Code **首次**打开项目文件夹时，会询问您是否信任其作者（窗口 **「Do you trust the authors of
the files in this folder?」**，按钮 **「Yes, I trust the authors」** / **「Trust Folder」** 和 **「No, I
don't trust the authors」**）。在文件夹被信任之前，VS Code 以受限模式（Restricted Mode）打开它，
扩展在其中无法完全工作。

因此，在第一次连接时，AI2P 传给 VS Code 的带令牌链接**会丢失**：在您阅读信任窗口期间，扩展还无法
接收它，AI2P 面板不会打开。处理方法（**只需一次**）：

1. 在信任窗口中点击 **「Yes, I trust the authors」**（**「Trust Folder」**）。
2. **关闭**该 VS Code 窗口（或关闭文件夹：**File → Close Folder**）。
3. 在 AI2P 中再次点击 **「在 VS Code 中打开项目」**（或 **「连接 VS Code」**）。

现在该文件夹已受信任，VS Code 不再询问，链接能够送达，项目会立即打开。同一文件夹无需重复此操作，
只有每个新的项目文件夹才需要。

## 菜单与面板

左侧 Activity Bar 中会出现 **AI2P** 图标，其菜单有四项：

| 菜单项 | 打开内容 |
|---|---|
| **项目** | 项目卡片 |
| **环境** | 工作环境和归档（仅在有归档时显示） |
| **设置** | AI2P 设置 |
| **文档** | 本文档 |

同样的操作也在命令面板（`Ctrl+Shift+P`）中，前缀为 **「AI2P:」**：「AI2P: 项目」、
「AI2P: 环境」、「AI2P: 设置」、「AI2P: 文档」、「AI2P: 打开任务…」、「AI2P: 从 AI2P 连接项目」、
「AI2P: 断开 VS Code」、「AI2P: 启动服务器」、「AI2P: 检查扩展更新」。这些文字已翻译为 AI2P 的
五种语言，并跟随 VS Code 的语言。

每个菜单项只打开一个面板：再次选择会把已打开的面板调到前面。在任意面板（树、看板、表格、
图表、Inbox、文本中的链接）中选中的**任务**会在旁边的**独立面板**中以单个任务卡片打开。
VS Code 重启后会恢复已打开的面板。

**主题。** 浅色或深色主题取自 VS Code，切换编辑器主题时所有已打开面板会即时变化。这不会改变
您在浏览器中的 AI2P 主题。

**语言。** 如果 VS Code 的语言是 AI2P 支持的语言之一（俄语、英语、西班牙语、葡萄牙语、中文），
面板使用该语言；否则使用 AI2P 安装时的语言。

## AI2P 服务器

如果服务器未运行，扩展会在打开第一个面板时自动启动它——每台计算机只启动一次，即使打开了多个
VS Code 窗口。服务器独立于 VS Code 运行：关闭编辑器不会停止服务器。

服务器重启后，面板会自行等待并重新加载，无需任何操作。

## 登录与撤销令牌

面板中没有登录表单：VS Code 使用连接时签发的**设备令牌**登录，身份和权限都是点击「连接 VS Code」
的那个人。令牌只在本服务器上有效。

您的令牌可在 AI2P 中查看：**设置 →「通知」→「我的设备（VS Code）」**——设备、项目、签发日期和
最后登录时间。**「撤销」**会关闭访问：下一次请求时面板会显示「需要连接 VS Code」。每个人只能看到
并撤销自己的令牌。

## 断开连接

在项目的「设置」标签中点击 **「断开 VS Code」**：AI2P 会删除 `.ai2p/link.json`，并撤销您在该项目
的所有令牌。扩展本身会保留——它由所有项目共用。

命令面板中的 **「AI2P: 断开 VS Code」** 只会删除本机上的令牌；如需在服务器端也关闭它，请在
「我的设备」中撤销令牌。

## 更新扩展

扩展随 AI2P 一起更新：

* 服务器启动时会检查所有已记住的 VS Code 副本中的扩展版本，如果落后则在后台安装新版本；
* 扩展本身在启动时会将自己的版本与服务器版本比较，如果落后则提示 **「更新」**；更新后 VS Code
  会要求重新加载窗口（Reload Window）。

手动检查：「AI2P: 检查扩展更新」。

## 限制

* **仅限 localhost 的 HTTP。** VS Code 面板不接受自签名证书，因此即使服务器启用了 HTTPS，嵌入
  模式也使用 `http://localhost`。无法将 VS Code 连接到另一台计算机上的服务器。
* **VS Code 衍生版**（VS Code Insiders、VSCodium、Cursor、Windsurf）可以被发现和选择，但只测试
  过普通 VS Code。
* **macOS 和 Linux。** 扩展已在 Windows、macOS 和 Linux 上测试通过。
* 如果计算机进入睡眠或网络中断而服务器没有停止，面板显示重新连接窗口的时间可能比平时长；
  请关闭并重新打开该面板。
* 面板内无法使用登录窗口和需要常规登录的表单：只能通过令牌登录。
