
# 按角色参考帧制作视频短片。示例

**本章的任务：**项目文件夹里放着一张角色的图片，需要让媒体模型用它做出一段短片 — 而且在
下一段短片里角色看上去还是一样的。

我们以本地模型 **`Kandinsky-5.0-I2V-Lite-5s`**（图片 + 文本 → 视频，5 秒）为例来讲。下面的
一切对任何「图片 → 视频」模式的模型都成立；而对「文本 → 视频」模型
（`Kandinsky-5.0-T2V-Lite-sft-5s`）起始帧无处可传 — 它只会收到文本。

## 1.1. 为什么不能光用文字描述图片

媒体模型作为提示词收到的**只有任务描述**，别的什么都没有：既没有标题，也没有验收标准、
项目经验和聊天 — 这些统统到不了它那里。也就是说，角色的外貌必须逐字写在镜头描述里。

在每个镜头里手工重写一遍是不行的：用自己的话一个镜头一个镜头地复述，正是角色「变形」的
原因。因此外貌只保存**一次** — 保存在项目对象里，而镜头描述中放的是对该对象的**引用**。
每次启动作业时，引用都会展开成档案和参考文件的路径，其中第一个路径作为起始帧交给模型。

修改档案会在下一个镜头上立即生效 — 不需要重写任务描述。

## 1.2. 需要准备什么

| | |
|---|---|
| 权限 | 组织中的 **admin** 角色（模型名录属于系统设置）。要**修改本地模型的记录**（在本机上启用或停用它），还需要**服务器管理员的本地登录** — 入口在顶栏用户菜单和「设置 → 服务器」中；安装本身并不需要它 |
| 硬件 | NVIDIA，至少 6 GB 显存，驱动 580+，磁盘约 18 GB，内存 16 GB（详情见模型表单中的**「i」**按钮） |
| 时间 | 768×512、121 帧、50 步的短片，在 6 GB 显存上大约要算一小时 |
| 图片 | 参考文件要在**项目文件夹之内**，比例最好一开始就接近 768×512 |

## 1.3. 第 1 步。安装模型

1. **设置**（左侧栏的齿轮图标）→ **「模型」**选项卡。
2. 点击 `Kandinsky-5.0-I2V-Lite-5s` 一行 → 会打开模型表单。
3. **「i」**按钮 — 模型文档：硬件要求、文件大小、常见错误。
4. **「安装」**按钮 — 安装窗口。会安装 ComfyUI 便携版（约 2.1 GB）和四个权重文件
   （约 16 GB；其中三个与 Kandinsky 文本模型共用 — 如果它已经装了，只需再下载约 4.3 GiB）。
   下载支持断点续传：中断的安装会从停下的地方继续。

**安装成功后模型会自动启用。**只要文件不齐，它就不可能处于启用状态 — 这一点在应用启动时
也会检查。本地模型的启用状态**在集群的每台计算机上各自独立**（表单中是「在本服务器上启用」）：
在相邻的服务器上要单独启用它，就在它的文件所在的那台机器上。

这个模型不需要 API 密钥 — ComfyUI 在本地启动，无需授权。

## 1.4. 第 2 步。建立 AI 执行者并让他投入工作

1. **执行者**（左侧栏的人形图标）→ **「+」**按钮（「添加执行者」）：
   * *对外名称（昵称）* — 在任务中怎么称呼他，例如 `kandinsky-i2v`；
   * *类型* — **AI**；
   * *内部名称* — `Kandinsky-5.0-I2V-Lite-5s`（列表中只有**已启用**的模型）；
   * *已启用* — 打开。
   连接配置档和能力声明会从名录记录中自动填入，现在不需要修改它们。
2. **团队** → 项目的团队（或「添加团队」）→ **「成员」**部分 → 把这个执行者加进去；请确认
   他的**「在团队中启用」**是打开的 — 未启用的成员在启动时不会连接，也不会被自动挑选。
3. **点击「启动」** — 启动整个团队，或者用**「启动成员」**。

第三步是必须的，原因如下：**把 ComfyUI 拉起来的正是团队工作的启动**（启动命令在安装时写进了
配置档）。如果没有启动工作，也没有手工把 ComfyUI 拉起来，作业就会失败并给出消息
*「连接 ComfyUI 超时（服务器未启动？）」*。

模型加载权重期间，成员处于「正在连接」状态 — 这是正常的，第一次连接要花上几分钟。

## 1.5. 第 3 步。项目文件夹和参考文件

起始帧是**在项目文件夹中**查找的，路径永远是相对的。向外走（`..`、`C:\…`）是有意禁止的。

1. 项目卡片 → **「基本」**选项卡 → **「项目文件夹路径」**字段（旁边有浏览按钮）。文件夹
   **在集群的每台服务器上各自独立**：在另一台计算机上同一个项目住在另一个目录里，而里面的
   相对路径是完全一样的。
2. 把参考文件放进这个文件夹，例如 `refs/hero.png`。

系列的第一帧可以用普通的「文本 → 图片」模型得到，也可以手工画出来 — 后面的一切都从它出发。

## 1.6. 第 4 步。建立角色对象

项目卡片 → **「对象」**选项卡 → **「+」**按钮（「新建对象」）。

| 字段 | 该写什么 |
|---|---|
| *名称* | 人们怎么称呼这个角色：`主角瓦夏` |
| *类型* | **角色**（类型有：角色、场景、道具、风格、参考帧、LoRA 适配器、文件、设备、媒体资源） |
| *所属对象* | 角色本身留空；它的参考帧则填角色自己 |
| *对象标签* | 独立的一组标签，与任务标签分开 |
| *文件或地址* | `refs/hero.png` — **相对于项目文件夹**的路径；旁边有选择文件的按钮（它在项目文件夹中浏览并填入相对路径），左边是预览窗 |
| *档案（会进入提示词）* | **逐字的**外貌描述：这段文字会替换掉引用 |
| *已启用* | 打开 |

档案是表单中最重要的字段。要按您希望它出现在提示词里的样子来写：

> 35 岁男性，短的深色胡须，左眉上方有疤，灰绿色眼睛。
> 磨旧的棕色皮夹克，灰色围巾，牛仔裤。冷色调的傍晚光线。

保存之后，表单中会出现两个按钮：

* **「对象引用」** — 就是要插入任务描述的东西（`@obj:OBJ-1`）；
* **「将进入模型的内容」** — 引用展开后的文字。请在这里、在生成**之前**检查档案，而不是
  等到画出一个不像的镜头之后。

**同一角色的多个参考帧**要建成它的子对象：新建一个类型为「参考帧」的对象，在*「所属对象」*
字段中填角色。在列表中它们缩进排在它下面，而它们的路径全都会进入替换。

## 1.7. 第 5 步。镜头描述

新建一个任务（任务列表中的「新建任务」按钮）并填写：

| 字段 | 值 |
|---|---|
| *标题* | `场景 1：主角回头`（**不会**进入提示词） |
| *描述（.md）* | 提示词文本 + 对象引用 — 见下文 |
| *技能* | **`video-animate`** — 这正是「图片 → 视频」模式（i2v） |
| *执行者* | 建好的那个 AI 执行者；也可以留空、依靠自动挑选 — 但那样任务就必须有**团队**：挑选是在它的成员中进行的 |
| *项目* 和 *团队* | 在**「扩展」**部分；项目是必填的 — 路径是从它算起的 |

描述：

```
@obj:OBJ-1 缓缓越过左肩回头，看向镜头。
细雨，湿沥青上的霓虹倒影，夜晚的街道。
镜头缓缓推进。
Результат положить в файл scenes/s01.mp4.
```

启动时这里会发生什么：

1. `@obj:OBJ-1` 展开成对象卡片 — 名称、类型、编号、逐字的档案以及参考文件的路径，每个
   路径各占一行；
2. 路径会从提示词中**剪掉**（它们是路径，不是场景文本），其中**第一个**成为起始帧；
3. 「Результат положить в файл `scenes/s01.mp4`」（把结果放到文件 `scenes/s01.mp4`）这一行
   同样会被剪掉 — 它由系统执行：做好的短片会用这个名字复制到项目文件夹；
4. 其余的一切 — 包括档案 — 作为提示词进入模型。

> **指示要单独写一行。**在多行的描述中，指示（「把结果放到 …」「以 … 为基础」）是**整行**
> 被删掉的 — 连同您顺手写在旁边的内容一起。「镜头缓缓推进。Результат положить в файл
> scenes/s01.mp4.」这样写成一行，就会让提示词失去镜头推进。（单行描述是例外：那里只删掉带
> 指示的那一句。）关于结果的指示同样只认**俄语和英语**的词（`положи`、`сохран`、`файл`、
> `результат`、`save`、`store`、`put`、`output`、`result`、`file`），所以上面的例子里这一行
> 是用俄语写的；镜头本身的文字用什么语言写都可以。

**引用不必手工输入：**对象列表中每一行都有一个「引用」按钮，而描述编辑器里有
**「项目对象引用」**按钮：它会在光标处插入引用，形式由项目设置*「对象引用格式」*决定 —
按编号（`@obj:OBJ-1`）或按名称（`@obj:[主角瓦夏]`）。**两种写法始终都能识别**，所以改了
设置也不会破坏已经写好的描述。

### 如果需要的是某个特定的帧，而不是第一个

用文字点名文件 — 这样的指示**强于**来自对象的路径：

```
Взять за основу refs/hero_side.png.
@obj:OBJ-1 缓缓越过左肩回头……
```

只要一行里既有图片文件名，又有指示用的词，就算作指示。指示词的识别只认**俄语和英语** —
这份词表写在代码里，与安装语言无关：`исходн`、`за основу`、`стартов`、`эталон`、
`референс`、`оживи`、`source`、`start`、`input`、`reference`、`based on`、`animate`。
这样的一行会被整行从提示词中删掉。

### 一个重要的限制

模型的起始帧只有**一个**。其余的参考路径只是从提示词中被删掉 — 模型看不到它们。对象有多个
参考帧，对人和将来训练 LoRA 适配器是有用的，但对 i2v 生成起作用的只有第一个路径：对象自己的
路径，如果它为空，就是第一个已启用的子对象的路径。

## 1.8. 第 6 步。启动与观察

任务卡片中的**「启动」**按钮。

* **「作业」**选项卡 — 作业列表和**控制台**：ComfyUI 自己的输出会转到那里，包括步数计数器。
  从中可以看出生成是在进行还是停住了。
* 控制台的第一行是启动摘要：ComfyUI 的地址、模型、画面尺寸、帧数和步数、`seed`、提示词长度、
  起始帧和结果文件。
* 要等很久：6 GB 显存上大约一小时。等待上限是执行者的「响应超时」，如果没有设置，就是配置档
  的 `params.timeoutMinutes`（默认 180 分钟）。
* 可以用任务卡片中的**「停止」**按钮停下来：ComfyUI 中的生成会被中断，作业会从它的队列中
  移除。

**会得到什么：**

* **「结果」**选项卡 — 作业的文件（`J-12-Kandinsky_00001.mp4`）和摘要 `J-12-result.md`：
  模型、画面尺寸、帧数和步数、**`seed`** 以及生成时间；
* 项目文件夹中短片的副本 — 前提是描述里有指出放到哪里的指示；
* 确切的请求 — 文件 `J-12-request.json`（所有替换完成之后的提示词、`startImage`、`seed`、
  整张计算图）。它的路径记在工作日志里，即任务的**「历史」**选项卡。这是检查模型收到的确实是
  您所设想内容的最好办法。

## 1.9. 一系列镜头中保持同一个角色

| 做法 | 有什么用 |
|---|---|
| 所有镜头都用**同一个对象** | 面孔、衣着和色彩在各段短片之间保持一致 |
| **固定的 `seed`** | 生成的「性格」一致；留空或 0 — 每个作业随机 |
| **接龙** | 把第 N 个场景的最后一帧保存成图片放进项目文件夹，作为第 N+1 个场景的输入 |
| **统一的画面尺寸** | `width`/`height` 不同的短片彼此会对不上 |

`seed` 和其余的生成参数在模型的配置档中修改 — 模型表单或执行者表单中的**「配置档…」**
按钮：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `width` / `height` | 768 × 512 | 画面分辨率；起始图片也会被归到这个尺寸（按中心裁剪） |
| `length` | 121 | 帧数，约 5 秒 |
| `steps` | 50 | 扩散步数；越少越快也越粗糙 |
| `negative` | 空 | 负面提示词 |
| `seed` | 无 | 固定的 seed |
| `timeoutMinutes` | 180 | 等结果等多久 |

执行者的配置档是他自己的：可以在同一个模型上建立两个执行者，各自用不同的 `seed` 和分辨率。

## 1.10. 常见错误

| 消息或症状 | 该怎么办 |
|---|---|
| **「该模型需要起始帧…」** | 描述中既没有图片文件，也没有引用带参考文件的对象 |
| **「项目文件夹中未找到起始帧文件：…」** | 路径是从项目文件夹算起的；请检查写法以及文件是不是确实放在那里 |
| **「项目在本机上未指定文件夹…」** | 请在项目卡片中填写「项目文件夹路径」 — 文件夹在每台服务器上各自独立 |
| **「起始帧 … 指向了项目文件夹之外」** | `..` 和绝对路径是有意禁止的 |
| **「连接 ComfyUI 超时（服务器未启动？）」** | 没有启动团队工作（第 2 步） — 正是它把 ComfyUI 拉起来 |
| **「任务描述为空 — 媒体模型需要在描述中给出生成提示词」** | 剪掉指示之后描述什么都没剩下；请补写镜头里发生了什么 |
| **「该模型的 workflow 不接受起始帧 — 文件 … 未被使用」** | 任务交给了「文本 → 视频」模型；请给任务加上 `video-animate` 技能，或者明确指定所需的执行者 |
| **引用 `@obj:…` 以文本形式留在提示词里** | 未找到对象：编号/名称不对，或者对象属于另一个项目。引用是有意不删除的 — 否则镜头会没有角色，而提示词看上去却是对的 |
| **角色「变形」** | 请检查各镜头引用的是同一个对象、`seed` 已固定、画面尺寸一致，而且描述里没有把档案又复述一遍 |
| **进程无声无息地消失** | 几乎总是 NVIDIA 驱动太旧；先从 `nvidia-smi` 开始，需要 580+ |
| **显存不够** | 减小 `width`/`height` 或 `length` |

## 1.11. 值得记住的事

* 媒体模型**不进行对话**：它既没有工具，也没有聊天。在任务聊天里给它写字是没用的 — 新的
  镜头就是新的一次作业启动。
* 标题、验收标准、项目经验和模板节点的经验**都不会进入**提示词。所有应当进入生成的内容，
  都放在任务描述里或对象的档案里。
* 档案内部的引用**不会展开**：一份引用了另一个对象的档案，会让那个引用以文本形式留下。
  这是对相互引用的对象的一种防护。
* 对象属于项目：引用够不到相邻项目的对象。
* 被关闭的对象仍留在列表中，指向它的引用也不会断 — 这不是删除；但被关闭的**子对象**不会
  进入路径替换。
