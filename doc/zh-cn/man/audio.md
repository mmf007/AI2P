# 使用音频模型

**本章目标：**用几个部分——音乐、歌曲、特定人物的说话声、噪声——拼成一个声音场景，并弄清楚有哪些
模型可用、它们需要什么样的声音样本、以及它们做不到什么。

我们以这样一个场景为例：

> 播放着舒缓的乡村音乐，由歌手 **X** 演唱。两个人 **Y** 和 **Z** 在山上谈论眼前燃烧的森林。一架
> 消防直升机从他们头顶飞过。

## 1. 首要规则：一个任务——一层声音

名录中没有任何一个音频模型能一次生成这样的场景：

* 音乐模型会唱歌，但不会用特定人物的声音说话；
* 语音模型会说话，但不会演奏音乐，也不会唱歌；
* 带声音样本的语音模型每个作业只接受**一个**样本——两个声音的对话无法在一个作业里完成；
* 名录中没有音效模型；
* AI2P 不会把音轨叠加在一起：连接器和 `tool.ffmpeg` 插件都没有混音功能。

因此场景要拆成若干**层**，每一层是一个单独的任务（或几个任务），做好的文件再在音频或视频编辑器中混音。

| 层 | 任务技能 | 名录中的模型 | 是否需要声音样本 |
|---|---|---|---|
| 歌手 X 演唱的乡村音乐 | `audio-song` | ACE-Step-1.5-XL-Turbo / -Base / -SFT（本地）、ElevenLabs-Music（云端） | 不需要——也没有地方传入（第 3 节） |
| Y 的台词 | `audio-speech` | Chatterbox-TTS、Zonos-2-TTS（按样本）、ElevenLabs-TTS-v3（预设声音） | 需要，Y 的声音录音（第 4 节） |
| Z 的台词 | `audio-speech` | 同上 | 需要，Z 的声音录音 |
| 直升机飞过 | — | 没有模型 | 需要——现成的录音（第 5 节） |

## 2. 名录中的音频模型

技能：`audio-song`——带人声的歌曲，`audio-music`——器乐，`audio-speech`——语音配音。三者都是
「文本 → 声音」：提示词就是**任务描述**，标题、验收标准和项目经验都不会传给模型。

| 模型 | 在哪里计算 | 做什么 | 声音样本 | 价格 |
|---|---|---|---|---|
| [ACE-Step-1.5-XL-Turbo](../models/ACE-Step-1.5-XL-Turbo.md)、[-Base](../models/ACE-Step-1.5-XL-Base.md)、[-SFT](../models/ACE-Step-1.5-XL-SFT.md) | 本地，ComfyUI，NVIDIA 8 GB 起 | 歌曲和音乐；描述里没有歌词时自己写 | 不接受 | 免费，权重 MIT |
| [ElevenLabs-Music](../models/ElevenLabs-Music.md) | 云端，fal.ai 网关 | 歌曲和音乐，3 秒到 10 分钟 | 不接受 | 每分钟 0.6 美元 |
| [ElevenLabs-TTS-v3](../models/ElevenLabs-TTS-v3.md) | 云端，fal.ai 网关 | 用预设声音说话（`voice` 字段） | 不接受 | 见模型页面 |
| [Chatterbox-TTS](../models/Chatterbox-TTS.md) | 云端，fal.ai 网关 | 用按样本复制的声音说话 | 一段录音，最长 30 秒 | 每 1000 字符 0.025 美元 |
| [Zonos-2-TTS](../models/Zonos-2-TTS.md) | 云端，fal.ai 网关 | 用按样本复制的声音说话，WAV 44.1 kHz | 一段录音，最长 30 秒，**必需** | 见模型页面 |

一些**视频模型**也能生成声音（Veo-3.1、Seedance-2.5、Wan-3.0-Prime、Kling-3.0、LTX-2.5、
Gemini-Omni-Flash），但声音只存在于视频片段中；如何利用这一点见第 5 节。

所有模型的准备工作都一样：模型处于启用状态（云端模型已设置 `fal.apiKey` 密钥，本地模型已安装文件），
在它上面建立了 AI 执行者，执行者已加入项目团队，本地模型还需启动团队工作。分步说明见
[视频短片示例](sample_video1.md) 第 1.3–1.4 章。

## 3. 音乐与歌手 X

**X 需要什么样本？**不需要：名录中的音乐模型不接受声音样本。ElevenLabs-Music 没有录音字段，
随 ACE-Step 提供的 workflow 中也没有加载音频的节点。而能按样本复制声音的模型（Chatterbox、Zonos）
**只会说话，不会唱歌**。

因此 X 的声音要**用文字**描述——性别、音色、演唱方式：

```
一首舒缓的乡村民谣，每分钟 80 拍：原声吉他、滑棒吉他、
低音提琴、军鼓上的鼓刷。温暖的复古音色。
男声：低沉的男中音，柔和，略带沙哑，轻声演唱。
歌词关于群山和森林上空的烟，用中文演唱。
Save the result to file sound/music.mp3.
```

* 任务技能为 `audio-song`；不带人声的器乐用 `audio-music`，并写上「无人声」。
* 自己的歌词直接写进描述——ACE-Step 会采用；不写的话它会自己创作。
* 时长：ACE-Step 是模型配置中的 `length`，**单位是秒**；ElevenLabs-Music 是配置 `request` 部分中的
  时长字段（模板中为 30 秒）。
* 保存结果的指示要**单独写一行**：这一行会整行从提示词中删除。识别用的词**只有俄语和英语**
  （`save`、`result`、`file`…），所以示例中这一行用英语写。
* 在描述中写真实艺人的名字并不能代替样本，还会带来法律风险——请描述声音的特点。

**让 X 的声音在各首曲目之间保持一致：**

| 方法 | 作用 |
|---|---|
| 同一段声音描述 | 方便把它保存为项目对象（类型「风格」或「角色」）的档案，并使用 `@obj:` 引用 |
| 配置中固定的 `seed`（ACE-Step） | 结果可复现；为空或 0——每个作业随机 |
| LoRA 适配器（ACE-Step） | 可以应用现成的适配器，但不能在 AI2P 中训练（见模型文档中关于 LoRA 训练的部分） |

如果 Y 和 Z 的对话叠在歌曲上，混音时需要把人声压低。更简单的做法是直接要求一首人声不在开头进入的
曲目：「前奏 30 秒，无人声」。

## 4. Y 和 Z 的声音：按样本合成语音

**是的，有语音合成模型**——名录中有三条带 `audio-speech` 技能的记录：

* **ElevenLabs-TTS-v3**——评分最高，但只用服务商的**预设**声音说话（配置 `request` 部分中的
  `voice` 字段，默认 `Rachel`），不接受样本。适用于 Y 和 Z 不是特定人物的情况：在同一个模型上建立
  两个执行者，设置不同的 `voice`（每个执行者有自己的配置）。
* **Chatterbox-TTS** 和 **Zonos-2-TTS**——按录音**样本**复制声音（zero-shot clone）：无需任何训练，
  10–20 秒录音就足够。

名录中没有本地语音模型：三者都在云端计算，需要 fal.ai 网关的密钥。

### 4.1. Y 和 Z 需要什么样的样本

每人**一段**录音：

| 要求 | 原因 |
|---|---|
| 长度 10–20 秒（允许 3–30 秒） | 太短抓不住音色，超过 30 秒网关会拒绝 |
| 只有一个说话人，没有音乐、噪声和回声 | 模型会复制听到的一切，包括房间声学 |
| 音量均匀，没有削波 | 失真会被带进合成结果 |
| 与场景需要的说话方式一致 | 平静的交谈——用平静的样本，而不是喊叫 |
| 与台词语言相同 | 发音更准确 |
| WAV 或 MP3 | 名录中两条记录都接受的格式 |
| **声音主人的同意** | 模型许可证不授予使用他人声音的权利 |

把文件放进项目文件夹，例如 `refs/voice_y.wav` 和 `refs/voice_z.wav`。方便的做法是把它们建成
**「参考音频」**类型的项目对象——作为角色 Y 和 Z 的子对象：这样样本在对象列表中一目了然，不会丢失。

### 4.2. 一句台词——一个任务

一个作业只有**一个**样本，所以对话要由单独的任务组成：Y 的台词、Z 的台词、再是 Y……任务描述会被
**整段朗读出来**，因此其中只能有台词文本和给系统的指示，每条指示单独一行：

```
你看，那边，第二道山脊后面——烟已经盖住了整个山谷。
Voice sample refs/voice_y.wav.
Save the result to file sound/dialog_01_y.wav.
```

* 含有音频文件名以及 `voice`、`sample`、`speaker`、`timbre` 之类词语（俄语为「образец」「голос」）
  的一行是指示：文件传给模型，这一行从文本中删除。识别词**只有俄语和英语**；中文的「声音样本」
  不会被识别。
* **配音任务中最好不要使用 `@obj:` 引用。**它会展开成对象卡片——名称、类型、编号和档案；路径会被
  删除，但名称和档案会留在文本中并被**朗读出来**。请像示例那样单独一行写出文件名。（对于第 3 节的
  音乐模型可以使用引用：那里的档案就是风格描述。）
* 任务技能为 `audio-speech`，执行者使用 Chatterbox-TTS 或 Zonos-2-TTS。方便的做法是把对话的各个
  任务作为同一个父任务「Y 和 Z 的对话」的子任务。
* 语调由台词文本和样本决定。微调字段在配置的 `request` 部分：Chatterbox 有 `exaggeration`
  （表现力），Zonos 有 `accurate_mode`（更贴近样本还是更有表现力）和 `language`（文本规范化语言）。
* 所有台词都**用同一个模型**生成：文件格式一致，拼接更简单。

做好的台词可以用 [tool.ffmpeg](../plugins/tool.ffmpeg.md) 插件的 `ffmpeg_concat` 动作按顺序拼接。
它不会在台词之间加停顿——停顿以及把语音叠加到音乐上，都要在编辑器中完成。

## 5. 消防直升机

**需要单独的直升机声音吗？**需要。名录中没有音效模型，现有的模型也不适合做这件事：

* 语音模型（Chatterbox、Zonos）按样本复制的是**声音**而不是噪声——把直升机录音作为样本，并不会
  变成直升机的声音；
* 音乐模型（ACE-Step、ElevenLabs-Music）生成的是**音乐**：描述中的「直升机轰鸣」最多带来一点音乐
  色彩，而不是逼真的飞过声。

三种可行的办法，从可靠到实验性：

1. **现成的录音**，来自许可证允许您使用的音效库——放进项目文件夹（`sound/helicopter.wav`），再加入
   混音。这是短小、易辨认音效的最佳选择。
2. **来自视频模型的声音。**「文本 → 带声音的视频」模型（Veo-3.1、Seedance-2.5、Wan-3.0-Prime 等）
   会自己为场景配音。像「一架消防直升机低空飞过燃烧的森林，旋翼声由远及近再远去」这样的任务会生成
   一个视频片段，再用 `tool.ffmpeg` 插件的 `ffmpeg_extract_audio` 动作提取声音。这需要付费，而且
   这类模型的声音质量没有单独验证过。
3. **自建名录记录。**fal.ai 网关有专门的音效模型；系统没有为它们提供现成记录，但网关的云端模型
   无需修改代码即可添加为名录记录。请对照目录 `https://fal.ai/api/models` 和端点的模式核对 id 和
   请求字段——网关会在已经付费的作业中以 HTTP 422 拒绝未知字段。

## 6. 场景混音

现在项目文件夹中有这些文件：

```
sound/music.mp3          — 歌手 X 演唱的乡村音乐
sound/dialog_01_y.wav …  — Y 和 Z 的台词
sound/helicopter.wav     — 直升机飞过
```

它们在音频或视频编辑器中混音：音乐作为背景且比语音小声，台词按顺序并留出停顿，直升机叠加在上面并
渐入渐出。如果场景要放进视频，方便的做法是直接在通过插件接入的视频编辑器中混音（OpenShot、Shotcut、
DaVinci Resolve、Blender——见 [插件与 MCP](../plugins/README.md)）。

## 7. 常见错误

| 消息或现象 | 怎么办 |
|---|---|
| **模型把对象名称或档案读了出来** | 配音任务中有 `@obj:` 引用——改为单独一行「Voice sample 路径/文件.wav」 |
| **模型把保存结果的指示读了出来** | 指示和台词写在同一行——把它移到单独一行 |
| **「未传入参考音频」** | 描述中没有带 `voice` 或 `sample` 之类词语的音频文件名；Chatterbox 和 Zonos 必须有录音 |
| **结果文件被当作样本传给了模型** | 结果那一行或文件名中含有识别词（`voice`、`sample`、`speaker`…）——给结果文件换个名字，例如 `dialog_01_y.wav` |
| **「该模型不接受录音」** | 任务交给了不接受样本的模型（ElevenLabs-TTS-v3 或音乐模型）——请明确指定执行者 |
| **网关返回 HTTP 422** | 样本超过 30 秒、格式不合适，或请求中有端点不认识的字段 |
| **声音不像样本** | 录音中有噪声、音乐或第二个人声——换一段干净的 10–20 秒录音 |
| **歌曲语言不对** | 在描述中写明语言；ACE-Step 则在 workflow 的 `language` 字段中填写语言代码 |
| **曲目比预期短或长** | ACE-Step 的 `length` 单位是秒 |

## 8. 值得记住

* 媒体模型**只接收任务描述**；对语音模型来说，整段描述就是它要说出的文本。
* 语音模型的固定声音靠**样本**而不是训练来保持：同一个人的所有台词使用同一段录音。
* 名录中的音乐模型不能按样本复制声音——歌手的声音要用文字描述。
* 名录不生成音效，各层的混音也不是由 AI2P 而是由编辑器完成。
* 声音和音效库素材的使用权需要您自己负责：模型许可证不授予这些权利。
