# 执行者

**执行者就是做任务的那个人（或那个东西）。** 人或者 AI：对系统来说这是同一个概念、同一套字段，
任务并不区分它被交给了谁。正因如此，工作可以从 AI 转给人、再转回来，什么都不用重写。

列表用左侧栏的**「执行者」**按钮打开（以及同名的菜单项）。

---

## 为什么需要它

执行者回答系统的三个问题：

1. **交给谁。** 任务恰好有一个执行者，而选择范围限于它所属团队的成员（见[团队](teams.md)）。
2. **谁会做这件事。** 执行者有一份**能力声明**：他掌握哪些技能、掌握得多好。自动挑选按它工作。
3. **他用什么做、价格多少。** AI 有模型、密钥、参数、每百万令牌的价格、限额和超时。人有邮箱、
   电话和忙碌情况。

账户和执行者是**两回事**。账户（设置 → 用户）是用来登录的；执行者是用来干活的。人类执行者有一个
「账户」字段把两者关联起来；没有账户的执行者不能登录系统，但任务可以记在他名下 — 不在 AI2P 里
工作的外包人员就是这样创建的。

---

## 列表里有什么

列表显示的是挑选执行者所依据的东西，而不是一股脑什么都显示：

| 列 | 含义 |
|---|---|
| **昵称** | 对外名称，在整个组织内唯一；执行者在各处都用它署名 |
| **类型** | 人、AI，还是「自动软件」（程序） |
| **启用** | 未启用的不会被填入新的团队和任务；旧的关联保留 |
| **忙碌至** | 执行者忙到什么时刻（已经过去的时间不显示） |
| **限额百分比** | 提供商限额的当前消耗 — 如果提供商会发送它的话 |
| **窗口上限** | 自己的计数：滑动窗口内的`已消耗/上限`，以及窗口何时释放 |

排序 — 点击列标题（再次点击改变方向）。按「窗口上限」排序时，没有限额的执行者排到最后。

## 执行者表单

表单比普通对话框更宽，并随类型而变化。逐字段拆解没有必要 — 重要的是四个容易出错的地方。

### 内部名称

* **对 AI 来说这不是文本，而是从模型名录中选取** — 而且只能从**已启用**的记录中选。随模型一起
  联动填入的还有配置档（连接参数）和能力声明：对执行者来说它们「与模型的相同」。重新选了模型 —
  两个文件都跟着换。
* **对人来说**这是姓名，并且其唯一性会被跟踪。

由此得到一条省时间的规则：**如果需要的模型不在列表里 — 那它没有启用。** 没有 API 密钥的云端模型
和没有下载文件的本地模型都不可能处于启用状态。该去的是 设置 → 模型，而不是在执行者表单里找错。

### 配置档和能力声明

两者都是 JSON 文件，但表单不显示它们的路径：它们用按钮来编辑。

* **配置档** — 如何连接：提供商、模型、地址、密钥引用、温度、各种超时、LoRA 训练的设置。人的
  配置档是另一种 — 邮箱、电话和其他属于人的数据。
* **能力声明** — 执行者会做什么：带掌握程度评分的技能列表、输入和输出格式、价格
  （`in_per_1m` + `out_per_1m`）。它的编辑器对 AI、人和模型名录记录来说是**同一个**。

能力声明不是装饰品：如果某个技能在任何一份声明里都没有，带这个技能的任务永远找不到执行者，而
自动挑选正是按它来算分的。

### 忙碌、限额和超时（仅 AI）

* AI 的**「忙碌至」不可编辑**：当提供商回答「限额已用尽」时，系统自己设置它。对人来说这是普通的
  日期和时间，清空日期即可解除忙碌。
* **「每个窗口的令牌上限」和「限额窗口（小时）」** — 自己的消耗计数，在提供商不报告余量的地方需要
  它（Claude Code 订阅：窗口 5 小时）。两个字段都由人凭经验设定。**留空或 0 — 不设限额**，整套
  机制会被完全关掉：不统计余量、没有警告、启动照旧。
* **「响应超时（分钟）」** — 等模型多久。留空 — 30 分钟，**0 — 不限制**。超时属于作业出错，而不是
  限额：不会把执行者标记为忙碌，也不会推迟启动。

限额几乎耗尽时会发生什么：作业**不会被创建**，任务的启动被推迟到窗口释放的时刻，而任务聊天里会
收到一条警告 — 消耗了多少、启动被推迟到了什么时候。这个推迟能挺过计算机关机，而人随时可以强制
启动任务。

### 通知用的邮箱

**「使用用户登录名中的邮箱」**复选框默认是勾选的，这时根本没有地址字段 — 取而代之的是一句说明，
写着将使用哪个地址。取消勾选并把字段留空，就意味着**「不向该执行者发送通知」**，表单也是这么写的。

## 第三种执行者类型：「自动软件」

除了人和 AI，还有第三种类型 —— **「自动软件」**。干活的既不是人，也不是语言模型，而是
**本机上的一个程序**：LoRA 适配器训练器、转换器、计算工具。任务本身仍然是普通任务 ——
有期限、有验收、有控制台、有历史、有结果。

这种执行者的内部名称既不是模型，也不是姓名，而是一对**「插件 + 操作」**：

* **插件** —— **本服务器**上[插件与 MCP](plugins.md)一节中的记录：它带来程序及其路径；
* **操作** —— 插件清单中带名字的长时间运行（在 musubi 训练器里就是「LoRA 训练」）。标有
  **「单实例」**的操作在表单里会明确标出：只要它正忙，第二个任务就在队列里**等待**，而不是
  报错。

「自动软件」与 AI 执行者的区别，以及为什么这样：

| 区别 | 为什么 |
|---|---|
| **没有提示词** | 程序不读文本：它需要的一切都来自插件记录中已声明的设置和项目文件夹内的路径。任意命令行谁都没有 |
| **没有 token、没有价格、没有限额** | 没什么可算，也没人可付：表单里既没有限额区块，也没有消耗行，「开销」里也不统计这种执行者 |
| **服务器是必填的** | 程序装在具体某台机器上。「服务器」字段填的是创建该执行者的那台服务器，并且永远不为空：空值意味着「在指挥者那里」，而一旦更换指挥者，这类工作就会整体跑到另一台机器上。别的服务器的任务不能交给它 —— 系统会用话说明拒绝 |
| **一次只做一件事** | 程序正在计算时不会再给它第二个作业；任务的等待方式和等待忙碌的 AI 完全一样 |
| **自动挑选永远不选它** | 见下 |

**为什么自动挑选会绕过「自动软件」。** 两个挑选按钮 ——「先 AI 后人」和「先人后 AI」—— 都是
**按类型**把这种执行者剔除的，而且在计算技能与价格之前就剔除了。第三种类型无法用「AI → 人」
这个顺序表达，而程序的能力声明可以写成任何样子：否则「画一张图」的任务就会悄悄跑到 LoRA
训练器上。因此「自动软件」要**手工**指定 —— 或者由需要这项工作的那个按钮按模板创建任务
（[LoRA 编辑器](LoRAEditor.md)里的「训练」就是这样做的）。

创建方式还是普通的「新建执行者」按钮：类型选「自动软件」，然后从下拉列表里选插件和操作。
它既没有配置档，也没有能力声明按钮。

## 执行者是怎样被选出来的

手动 — 从任务表单的下拉列表中选（只有它所属团队的成员）。

自动 — 用执行者字段旁边的两个按钮：**「先 AI，后人」**和**「先人，后 AI」**。候选人是任务团队中
**已启用**的成员，而且启用是双重的：执行者本人要启用，他在这个团队中的参与也要启用。得分是这样
算的：

```
得分 = bias × 质量 + (1 − bias) × 便宜程度
```

其中*质量*是声明中所需技能掌握程度的平均值，*便宜程度*是同一份声明中价格的倒数，而 `bias` 是
项目设置**「价格 ↔ 质量」**（见[项目](progects.md)）。忙碌的执行者会被跳过；如果所有合适的人都
忙，系统会说明原因和释放时间。挑选的理由会直接在界面上解释 — 质量、价格、得分。

还有**备选执行者**：任务表单中的「可替代的执行者」列表。其中的顺序就是优先顺序，取第一个空闲的。
被替换时，被指派的执行者本身不变 — 卡片上会出现一行「正在处理：<昵称>」。

## 值得马上创建的 AI

首次启动之后，系统会按所选的典型用途，在技能最合适的模型上创建三个 — `Jon`、`Bob` 和 `Stiv`。
这是个合理的起点，而它们是三个而不是一个的原因在于：**每个 AI 执行者一次只带一个作业**。同一个
模型要同时处理多个任务，只能通过**不同的执行者**。因此这里的「增加算力」意味着「增加执行者」，
而不是「买个更大的密钥」。

## 特殊情况

* **本地模型把执行者绑在服务器上。** 权重和启动命令放在具体某台计算机上，因此这样的执行者有一个
  「服务器」字段；不能把他指派给另一台服务器的任务 — 系统会用文字拒绝（「他运行在服务器 S1 的
  模型上 — 请把任务转到那里」）。您在自己这边关掉了本地模型 — 您这台机器上使用该模型的执行者也
  会不再启用；这不影响其他服务器上的执行者。
* **执行者列表只能在**组织的**指挥服务器上修改**：执行者会被指派给所有服务器的任务，而列表必须
  只有一份。例外是账户加入组织时创建成员。
* **一个账户对应一个执行者。** 不能把一个账户绑到两个执行者上，保存会被一条明白的错误拦下。
