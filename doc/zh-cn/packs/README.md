# 经验集：工作风格

本目录存放**经验集**的说明文档——每个**经验集代码**一个文件（`style.tdd.md`）。文档通过经验集所在行的
**“i”**按钮打开：**设置 → 经验 → 经验集**。

经验集是一整包现成的经验条目：人只需按一个按钮安装，就能获得开箱即用的代理工作纪律——我们如何评审、如何写测试、
如何写报告。经验集文件位于数据目录的 `packs/<代码>/pack.json`；条目会落入你在安装时选择的范围（组织通用规则、
某个项目的经验，或模板节点），并且可以用一个按钮整体卸载。

## 本节目录

* [style.strict-review](style.strict-review.md) — 严格代码审查
* [style.tdd](style.tdd.md) — 测试驱动开发
* [style.research-report](style.research-report.md) — 调研与报告
* [style.experience-analysis](style.experience-analysis.md) — 经验分析

最后一个自成一类：`style.experience-analysis` 不是工作风格，而是用于定期梳理已积累经验的任务模板。

## 所有经验集的共同点

**条目是规则，不是论述。** 每条都简短、只说一件事，并且改变执行者的行为。复述人所共知的内容不会进入经验集：那会
吃掉任务的经验额度，把真正需要的内容挤出去。

**条目带技能。** 关于测试的规则发给写测试的人，关于报告的规则发给写报告的人。没有技能的条目根本不会进入任何任务——
除非标记为“始终加载”，而发行版中这样的条目恰好只有一条。

**不含任何项目专有内容。** 随发行版提供的经验集不点名产品、文件路径或任务代码：它可以安装到任何组织。你自己的结论
写在旁边，作为普通的项目经验条目。

**经验集整体安装、整体卸载。** 安装会给自己的条目打上服务标签 `pack:<代码>`；卸载只带走这些条目，不动你的条目，
也不动你的修改。你编辑过的条目仍属于你：再次安装不会覆盖它。

## 如何为新的经验集添加文档

把 `<经验集代码>.md` 放到这里，代码要与 `pack.json` 中完全一致。同名文件也要在其余各语言中建立：各语言的文档
清单必须一致。
