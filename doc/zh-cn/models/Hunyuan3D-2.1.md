# Hunyuan3D-2.1

**部署位置:** 本地（在这台计算机上运行）
**接入方式:** `provider: comfyui`，`baseUrl: http://127.0.0.1:8188`，模型 `hunyuan3d_2_1`
**API 密钥:** 不需要 —— 服务器在本地启动，无需授权
**功能:** 图像 → 3D 模型，技能 `3d-image` 86

腾讯的开放模型，把一张图片变成三维网格。它是名录中第一条覆盖 3D 的本地记录：
在它之前，`3d-*` 技能只有云端的 Tripo 和 Meshy 有。

它通过 **ComfyUI** 工作：AI2P 把它作为本地服务器启动，发送 workflow，
再把做好的 `.glb` 取回任务的产物中。

**读的是图片，不是文字。**模型的图里根本没有文本编码器 —— 条件是 CLIP Vision
从起始帧给出的。任务描述模型看不到：图片上画的是什么，出来的就是什么。
起始帧在任务描述中用项目对象引用（`@obj:OBJ-3`）指定，或者用相对于项目文件夹的
文件路径指定；没有它，作业根本不会启动。

**不会有颜色。**ComfyUI 只算 Hunyuan3D 的**形状**分支
（`VAEDecodeHunyuan3D` → `VoxelToMesh` → `SaveGLB`）。腾讯仓库里的上色分支 ——
就是那个需要 Linux、CUDA 12.4 和自带 CUDA 光栅化的分支 —— 引擎里没有实现，
用标准的包也接不上。需要彩色网格，请用
[TRELLIS-2](https://huggingface.co/microsoft/TRELLIS.2-4B)，它在旁边一条记录里。

## 不需要密钥，需要安装

一切都用模型表单中的**「安装」**按钮完成：**设置 → 名录 →
模型 → Hunyuan3D-2.1 →「安装」**。会安装：

* **ComfyUI 包**（约 2,1 GB）—— 自带 Python 的便携版；
* 模型仓库（`storage.modelsRepo`）中的**一个权重文件**，组 `Hunyuan3D-2.1`：

| 文件 | 大小 | 放到哪里 |
|---|---|---|
| `hunyuan_3d_v2.1.safetensors` | ~6,86 GiB | `checkpoints` |

**总共约 7,4 GB 的下载量。**下载支持续传：中断的安装会从停下的地方继续，
已经下好的文件不会重下。

文件没有就位之前，模型**不可能处于已启用状态** —— 应用启动时也会检查这一点。

## 硬件要求

| | |
|---|---|
| 显卡 | NVIDIA，**8 GB 显存起**（12 GB 会很宽裕） |
| NVIDIA 驱动 | **580 或更新** —— 驱动太旧时 torch 会无声崩溃 |
| 磁盘空间 | ~10 GB（权重 + ComfyUI 包） |
| 内存 | 16 GB 起 |
| 操作系统 | Windows（ComfyUI 便携版）；在 Linux 上 ComfyUI 需要手动安装 |

显存这个数字是**估算**，不是实测：这里只算形状分支，而各类评测里 Hunyuan3D 2.1
提到的「10–29 GB 显存」说的是腾讯的完整流水线，包括烘焙纹理。内存不够时，
请调小 workflow 模板中的 `octree_resolution`。

## 要等多久

在现代显卡上，一个模型是几分钟。配置档中作业超时设为
60 分钟（`params.timeoutMinutes`）。

生成进度可以在任务卡片的**作业控制台**中看到：ComfyUI 自己的输出连同进度条
都会流到那里。

## 生成参数

在模型配置档中修改（「连接配置档」按钮）：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `steps` | 30 | 扩散步数；低于 20 形状会散掉 |
| `timeoutMinutes` | 60 | 等待结果多久 |
| `width` / `height` | 1024 | 对结果**没有**影响：3D 没有画面 |
| `negative` | 空 | 不起作用 —— 图里没有文本编码器 |

网格的密度不由配置档决定，而由 workflow 模板本身决定：`VAEDecodeHunyuan3D` 的
`octree_resolution`（256）和 `VoxelToMesh` 的 `threshold`（0.6）。

## LoRA 训练

**不支持，而且这是如实的拒绝，不是没做完。**今天还没有面向 3D 架构的公开 LoRA
训练器：AI2P 里所有适配器训练都依赖的
[musubi-tuner](https://github.com/kohya-ss/musubi-tuner) 只会图片和视频。
因此配置档里写的是 `lora.supported: false`，模型表单会用文字显示原因。

这里要让对象在各帧之间保持一致，靠的是另一种办法：把角色的同一张参考图片
（项目对象，`@obj:` 引用）送进输入 —— 相同的图片加相同的 `seed`，出来的网格也相同。

## 常见错误

* **「模型未安装」** —— 文件没有下全；请打开「安装」，窗口会显示还剩多少。
* **没有图片时作业拒绝启动** —— 本来就是这样设计的：这个模型只从图像工作。
  请给出指向参考帧的 `@obj:` 引用或者文件路径。
* **做出来的模型是白的** —— 这条记录根本不会有颜色（见开头）。
* **显存不足** —— 请调小 workflow 模板中的 `octree_resolution`。
* **进程无声无息地消失** —— 几乎总是 NVIDIA 驱动太旧（见上）。
