# ACE-Step-1.5-XL-Turbo

**部署位置:** 本地（在本机运行）
**接入方式:** `provider: comfyui`，`baseUrl: http://127.0.0.1:8188`，模型 `acestep_v1_5_xl_turbo`
**API 密钥:** 不需要 — 服务器在本地启动，无需授权
**功能:** 文本 → 音乐与歌曲，技能 `audio-song` 84、`audio-music` 86

来自 ACE-Step 团队的音乐创作模型，**Turbo** 变体：蒸馏版，用**八步**而不是五十步算出一首
曲目，而且不用 classifier-free guidance。这是拿到成品曲目最快的方式 — 在您还在斟酌措辞时，
它是合理的首选。

值得选用 ACE-Step 1.5 的那个特点：模型内部运行着一个**语言模型规划器**。它会自行把您的
请求分解为歌曲结构、歌词、速度和调性。因此不需要用单独的字段写歌词 — 只要用文字描述任务
即可，歌词模型会自己创作（或者采用您写的那些）。它能理解五十多种语言，其中包括俄语和中文。

通过 **ComfyUI** 工作：AI2P 把它作为本地服务器启动，发送 workflow，并把生成好的 `.mp3`
取回任务的产物中。

## 不需要密钥，但需要安装

一切都用模型表单中的 **「安装」** 按钮完成：**设置 → 名录 → 模型 → ACE-Step-1.5-XL-Turbo →
「安装」**。会安装：

* **ComfyUI 包**（约 2,1 GB） — 自带 Python 的便携版；
* **四个权重文件**放入模型仓库（`storage.modelsRepo`），分组 `ACE-Step-1.5`：

| 文件 | 大小 | 放到哪里 |
|---|---|---|
| `acestep_v1.5_xl_turbo_bf16.safetensors` | ~9,3 GiB | `diffusion_models` |
| `qwen_4b_ace15.safetensors` | ~7,8 GiB | `text_encoders` |
| `qwen_0.6b_ace15.safetensors` | ~1,1 GiB | `text_encoders` |
| `ace_1.5_vae.safetensors` | ~322 MiB | `vae` |

**合计约需下载 19,9 GB。** 下载支持续传：中断的安装会从停下的地方继续，已下载的文件不会
重新下载。

名录中三条 ACE-Step 1.5 XL 记录（Turbo、Base、SFT）共用**同一个分组**以及四个文件中的
三个。如果您已经装过其中一条，第二条只会补下载它自己的权重文件 — 约 9,3 GiB，而不是全部
19,9 GB。

在文件到位之前，模型**不能被启用** — 应用启动时也会检查这一点。

## 需要等多久

八步就是每首曲目**几秒到几十秒**：作者声称在 RTX 3090 上不到 10 秒出一首完整的歌。配置档
中作业超时设为 60 分钟（`params.timeoutMinutes`） — 即使在慢机器上也绰绰有余。

生成进度可以在任务卡片的**作业控制台**中看到：ComfyUI 自己的输出连同它的进度条都会流到
那里。

## 生成参数

在模型配置档中修改（「连接配置档」按钮）：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `length` | 120 | **曲目时长，单位为秒**（不是视频那样的帧数） |
| `steps` | 8 | 扩散步数；Turbo 超过八步没有意义 |
| `width` / `height` | 未设置 | 声音没有画面尺寸；作业摘要中会显示默认的 768×512 — 与声音无关 |
| `negative` | 空 | 负面提示词 — **在 Turbo 上不起作用**（见下文） |
| `timeoutMinutes` | 60 | 等待结果多久 |

**关于时长。** 这条记录中的 `length` 字段表示秒，并会同时进入图的两个位置：空潜变量的尺寸
和规划器的 `duration` 字段。在作业摘要中它被标注为「帧数」 — 所有媒体模型都是这样标注的；
请把它读作「秒」。模型设计的曲目长度大约到十分钟。

**关于负面提示词。** Turbo 模式不用 classifier-free guidance 计算（`cfg = 1`），因此模板
中的负面条件是用 `ConditioningZeroOut` 节点做的 — 与 ComfyUI 官方模板完全一致。`negative`
的值可以写进配置档，但它不会影响声音；如果需要负面条件，请用
**ACE-Step-1.5-XL-Base** 或 **-SFT**。

**关于演唱语言。** 图中的 `language` 字段设为 `unknown` — 模型会自行按您的文本判断语言。
在 ComfyUI 官方模板中那里写的是 `en`，那样中文歌词会带上英语发音。如果您总是用同一种语言
演唱，请直接在模型的 workflow 模板中写上它的代号（`ru`、`en`、`zh`、…）。

任务描述会整体进入提示词（模型的 `tags` 字段）。诸如「результат положить в файл X.mp3」
这样的指令由连接器执行：文件会被复制到项目文件夹，而这一行会从提示词中删掉。指令只能用
俄语或英语书写，场景文本可以是任何语言。

## 如何写任务描述

模型期待的是对音乐的描述，而不是命令。有效的写法：

* **风格、速度、乐器、情绪** — 「安静的氛围音乐，每分钟 72 拍，温暖的铺底音色，黑胶噪音」；
* **人声** — 「女声，轻柔，带长混响」；
* **自己的歌词** — 直接写在任务描述里，规划器会采纳；
* **纯器乐** — 就那样写：「无人声，只有乐器」。

每次运行都取**随机 seed**，因此两个文本相同的作业会给出不同的曲目。需要可重复的结果 —
请在模型配置档中把 `seed` 写成数字。

## LoRA 训练

**应用 — 可以，训练 — 不行。**

现成的适配器模型是接受的：ComfyUI 认识 ACE-Step 的官方 LoRA 格式，AI2P 会即时把
`LoraLoaderModelOnly` 节点插入图中。请把文件放到 `<模型仓库>/loras/`，并在任务描述中用
`@obj:` 引用来指名该适配器对象。

而**从 AI2P 里训练适配器是做不到的**，这一点在配置档中如实标注了
（`lora.train.kind: external`）。原因有两个：

* AI2P 用来为其余本地模型训练 LoRA 的
  [musubi-tuner](https://github.com/kohya-ss/musubi-tuner) 根本不认识 ACE-Step — 里面
  一个 acestep 脚本也没有（2026-08-27 核实）；
* ACE-Step 的官方训练器（<https://github.com/ace-step/ACE-Step-1.5>，`train.py`）是在
  **音频录音**上训练的，而 AI2P 中的 LoRA 数据集是画面图片：数据集编辑器和尺寸检查都是
  为图像设计的。

因此适配器要在 AI2P 之外用官方训练器训练，训练好的文件再放到这里。

## 常见问题

* **进程无提示地消失** — 几乎总是 NVIDIA 驱动过旧（见上文）。
* **「模型未安装」** — 文件没有下载完；打开「安装」，窗口会显示剩余的下载量。
* **负面提示词不起作用** — Turbo 就是这样设计的（见「生成参数」）。
* **人声唱的语言不对** — 在 workflow 模板的 `language` 字段里填上语言代号，替换 `unknown`。
* **曲目比预期短或长** — 那是配置档中的 `length`，它的单位是秒。
* **ComfyUI 被别的进程占用** — AI2P 只会卸载它自己启动的那个服务器；8188 端口上已经在运行
  的别人的 ComfyUI 它不会去动。
