# ACE-Step-1.5-XL-Turbo

**部署位置:** 本地（在本机运行）
**接入方式:** `provider: comfyui`，`baseUrl: http://127.0.0.1:8188`，模型 `acestep_v1_5_xl_turbo`
**API 密钥:** 不需要 — 服务器在本地启动，无需授权
**功能:** 文本 → 音乐与歌曲，技能 `audio-song` 84、`audio-music` 86

来自 ACE-Step 团队的音乐创作模型，**Turbo** 变体：蒸馏版，用**八步**而不是五十步算出一首
曲目，而且不用 classifier-free guidance。这是拿到成品曲目最快的方式 — 在您还在斟酌措辞时，
它是合理的首选。

值得选用 ACE-Step 1.5 的那个特点：模型内部运行着一个**语言模型规划器**。它会自行把您的
请求分解为歌曲结构、歌词、速度和调性。因此不需要用单独的字段写歌词 — 只要用文字描述任务
即可，歌词模型会自己创作（或者采用您写的那些）。它能理解五十多种语言，其中包括俄语和中文。

通过 **ComfyUI** 工作：AI2P 把它作为本地服务器启动，发送 workflow，并把生成好的 `.mp3`
取回任务的产物中。

## 不需要密钥，但需要安装

一切都用模型表单中的 **「安装」** 按钮完成：**设置 → 名录 → 模型 → ACE-Step-1.5-XL-Turbo →
「安装」**。会安装：

* **ComfyUI 包**（约 2,1 GB） — 自带 Python 的便携版；
* **四个权重文件**放入模型仓库（`storage.modelsRepo`），分组 `ACE-Step-1.5`：

| 文件 | 大小 | 放到哪里 |
|---|---|---|
| `acestep_v1.5_xl_turbo_bf16.safetensors` | ~9,3 GiB | `diffusion_models` |
| `qwen_4b_ace15.safetensors` | ~7,8 GiB | `text_encoders` |
| `qwen_0.6b_ace15.safetensors` | ~1,1 GiB | `text_encoders` |
| `ace_1.5_vae.safetensors` | ~322 MiB | `vae` |

**合计约需下载 19,9 GB。** 下载支持续传：中断的安装会从停下的地方继续，已下载的文件不会
重新下载。

名录中三条 ACE-Step 1.5 XL 记录（Turbo、Base、SFT）共用**同一个分组**以及四个文件中的
三个。如果您已经装过其中一条，第二条只会补下载它自己的权重文件 — 约 9,3 GiB，而不是全部
19,9 GB。

在文件到位之前，模型**不能被启用** — 应用启动时也会检查这一点。

## 需要等多久

八步就是每首曲目**几秒到几十秒**：作者声称在 RTX 3090 上不到 10 秒出一首完整的歌。配置档
中作业超时设为 60 分钟（`params.timeoutMinutes`） — 即使在慢机器上也绰绰有余。

生成进度可以在任务卡片的**作业控制台**中看到：ComfyUI 自己的输出连同它的进度条都会流到
那里。

## 生成参数

在模型配置档中修改（「连接配置档」按钮）：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `length` | 120 | **曲目时长，单位为秒**（不是视频那样的帧数） |
| `steps` | 8 | 扩散步数；Turbo 超过八步没有意义 |
| `width` / `height` | 未设置 | 声音没有画面尺寸；作业摘要中会显示默认的 768×512 — 与声音无关 |
| `negative` | 空 | 负面提示词 — **在 Turbo 上不起作用**（见下文） |
| `timeoutMinutes` | 60 | 等待结果多久 |

**关于时长。** 每首曲目的时长由**提词模型**根据任务描述给出（「一分半」变成
`duration: 90`）。配置档里的 `length` 成了后备：只有在没有选提词模型、它没有回答，或者
任务里根本没提时长时才生效。该值会同时进入图的两个位置 —— 空潜变量的尺寸和规划器的
`duration` 字段 —— 并且边界是硬性的：1 到 1000 秒（已与运行中的 ComfyUI 核对）。在作业
摘要中 `length` 被标注为「帧数」 —— 所有媒体模型都是这样标注的；请把它读作「秒」。

**关于负面提示词。** Turbo 模式不用 classifier-free guidance 计算（`cfg = 1`），因此模板
中的负面条件是用 `ConditioningZeroOut` 节点做的 — 与 ComfyUI 官方模板完全一致。`negative`
的值可以写进配置档，但它不会影响声音；如果需要负面条件，请用
**ACE-Step-1.5-XL-Base** 或 **-SFT**。

**关于演唱语言。** 语言由提词模型给出 —— 取自节点的代号清单（`ru`、`en`、`zh`、
`ja`、… 共 51 个值）。谁都没有指定时保持 `unknown`，模型会自行按歌词判断语言；ComfyUI
官方模板中那里写的是 `en`，这会让非英语歌词带上英语发音。固定语言也可以不用提词模型：
直接写在模型的 workflow 模板里。

没有提词模型时，任务描述会整体进入提示词（模型的 `tags` 字段）；有提词模型时，进入 `tags` 的是它拼出的风格标签。诸如「результат положить в файл X.mp3」
这样的指令由连接器执行：文件会被复制到项目文件夹，而这一行会从提示词中删掉。指令只能用
俄语或英语书写，场景文本可以是任何语言。

## 提词器

这条记录在配置档中带有**「需要提词模型」**的标记。提词器是另一位执行者：在生成之前，它读取
任务描述，并以一个单独的作业为 ACE-Step 准备控制 json。任何 AI 执行者都可以担任 ——
CLI 订阅、本地模型、云端 API：它像处理普通任务一样，用自己的连接器工作。指定方式有两
处：AI 执行者卡片中的**「提词器」**字段（该执行者所有任务的默认值），以及任务表单中的
**「提词器」**字段，旁边还有**「可替换提词器」**清单，用于指定者正忙于其他工作时。

提词模型会填写 `TextEncodeAceStepAudio1.5` 节点的七个字段：

| 字段 | 含义 | 未指定时 |
|---|---|---|
| `tags` | 风格标签：流派、速度、乐器、情绪、人声 | 整段任务描述 |
| `lyrics` | 歌词 | 留空 —— 模型自己创作 |
| `duration` | 时长，单位秒（1…1000） | 配置档的 `length` |
| `language` | 人声语言代号，取自节点清单 | `unknown` |
| `bpm` | 速度，每分钟拍数（10…300） | 120 |
| `keyscale` | 调与调式（`C major` … `B minor`） | `C major` |
| `timesignature` | 拍号：2、3、4 或 6 | 4 |

**不设置提词器会怎样。** 任务不会启动：它会以错误停止，并提示执行者需要提词器，而任务
和执行者本身都没有指定。系统不能悄悄「照旧」运行：那样曲目参数就是凭空来的，而人要等
半小时算完、拿到不对的曲目才会发现。回答里没有 json、提词器作业出错，结果也一样。另外
两种结局要温和些：指定的提词器正忙时，工作交给「可替换提词器」中的第一个空闲者；全都
忙时，任务暂停等待，直到有人空闲；提词器向人提问时，任务同样暂停，收到回答后继续。

**再次启动。** 处于「暂停」或「错误」且已有 json 的任务直接进入生成 —— 不会第二次询问
提词器。处于「草稿」「等待」或「返工」的任务则从头开始：提词器准备新的 json。

**怎样用任务描述影响结果。** 把应当进入这些字段的内容写进去：时长（「一分钟」「90 秒」）、
人声语言、速度、调式、拍号；歌词要逐字给出 —— 提词模型会原样转交。风格用文字描述：它会
据此拼出标签。它最终给出了什么，可以在作业控制台和任务文件中的 `prompter.json` 里
看到。

**它遵循的规则**就放在模型配置档旁边 —— 数据目录中的
`models/prompter_<记录标识>.md` 文件。可以编辑它：文本会整体进入提词模型的提示词，修改
从下一个作业起生效。该文件在版本提升时由安装程序重写，并且不会通过复制同步到其他
服务器。

## 如何写任务描述

模型期待的是对音乐的描述，而不是命令。有效的写法：

* **风格、速度、乐器、情绪** — 「安静的氛围音乐，每分钟 72 拍，温暖的铺底音色，黑胶噪音」；
* **人声** — 「女声，轻柔，带长混响」；
* **自己的歌词** — 直接写在任务描述里，规划器会采纳；
* **纯器乐** — 就那样写：「无人声，只有乐器」。

每次运行都取**随机 seed**，因此两个文本相同的作业会给出不同的曲目。需要可重复的结果 —
请在模型配置档中把 `seed` 写成数字。

任务描述由提词模型阅读，所以请把数字和语言直接写进去：「90 秒」「用俄语
演唱」「每分钟 120 拍」「小调」。它理解成了什么，可以在作业控制台里看到。

## LoRA 训练

**可以应用，但不能在 AI2P 内训练。**

模型接受现成的适配器：AI2P 会即时把 `LoraLoaderModelOnly` 节点插入工作流。把文件放到
`<模型仓库>/loras/`，并在任务描述中用 `@obj:` 引用适配器对象。

在 AI2P 内训练适配器则不行，配置文件如实标注了这一点：`lora.train.kind: external`
且命令为空——「训练」按钮会立即拒绝，而不是先算上半小时。2026-09-14 依据仓库文件核对：

* **模型确实有训练器**——官方
  [ACE-Step-1.5](https://github.com/ace-step/ACE-Step-1.5)，MIT 许可，并且能在 Windows
  上用单张显卡运行：`python -m acestep.training_v2.cli.train_fixed`，不需要 `torchrun`，
  `--num-devices` 默认为 1，Windows 上 DataLoader 工作进程刻意为 0。最低需要 16 GB
  显存，建议 20 GB 以上；
* **但它需要的权重和我们安装的不是一回事。** 训练器读取 HuggingFace 版式的检查点目录
  （`config.json` 加 `model-0000N-of-00004.safetensors`，每个变体约 19.9 GB，另有 VAE
  和用于打标的语言模型），而 AI2P 安装的是 Comfy-Org 的重新打包：文件不同，目录结构也
  不同。安装程序不会再下载第二份权重；
* **而且训练出的文件格式未经验证**：训练器产出的是基于自家 DiT 的 peft 适配器，而
  `comfy/lora.py` 中「ACE-Step 官方格式」的分支挂在 `ACEStep` 类下，1.5 却是独立的
  `ACEStep15` 类；
* AI2P 训练其他本地模型 LoRA 所用的
  [musubi-tuner](https://github.com/kohya-ss/musubi-tuner) 根本不认识 ACE-Step
  （2026-08-27 核实）。

**数据集的限制仍然是声明了的**——AI2P 按它们校验数据集，您则据此为外部训练准备素材。
数据集是音频型（`media: audio`）：单条录音不超过 240 秒、48 000 Hz、2 声道，格式为
WAV、MP3、FLAC、OGG、Opus，至少 10 条，文字说明放在录音旁边的 `.txt` 文件里（转写或
标签）。数据集编辑器显示的正是这些字段，并把录音原样放入数据集——音频不会经过图片压缩。

官方训练器的步骤：准备带 `<名称>.lyrics.txt` 和说明的录音 → 预处理成张量 → 启动训练
（LoRA 或 LoKr，后者大约快十倍）。详见 [LoRA Training Tutorial](https://github.com/ace-step/ACE-Step-1.5/blob/main/docs/en/LoRA_Training_Tutorial.md)。

## 常见问题

* **进程无提示地消失** — 几乎总是 NVIDIA 驱动过旧（见上文）。
* **「模型未安装」** — 文件没有下载完；打开「安装」，窗口会显示剩余的下载量。
* **负面提示词不起作用** — Turbo 就是这样设计的（见「生成参数」）。
* **人声唱的语言不对** — 请直接在任务描述里说明语言，提词模型会转交；没有提词
  模型时，在 workflow 模板的 `language` 字段里填上语言代号，替换 `unknown`。
* **曲目比预期短或长** — 请在任务描述里说明时长（提词模型会以秒交出）；没有提词模型时
  由配置档的 `length` 决定，它的单位也是秒。
* **ComfyUI 被别的进程占用** — AI2P 只会卸载它自己启动的那个服务器；8188 端口上已经在运行
  的别人的 ComfyUI 它不会去动。
