# Qwen3.6-35B-A3B-Local

**部署位置:** 本地（在这台计算机上运行）
**接入方式:** `provider: openai-compatible`，`baseUrl: http://localhost:8080/v1`
**API 密钥:** 不需要 —— 本地服务器无需授权即可启动
**功能:** 代码和文本，技能评分 72–80

Qwen 3.6 文本模型（350 亿参数，MoE，激活约 30 亿），量化 **Q4_K_M**，
通过 **llama.cpp / llama-server** 工作。质量不如云端模型，
但**免费而且哪儿也不去**：数据不会离开这台计算机。对于不能交给云端的
任务来说，这是个合理的选择。

## 不需要密钥，需要安装

一切都用模型表单中的**「安装」**按钮完成：**设置 → 名录 →
AI 模型 → Qwen3.6-35B-A3B-Local →「安装」**。会安装：

* **llama.cpp 包**（约 640 MB）—— 带 `llama-server` 的构建；
* **权重文件** `Qwen3.6-35B-A3B-UD-Q4_K_M.gguf` —— **约 20,6 GiB**，放入模型仓库
  （`storage.modelsRepo`，Windows 上默认 `C:\ai`，Linux/macOS 上默认 `~/ai`，
  组 `Qwen3.6`）。

下载支持续传：中断的安装会继续，已经下好的不会重下。
文件没有就位之前，模型不可能处于已启用状态。

安装后会自动把启动命令写入配置档：

```
llama-server.exe -m <.gguf 文件路径> --n-cpu-moe 99 -ngl 99 -c 65536 --jinja
                 --port 8080 --alias qwen3.6-35b-a3b
```

团队开始工作时 AI2P 会自己启动这个进程，停止时再把它卸载 ——
**而且只管自己启动的那个**；8080 上已经在跑的别人的 llama-server 它不会去动。

## 硬件要求

| | |
|---|---|
| 磁盘空间 | **约 22 GB**（权重 + 包） |
| 内存 | **至少 24 GB**，32 GB 才宽裕 |
| 显卡 | 不是必需的，但能大幅提速 |
| 显存 | 6 GB 起就有明显收益；`--n-cpu-moe 99` 参数把专家留在内存里，其余部分交给 GPU |
| 处理器 | 核心越多，CPU 模式下越快 |

这是 **MoE** 模型：350 亿参数中约有 30 亿是激活的，所以它比同样大小的稠密模型
明显更快。但它是整体加载到内存的 —— 20,6 GiB 权重总得放得下。

**首次启动很慢：**加载权重要几分钟。AI2P 会等待 API 就绪，并把团队成员显示为
「正在启动」状态 —— 这不是卡死。

## 上下文和回复上限

| | |
|---|---|
| 上下文 | 65 536 个令牌（启动命令中的 `-c 65536`） |
| 回复上限 | 32 768 个令牌（`params.maxTokens`） |

这一对数值是验证过的，而且很重要：上下文**更小**时回复会因 `length` 被截断 ——
模型把限额烧在推理上，然后返回空结果。要改一个数，就把另一个也改了。

## 常见错误

* **「37529 tokens exceeds context 32768」** —— 启动命令中的 `-c` 太小。
  请在配置档的「启动命令」字段里设为 `-c 65536`，再重新启动团队的工作。
* **结果为空，原因是 `length`** —— `params.maxTokens` 太小；请设为 32768。
* **内存不足 / 系统开始用交换文件** —— 这个模型需要 24 GB 左右的内存；
  请关掉多余的程序，或者换更小的量化（那就得自己建一条带自己清单的名录记录）。
* **端口 8080 被占用** —— 请改启动命令中的 `--port` 和配置档中的 `baseUrl`。

## 过时的安装方式

应用目录中的 `install_local_model.bat/.ps1/.sh` 脚本能不经界面装上同一个模型
（用于离线场景）。它们会建立**单独的自定义名录记录** —— 别把它和内置的那条弄混。
从 1.42 版起，正规的方式是「安装」按钮。
