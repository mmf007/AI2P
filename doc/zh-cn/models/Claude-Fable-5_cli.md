# Claude-Fable-5_cli

**部署位置:** 云端，但接入方式**不是 API，而是 CLI**
**接入方式:** `transport: cli`，命令 `claude --permission-mode acceptEdits`，
模型 `claude-fable-5`
**密钥引用:** 空 — **不需要 API 密钥**

与 Claude-Fable-5 是同一个模型，但通过 headless 模式的 **Claude Code CLI** 启动。付费方式
不是按令牌，而是**按订阅**，因此在 AI2P 的计费中这类作业的费用为零。

## 不需要 API 密钥

授权靠的是 CLI 的会话，而不是密钥。因此配置档中的 `secretRef` 为空，这个模型也没有
「设置 API 密钥」按钮。

## 代替密钥需要什么

1. **安装 Claude Code** — [官方说明](https://docs.claude.com/en/docs/claude-code/overview)。
   检查方法：在控制台里 `claude --version` 应该能打印出点什么。
2. **用您的订阅登录**：`claude login`（浏览器会自行打开）。会话保存在操作系统的用户配置
   文件中。
3. 确认 `claude` 在**运行 AI2P 的那个用户的 PATH** 中可用。如果 AI2P 是以另一个账户作为
   服务运行的，登录也要在那个账户下完成，否则代理会卡在「未授权」上。
4. 如果可执行文件不在 PATH 中 — 请在模型配置档的 `cliCommand` 字段中写上完整路径
   （模型表单中的「连接配置档」按钮）。

## 与 API 变体有什么不同

| | 通过 API | 通过 CLI |
|---|---|---|
| 付费 | 按令牌 | 按订阅 |
| 计费中的费用 | 会计算 | 0 |
| 工具 | AI2P 的工具（读写文件等） | **CLI 自带的工具** |
| 工作目录 | 无所谓 | **项目文件夹** — 代理直接在其中工作 |
| 向人提问 | 标准方式 | 靠回复中的 `AI2P_QUESTION` 标记，继续对话用 `--resume` |
| 创建子任务 | 用 `create_task` 工具 | 靠回复中的 `AI2P_SUBTASK` 标记 |
| 读取其他作业 | 用 `get_task_by_code`、`get_task_by_url`、`get_task_chat` 工具 | 靠回复中的 `AI2P_GET_TASK` 标记 |
| 作业的外部文件（附件图片） | 用 `fetch_file` 工具 | 靠回复中的 `AI2P_GET_FILE` 标记 |
| 在层级中移动任务 | 用 `move_task` 工具 | 靠回复中的 `AI2P_MOVE_TASK` 标记 |

一个重要的推论：在 CLI 接入方式下，AI2P 的工具**不会**提供给代理 — 它用的是自己的工具。
AI2P 的安全规则（技术规格第 12 章）不适用于它在项目目录内的动作，因此项目目录要有意识地
设置。

### 用 `AI2P_SUBTASK` 标记创建子任务

CLI 代理没有 `create_task` 工具，而 AI2P 的 API 是用 cookie 登录关闭的 — 因此它以前根本
无法把任务拆成子任务。现在子任务是用**回复中的一行**创建的：

```
AI2P_SUBTASK: {"title": "标题", "description": "工作描述", "skills": ["code-write"], "priority": 20, "acceptance": "验收标准"}
```

一行一个子任务；`title` 和 `description` 是必填的。代理一结束工作，AI2P 就会自行执行这些
行：把它们从回复文本中去掉，创建子任务（执行者自动挑选 — 先 AI，后人），把父任务标记为
已拆分，并在结果中补上一节「子任务」，列出创建的内容。之后子任务会按普通的自动拆分队列
启动 — 按数字优先级从高到低。

这与工具用的是同一个 **`AI2P.Tasks.Create`** 动作，因此针对该动作的安全规则是有效的：
禁止（deny）或要求确认（confirm） — 子任务就不会被创建，拒绝的原因会进入作业的结果和
工作日志。标记只在**行首**才被计入：句子中间或报告里的提及不会变成子任务。

### 用 `AI2P_GET_TASK` 标记读取其他作业

AI2P 的任务放在组织的数据库里，项目文件中没有它们，而 `/api` 是用 cookie 登录关闭的 —
因此 CLI 代理只能看到自己作业的文本和父任务那一块。如果人在表述中给出了指向另一个任务的
链接（「把 … 任务结果里的文案拿过来」），代理是读不到它的。现在它用**回复中的一行**来
请求：

```
AI2P_GET_TASK: {"code": "T-15"}
```

除了 `code`，也可以指定 `"url"`（形如 `…/task/<id>` 的链接）或 `"title"`（按标题的一部分
搜索 — 会返回找到的作业列表，不含正文）。AI2P 执行该请求，并把回答**作为同一个 CLI 会话的
下一条消息**发给代理（`--resume`，和人回答问题时一样），之后它就从原处继续工作。回答总是
完整的：作业卡片（表述、验收标准、状态、结果产物）**以及整个聊天** — 不需要另外请求往来
消息。标记可以一次输出多个；一个作业内的请求总数不超过 10 个（防止死循环），再多系统就会
告诉代理次数已经用完。

这与同名的工具用的是同样的 **`AI2P.Tasks.GetByCode` / `GetByUrl` / `FindByTitle` /
`GetChat`** 动作，因此安全规则照常生效：禁止或要求确认 — 作业就读不到，拒绝会送给代理并
进入工作日志。只能访问同一个项目的任务。

## 限制

| | |
|---|---|
| 上下文 | 1 000 000 令牌 |
| 最大响应 | 128 000 令牌 |
| 费用 | 0（由订阅支付） |

**CLI 不会报告订阅限额的余量**（v1.62 的改动），因此 AI2P 自己统计消耗 — 按滑动窗口内各
作业的令牌数。请在 AI 执行者那里填好 **「每个窗口的令牌限额」** 和 **「限额窗口，小时」**
（Claude 订阅的窗口是 5 小时）：这样在启动任务之前，系统会提醒限额快用完了，并把启动推迟
到窗口释放的时刻（也可以改为拆分任务或强制启动）。字段留空 — 不做检查，一切照旧。而如果
限额是在作业中途才到的，AI2P 会认出 CLI 的消息
（`5-hour limit reached ∙ resets 4:10pm (…)`），从中取出重置时间，并把任务转为**「等待中」**
直到那个时刻，而不是「出错停止」 — 之后它会自行启动。详情见 Claude-Opus-5.0_cli 的文档。

**等待响应多久**（v1.63 的改动） — 执行者表单中的 **「响应超时，分钟」** 字段：空为 30
分钟，数字就是那么多分钟，**0 为无限制**。超时到了 — 作业以错误结束并给出提示；此时执行者
不会被标记为忙碌（代理的沉默不算作限额）。

## 许可证

| | |
|---|---|
| 对生成结果的条款 | **结果归您**：Anthropic 把它对 Outputs 的权利让与您（Consumer Terms，第 4 条） |
| 商业使用 | 允许；「仅限个人非商业用途」的说法针对的是试用访问，而不是付费订阅 |
| 必须做到 | 遵守 Usage Policy；记住按消费者条款，在您到账户设置中拒绝之前，您的材料会被用于训练模型 |
| 条款文本 | <https://www.anthropic.com/legal/consumer-terms> （2025-10-08 版） |
| 生成费用 | 按订阅，而非按令牌 — 在 AI2P 的计费中这类作业费用为 0 |

这里重要的是别把两份协议弄混。Claude 订阅适用的是**消费者**条款；API 密钥适用的是**商业**
条款（<https://www.anthropic.com/legal/commercial-terms>），其中根本不存在用您的数据训练
这回事。

实际的推论：如果作业处理的是保密协议下的他人代码或数据，那么按 API 密钥的变体比订阅变体
更安全 — 或者请在 Claude 账户设置中拒绝参与训练。

条款已按其文本于 2026-08-27 核对。

## 硬件要求

没有特别要求：由提供商计算。需要安装好的 Claude Code、互联网连接以及项目目录中足够的
空间 — 代理是直接和文件打交道的。

## 常见问题

* **「找不到 claude」** — CLI 没有安装，或者不在 AI2P 用户的 PATH 中。
* **无声拒绝或要求登录** — CLI 会话没有建立，或者是在操作系统的另一个账户下建立的；请在
  正确的用户下重新执行 `claude login`。
* **代理看不到任务的文件** — 项目没有设置目录（「项目文件夹」字段）：CLI 进程的工作目录
  正是它。
