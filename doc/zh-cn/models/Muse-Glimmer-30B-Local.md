# Muse-Glimmer-30B-Local

**部署位置:** 本地（在这台计算机上运行）
**接入方式:** `provider: openai-compatible`，`baseUrl: http://localhost:8083/v1`，
模型 `muse-glimmer-30b`
**API 密钥:** 不需要 —— 本地服务器启动时无需授权
**功能:** 文本和代码，技能评分 73–80

Meta 的 300 亿参数开放模型，量化为 **UD-Q4_K_XL**，通过
**llama.cpp / llama-server** 工作。它是云端 Muse-Spark-1.2 的小妹妹。
写代码比同尺寸的 Qwen 系列弱（75–78 对 82–87），但写文本更稳 ——
而且和所有本地记录一样，**免费，而且不把数据发到任何地方**。

## 不需要密钥，需要安装

一切都用模型表单中的**「安装」**按钮完成：**设置 → 名录 →
AI 模型 → Muse-Glimmer-30B-Local →「安装」**。会安装：

* **llama.cpp 包**（约 0,5 GB）—— 带 `llama-server` 的构建，和别的本地模型共用；
* **权重文件** `Muse-Glimmer-30B-UD-Q4_K_XL.gguf` —— **14,8 GiB**（15 878 222 368 字节），
  放到模型仓库（`storage.modelsRepo`，Windows 上默认是 `C:\ai`，
  Linux/macOS 上是 `~/ai`，组 `Muse-Glimmer`）。

这是名录中本地记录里最小的文件，所以显存不够的时候从它开始更省事。
下载支持续传，下好的部分按精确大小核对。**文件没有就位之前，模型不可能处于已启用状态** ——
这是 AI2P 的规则，不是错误。

安装之后写进配置档的启动命令：

```
llama-server.exe -m <.gguf 文件路径> -ngl 99 -c 65536 --jinja --port 8083 --alias muse-glimmer-30b
```

端口 **8083** 是这条记录自己的（Qwen 系列的模型是 8081 和 8082）：
两个 `llama-server` 不能同时占用一个端口。

## 常见错误

* **「N tokens exceeds context 32768」** —— 启动命令里的 `-c` 太小；请设成
  `-c 65536` 并重启该命令的运行。
* **结果为空，原因是 `length`** —— `params.maxTokens` 太小；请设成 32768。
* **端口 8083 被占用** —— 请改启动命令中的 `--port` 和配置档中的 `baseUrl`。
* **内存不够** —— 请换更小的量化，或者腾出显存。
