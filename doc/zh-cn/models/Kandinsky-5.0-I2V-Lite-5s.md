# Kandinsky-5.0-I2V-Lite-5s

**部署位置:** 本地（在这台计算机上运行）
**接入方式:** `provider: comfyui`，`baseUrl: http://127.0.0.1:8188`，
模型 `kandinsky5lite_i2v_5s`
**API 密钥:** 不需要 —— 服务器在本地启动，无需授权
**功能:** 图像 + 文本 → 视频（5 秒），技能 `video-animate` 78、
`video-generate` 74

和 `Kandinsky-5.0-T2V-Lite-sft-5s` 是同一个 Kandinsky 5.0 Video Lite，
但片子是**从图片**开始建的：起始帧决定角色和场景长什么样，任务描述决定画面里发生什么。
收录这条记录正是为了这个：**同一个角色出现在好几段片子里**，靠文字是稳不住的，
稳住它的是参考帧。

**Lite 版的 i2v 没有 10 秒的版本**：kandinskylab 只发布了
`Kandinsky-5.0-I2V-Lite-5s`（2026-08-20 按该组织的仓库列表核实）。
10 秒的有文本版 `T2V-Lite` 和 Pro 版 —— 后者要另一档硬件。

## 怎样给它起始帧

文件是**在项目文件夹里**找的，路径是相对的。有两种办法：

1. **写在任务描述里** —— 一行里带指示词和文件名：
   「Взять за основу `refs/hero.png`」、「Стартовый кадр `refs/hero.png`」、`based on
   refs/hero.png`。这一行会从提示词中剪掉 —— 文件名不会进入生成用的文本。
   （**这类指示只按俄语和英语识别**，单词列表写死在代码里；场景文本可以用任何语言写。）
2. **引用项目对象** —— 在描述里写 `@obj:OBJ-3`。启动时这个引用会展开成角色的档案
   和他的参考帧路径；第一个路径就是起始帧，而路径本身会从提示词中去掉。这样更方便：
   档案在一个地方修改，对之后所有的画面都生效。

用文字指名的文件优先于对象里的路径。要是根本没有关于文件的指示 —— 作业会带着
清楚的错误停下：这个模型没有图片就无事可做。

图片会被送到 ComfyUI（`POST /upload/image`），以作业名放进它的 `input` 目录，
并代入图中的 `LoadImage` 节点；接着 `ImageScale` 把它调整到画面的 `width`×`height`
（按中心裁切），所以起始帧的比例最好一开始就接近 768×512。

## 让一系列片子里的角色保持一致

| 做法 | 能带来什么 |
|---|---|
| **参考帧**（这个模型） | 脸、衣服和颜色在各段片子之间保持一致 |
| **固定 `seed`**（配置档中的 `params.seed`） | 所有画面的生成「性格」一致；留空则和以前一样随机 |
| **接龙** | 把第 N 个场景的最后一帧存成图片，作为第 N+1 个场景的输入 |
| **逐字档案**写在描述里 | 外貌描述一字不差地重复，而不是换个说法复述 |

系列的第一帧可以用普通的 t2i 模型生成，或者手工画出来 —— 后面的一切都从它出发。

## 不需要密钥，需要安装

一切都用模型表单中的**「安装」**按钮完成：**设置 → 名录 →
AI 模型 → Kandinsky-5.0-I2V-Lite-5s →「安装」**。会安装：

* **ComfyUI 包**（约 2,1 GB）—— 自带 Python 的便携版；
* 模型仓库（`storage.modelsRepo`，Windows 上默认是 `C:\ai`，
  Linux/macOS 上是 `~/ai`）中的**四个权重文件**：

| 文件 | 大小 | 放到哪里 |
|---|---|---|
| `kandinsky5lite_i2v_5s.safetensors` | ~4,3 GiB | `diffusion_models` |
| `qwen_2.5_vl_7b_fp8_scaled.safetensors` | ~8,7 GiB | `text_encoders` |
| `clip_l.safetensors` | ~235 MiB | `text_encoders` |
| `hunyuan_video_vae_bf16.safetensors` | ~470 MiB | `vae` |

**总共约 16 GB 的下载量**，但四个文件里有三个与
`Kandinsky-5.0-T2V-Lite-sft-5s` **完全相同**，而且都放在同一个组 `Kandinsky-5` 里。
如果文本模型已经装好了，只需补下 DiT 本身 —— **约 4,3 GiB**。下载支持续传：
中断的安装会从停下的地方继续。

文件没有就位之前，模型**不可能处于已启用状态** —— 应用启动时也会检查这一点。

## 硬件要求

| | |
|---|---|
| 显卡 | NVIDIA，**至少 6 GB 显存** |
| NVIDIA 驱动 | **580 或更新** |
| 磁盘空间 | ~18 GB（权重 + ComfyUI 包）；旁边再放一个 t2v 模型要多约 4,3 GB |
| 内存 | 16 GB 起 |
| 操作系统 | Windows（ComfyUI 便携版）；在 Linux 上 ComfyUI 需要手动安装 |

**关于驱动。**ComfyUI 包里带的 torch 是按 CUDA 13.0 编译的。在旧驱动上
（例如 527.99 = CUDA 12.0）它不会给出清楚的错误，而是 **access violation** ——
进程直接消失。这不是 AI2P 的缺陷：请把 NVIDIA 驱动升级到 580+。
如果模型「一声不响就是不启动」，请从 `nvidia-smi` 查起。

## 要等多久

和文本版一样：在 6 GB 显存上，**768×512、121 帧、50 步**的片子
大约要算一小时（这个数字是在 t2v 模型上测的：58 分 49 秒；这里的权重和图规模相同）。
作业超时是 180 分钟（`params.timeoutMinutes`），执行者的「响应超时，分钟」
字段优先级更高，0 表示无限等待。

生成进度可以在任务卡片的**作业控制台**中看到。

## 生成参数

在模型配置档中修改（「连接配置档」按钮）：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `width` / `height` | 768 × 512 | 画面分辨率；起始图片也会被调整到这个尺寸 |
| `length` | 121 | 帧数（约 5 秒） |
| `steps` | 50 | 扩散步数；越少越快也越糙 |
| `negative` | 空 | 负面提示词 |
| `seed` | 无 | **固定 seed**：留空（或 0）则每个作业随机 |
| `timeoutMinutes` | 180 | 等待结果多久 |

任务描述全文都会进入提示词 —— 除了关于起始帧的指示和
「результат положить в файл X.mp4」这类指示：这两样都由连接器执行。

## LoRA 训练

这个模型会用 LoRA 适配器，而且**适配器可以直接从 AI2P 训练**：LoRA 编辑器
（项目卡片 →「对象」→ 角色对象 →「数据集与训练」）。

**用什么训练。**[musubi-tuner](https://github.com/kohya-ss/musubi-tuner) —— 它有一个
正好对着这套权重的现成任务 `k5-lite-i2v-5s-sd`，只需要**一张**显卡，
注意力可以用 `sdpa` 计算。官方的
[kandinsky-5-lora-train](https://github.com/kandinskylab/kandinsky-5-lora-train) 不行：
它会起 `torchrun` 和 `init_device_mesh("cuda")`，也就是要求 NCCL 和多张显卡 ——
在 Windows 上根本跑不起来。

**还会额外装什么。**`musubi-tuner` 包（源码，约 30 MB）和 **Python 3.12**
（约 45 MB）随模型一起来 —— 就用「安装」按钮，和下载权重在同一处；计算机上已经有的
Python 3.10–3.12 会直接拿来用，不会重复下载。第一次启动训练时，训练器会在旁边给自己
建一个环境（`.venv`），并往里装 CUDA 12.4 版的 `torch` —— 这还要**大约 3 GB**，
第一次要花十到二十分钟。之后这个环境会被反复使用。

第一次缓存文本时训练器还会自己拉两个文件 —— **它们不是生成用的那些文件**：
生成用的是 ComfyUI 的精简版，而训练需要 Hugging Face 上的原始模型：

| 什么 | 大小 | 从哪里 |
|---|---|---|
| `Qwen/Qwen2.5-VL-7B-Instruct` | ~16 GB | Hugging Face 缓存 |
| `openai/clip-vit-large-patch14` | ~1,7 GB | Hugging Face 缓存 |

**计算机上需要什么：**`PATH` 里有 Python **3.10–3.12**（否则训练会停下并给出提示），
以及一张 NVIDIA 显卡。训练 Lite 模型的适配器能装进 **13–16 GB 显存**；
缓存潜变量需要得更多 —— 那是最耗资源的一步。
自己的 Python 路径用环境变量 `AI2P_LORA_PYTHON` 指定，自己的 torch 轮子索引用
`AI2P_LORA_TORCH_INDEX`（默认是 `https://download.pytorch.org/whl/cu124`）。

**训练是怎么进行的。**AI2P 把数据集的画面放进 `<项目文件夹>/lora/<对象代号>/dataset`
（每个画面配一个同名的 `.txt` 说明），在旁边写好 `dataset.toml` 和 `train.cmd`，
然后运行后者。脚本会连着做三步：缓存潜变量 → 缓存文本编码器输出 → 正式训练。
训练好的适配器会放到 `<模型仓库>/loras/<对象代号>.safetensors`，并成为这个对象的
当前适配器 —— 生成时就从那里取（`LoraLoaderModelOnly` 节点）。

`dataset.toml` 和 `train.cmd` **在每次启动前都会重写**：它们属于模型配置档
（`lora.train.files` 一节），要改就在那里改，而不是改磁盘上的文件。步数
（`lora.train.start.steps`，默认 2000）、秩以及训练器的所有参数也在同一处修改。

**这条路给不了什么。**AI2P 里的数据集由**图片**组成，不是片子，所以这样训练出来的是
**外貌**适配器（角色、风格）。**动作**适配器（像官方的 `Arc-right`、`Dolly-in` 那样）
是在视频上训练的 —— LoRA 编辑器目前还没有视频数据集。

## 常见错误

* **「这个模型需要起始帧」** —— 描述里既没有图片文件，也没有指向带参考帧的对象的引用。
* **「在项目文件夹中找不到起始帧文件」** —— 路径是从项目文件夹算起的；
  往外走（`..`、`C:\…`）是有意禁止的。
* **「项目在这台计算机上没有指定文件夹」** —— 项目文件夹在它的卡片里设置，
  每台服务器上各有各的。
* **角色还是会「飘」** —— 请检查起始帧是不是同一张，`seed` 是不是固定的；
  `width`/`height` 不同的片子也会走样。
* **进程无声无息地消失** —— 几乎总是 NVIDIA 驱动太旧。
* **显存不足** —— 请调小 `width`/`height` 或 `length`。
* **训练 LoRA 时出现「cannot create the virtual environment」** —— 计算机上没有
  Python 3.10–3.12，或者它不在 `PATH` 里；请安装它，或者在 `AI2P_LORA_PYTHON`
  中指定路径。
