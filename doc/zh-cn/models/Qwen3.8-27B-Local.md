# Qwen3.8-27B-Local

**部署位置:** 本地（在这台计算机上运行）
**接入方式:** `provider: openai-compatible`，`baseUrl: http://localhost:8081/v1`，
模型 `qwen3.8-27b`
**API 密钥:** 不需要 —— 本地服务器无需授权即可启动
**功能:** 代码和文本，技能评分 80–87

名录里「一张显卡就够」的最佳选择：270 亿参数，量化
**UD-Q4_K_XL**，通过 **llama.cpp / llama-server** 工作。在代码上（评分 87）超过
Qwen3.6-27B-Local 和 Muse-Glimmer-30B-Local，
而且完全不用付费：**数据不会离开这台计算机**。对于不能交给云端的任务来说，
这是个合理的选择。

## 不需要密钥，需要安装

一切都用模型表单中的**「安装」**按钮完成：**设置 → 名录 →
AI 模型 → Qwen3.8-27B-Local →「安装」**。会安装：

* **llama.cpp 包**（约 0,5 GB）—— 带 `llama-server` 的构建；
* **权重文件** `Qwen3.8-27B-UD-Q4_K_XL.gguf` —— **16,7 GiB**（17 923 394 624 字节），
  放入模型仓库（`storage.modelsRepo`，Windows 上默认 `C:\ai`，Linux/macOS 上默认 `~/ai`，
  组 `Qwen3.8`）。

下载支持续传：中断的安装会继续，已经下好的不会重下，下好的文件按精确大小核对。
**文件没有就位之前，模型不可能处于已启用状态** —— 这是 AI2P 的规则，不是错误。

安装后会把启动命令写入配置档：

```
llama-server.exe -m <.gguf 文件路径> -ngl 99 -c 65536 --jinja --port 8081 --alias qwen3.8-27b
```

端口 **8081** 是这条记录专用的：相邻的本地模型用 8082 和 8083，否则第二个
`llama-server` 就没法和第一个并排启动。团队开始工作时 AI2P 会自己启动这个进程，
停止时再把它卸载 —— **而且只管自己启动的那个**；同一端口上别人的 llama-server
它不会去动。

## 硬件要求

| | |
|---|---|
| 磁盘空间 | 每个模型 **20 GB 起**（权重 + llama.cpp 包） |
| 显存 | **24 GB** —— 整个模型都在显卡上（RTX 3090/4090/5090） |
| | **16 GB** —— 一部分层会卸载到内存，明显更慢 |
| | **不足 12 GB** —— 请用自己的名录记录换更小的量化（`UD-Q3_K_XL`） |
| 内存 | **32 GB 起** |
| 处理器 | 核心越多，CPU 模式下越快 |

这些数字是**按权重大小估算的，没有做过实测**：这个模型没有在这台计算机上跑过。
启动命令中的上下文是 65 536 个令牌（`-c 65536`）；它越大，KV 缓存占的显存就越多。

**首次启动很慢：**加载权重要几分钟。AI2P 会等待 API 就绪，并把团队成员显示为
「正在启动」状态 —— 这不是卡死。

## 常见错误

* **「N tokens exceeds context 32768」** —— 启动命令中的 `-c` 太小；请设为
  `-c 65536` 并重新启动团队的工作。
* **结果为空，原因是 `length`** —— `params.maxTokens` 太小；请设为 32768。
* **内存不足 / 系统开始用交换文件** —— 请关掉多余的程序，或者换更小的量化。
* **端口 8081 被占用** —— 请改启动命令中的 `--port` 和配置档中的 `baseUrl`。
