AI2P — MakePackage: ПАКЕТ УСТАНОВКИ из готовой выкладки

Один файл-установщик, который можно отдать человеку, не объясняя ему про install.*
и каталоги.

ЗАПУСКАЕТСЯ ИЗ КАТАЛОГА ВЫКЛАДКИ. buildRelease кладёт этот скрипт в
builds/<ОС>/release и builds/<ОС>/releasefull, и работает он «отсюда — туда»:
источник — каталог, где лежит сам скрипт, приёмник — ../../packages (то есть
builds/packages).

ИСПОЛЬЗОВАНИЕ (Windows)
  MakePackage.cmd                   из каталога выкладки, обычный запуск
  MakePackage.cmd D:\out            положить пакет в другой каталог
  MakePackage.ps1 -Output D:\out    то же самое
  MakePackage.ps1 -Source D:\release  собрать пакет из чужой выкладки
  MakePackage.ps1 -KeepStage        не удалять временный каталог (разбор ошибок)
  MakePackage.ps1 -Lang ru          язык сообщений
  MakePackage.cmd --help            эта справка

ИСПОЛЬЗОВАНИЕ (Linux / macOS)
  ./MakePackage.sh                  из каталога выкладки
  ./MakePackage.sh /tmp/out         положить пакет в другой каталог
  ./MakePackage.sh --source DIR     собрать пакет из чужой выкладки
  ./MakePackage.sh --lang ru        язык сообщений
  ./MakePackage.sh --help           эта справка

ИМЯ ФАЙЛА складывается само, из version.json выкладки:
  releasefull -> AI2P_v_1_NN_full_windows_x64.exe / AI2P_v_1_NN_full_linux_x64.run
  release     -> AI2P_v_1_NN_windows_x64.exe      / AI2P_v_1_NN_linux_x64.run
NN — номер билда (вторая часть версии), спрашивать его не надо. Слово full стоит
ПОСЛЕ номера версии, за ним — система (windows, linux, macos) и архитектура
(x64, arm64, arm, x86): у полной выкладки их называет её рантайм, у обычной —
каталог ОС и текущий компилятор. На Windows
установщик собирается Inno Setup (ISCC.exe), и .exe — его вид результата; .run —
вид результата makeself: самораспаковывающийся архив, который сам запускает
install.sh.

ЧТО НУЖНО НА МАШИНЕ
  Windows      — Inno Setup 6 (ISCC.exe), ставит install_required.bat
                 (winget: JRSoftware.InnoSetup)
  Linux/macOS  — makeself, ставит install_required.sh
                 (apt/dnf/brew: makeself)
Если инструмента нет, скрипт честно об этом скажет.

ЧТО ПОПАДАЕТ В ПАКЕТ: вся выкладка, КРОМЕ данных пользователя (data, logs, secrets,
secrets.json) и описи прошлой установки (installed.json). Рабочий config.json
установщик не перезаписывает: он кладёт его только если файла нет, а рядом всегда
кладёт config.new.json — приложение сольёт их при первом старте (ConfigMerge),
ровно как это делает install.*.

СЛУЖБА ОС. Если установка сделана сервисом (makeAsServise, имя службы AI2P),
установщик сам останавливает её перед копированием и запускает обратно после, а при
удалении программы — снимает. Чужую службу, ведущую в другую папку, он не трогает.
Сам makeAsServise едет в пакете и попадает в установку: сервисом её делают руками.

КУДА ЛОЖАТСЯ ДАННЫЕ (Windows). Установка «для всех пользователей» — это
C:\Program Files\AI2P, и писать туда обычный пользователь не может. Поэтому рабочие
файлы (config.json, data, logs, secrets) у такой установки лежат в
C:\ProgramData\AI2P; установщик заводит этот каталог и открывает его на запись всем
пользователям компьютера. Установка «только для меня» кладёт программу в каталог
пользователя — там всё как раньше, рядом с программой.

ЯЗЫК САМОГО УСТАНОВЩИКА. Сценарий Inno Setup несёт оба языка (russian и english);
тексты AI2P из раздела [Code] берутся при сборке из i18n/scripts.<язык>.txt и
кладутся в [CustomMessages], поэтому новый язык установщика — это новый каталог
плюс одна строка в [Languages].
