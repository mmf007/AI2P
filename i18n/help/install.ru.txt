AI2P — install: УСТАНОВКА И ОБНОВЛЕНИЕ релизной выкладки (ТЗ гл. 4.3)

Скрипт кладётся В КАТАЛОГ ВЫКЛАДКИ самим buildRelease и работает «отсюда — туда»:
источник — каталог, где лежит сам скрипт, приёмник — единственный параметр.

ИСПОЛЬЗОВАНИЕ (Windows)
  install.cmd D:\AI2P                 поставить или обновить установку в D:\AI2P
  install.cmd D:\AI2P -Force          не спрашивать и не сверять версии
  install.cmd D:\AI2P -WhatIf         только показать, что будет сделано
  install.cmd D:\AI2P -NoRuntimeCheck не проверять рантайм .NET
  install.cmd D:\AI2P -Lang ru        язык сообщений
  install.cmd --help                  эта справка
  install.ps1 …                       то же самое, без обёртки .cmd

ИСПОЛЬЗОВАНИЕ (Linux / macOS)
  ./install.sh ~/ai/AI2P                    поставить или обновить
  ./install.sh ~/ai/AI2P --force            не спрашивать и не сверять версии
  ./install.sh ~/ai/AI2P --what-if          только показать, что будет сделано
  ./install.sh ~/ai/AI2P --no-runtime-check не проверять рантайм .NET
  ./install.sh ~/ai/AI2P --lang ru          язык сообщений
  ./install.sh --help                       эта справка

ЯЗЫК СООБЩЕНИЙ
  --lang / -Lang, затем переменная окружения AI2P_LANG, по умолчанию en. Ключ
  "language" из config.json намеренно НЕ спрашивается: язык интерфейса приложения
  и язык консоли установки — разные вещи. Тексты лежат в i18n/scripts.<язык>.txt,
  эта справка — в i18n/help/install.<язык>.txt; сам скрипт по языкам не дублируется.

ЧТО ДЕЛАЕТ
  * приёмника нет или он пуст  -> ПЕРВИЧНАЯ УСТАНОВКА: копируется всё;
  * в приёмнике есть установка -> ОБНОВЛЕНИЕ: версии сверяются по version.json,
    программные файлы заменяются, ДАННЫЕ ПОЛЬЗОВАТЕЛЯ НЕ ТРОГАЮТСЯ.

  Никогда не перезаписываются: data, logs, secrets.json, secrets, config.json.
  Конфигурация новой версии кладётся рядом как config.new.json — приложение сольёт
  её при первом старте: основа новая (все новые параметры с умолчаниями), поверх
  рабочие значения пользователя (ConfigMerge). Структуру БД приложение доводит само
  там же.

РАНТАЙМ .NET
  Обычная выкладка (builds/<ОС>/release) собрана БЕЗ рантайма: чтобы её запустить,
  на машине нужен ASP.NET Core Runtime 8.x — скрипт его проверяет и предлагает
  поставить (winget на Windows, apt/dnf или официальный dotnet-install.sh на
  остальных). Полной выкладке (builds/<ОС>/releasefull) рантайм не нужен вовсе: он
  лежит внутри неё, и проверка пропускается по признаку selfContained в version.json.

СЛУЖБА ОС
  Если установка сделана сервисом (makeAsServise, имя службы AI2P), скрипт сам
  останавливает её перед копированием и запускает обратно после. Спрашивает он
  СИСТЕМУ, а не пометку в конфиге: настоящее состояние знает только она. Чужую
  службу, ведущую на другую установку, скрипт не трогает никогда.

ПРОПУСК ВЕРСИЙ
  Выкладка ПОЛНАЯ, а не заплатка к предыдущей: ставить 1.79 поверх 1.70 можно ровно
  так же, как поверх 1.78. Чтобы обновление через несколько версий не оставляло
  мусора, скрипт ведёт ОПИСЬ (installed.json): что положено в приёмник этой версией.
  При следующей установке файлы прошлой описи, которых в новой выкладке больше нет,
  удаляются, а добавленные человеком (свой язык в i18n) в описи не значатся и потому
  остаются.
